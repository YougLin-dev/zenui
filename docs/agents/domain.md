# 领域文档

工程技能在探索代码库时应如何消费本仓库的领域文档。

## 探索前先读

- 仓库根的 **`GLOSSARY.md`**；或
- 若存在则读仓库根的 **`GLOSSARY-MAP.md`**：它指向每个上下文的 `GLOSSARY.md`，读取与当前主题相关的每一个。
- **`docs/adr/`**：读取涉及即将改动区域的 ADR。多上下文仓库中还要检查 `src/<context>/docs/adr/` 里的上下文级决策。

以上文件不存在时，**静默继续**。不要指出其缺失，也不要主动建议创建。`/domain-modeling` 技能（通过 `/grill-with-docs` 和 `/improve-codebase-architecture` 触达）会在术语或决策真正确定时按需创建。

## 文件布局

本仓库为单上下文布局：

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-....md
│   └── 0002-....md
└── src/
```

## 使用术语表的词汇

当输出中提及领域概念（issue 标题、重构提案、假设、测试名）时，使用 `GLOSSARY.md` 中定义的术语，不要漂移到术语表明确避免的同义词。

若所需概念尚未进入术语表，这是一个信号：要么你在发明项目不用的语言（请重新考虑），要么存在真实空白（记下来留给 `/domain-modeling`）。

## 标记 ADR 冲突

若你的输出与现有 ADR 矛盾，请明确指出，而不是默默覆盖：

> _与 ADR-0007（事件溯源订单）矛盾，但值得重新讨论，因为……_
