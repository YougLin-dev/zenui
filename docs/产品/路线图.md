# 路线图

ZenUI 的路线以完整开发体验的逐步闭环推进：先让少量目标 API 真正运行，再连接 Windows 平台，扩展为完整应用能力，最后兑现跨平台与稳定开发承诺。

每个阶段都应同时推进熟悉的表达、原生平台体验、稳定的身份与生命周期，不以某一层的技术完成替代产品闭环。

## 当前起点

仓库已有 headless core、确定性 Todo 场景和独立的宏、文本、布局与图形原型。它们验证了局部机制，尚未组成统一、可运行的桌面 SDK。

近期工作以使实际开发模型与目标语法贯通为主。

## 阶段一：目标语法的最小可运行核

**交付：**一个使用目标 SDK API 运行的最小 Todo。

这一阶段统一已有探索与新目标的表现形式：

- Copy identity 与运行时安装的执行上下文，让嵌套回调中的状态访问简洁且可检查；
- Signal、Memo、Store Field 与共享 RowSet，形成一致的依赖和更新关系；
- mount-once 组件与 `MountResult<MountPlan>`，保留普通 Rust 的 `?`；
- 数据位的 handle、字面量与 `once`，以及具有明确类型的事件与分支 factory；
- 命令 turn、模型事务与统一更新，不用跨域原子事务代替清晰的职责边界；
- `Show`、`For` 的挂载、卸载、业务键重排和 Owner 释放；
- worker 与 UI 交付的身份、归属和生命周期边界。

**完成判据：**

- 最小 Todo 使用目标 API 运行，普通数据位不依赖任意零参数闭包或层层 clone。
- 字段更新不重跑组件；列表重排保留行身份；业务删除与界面卸载不互相替代。
- 跨 Runtime、已释放 Owner、代际回收、非法写入和失败后恢复具有可复跑的行为验证。
- 验证目标 SDK 的实际行为，由对应 API 和测试定义其实现。

## 阶段二：Windows 基本闭环

**交付：**在 Windows 上通过真实 `view!` 运行 Todo 基本工作流。

这一阶段连接目标语法与真实平台：

- 组件宏、typed intrinsic、属性、事件、slot、`Show`、`For` 和对应的编译诊断；
- MountPlan 与 retained 界面树的提交，保持单一界面权威；
- Windows 窗口、布局、文本测量、GPU 绘制与呈现，包括区分测量模式、交付 baseline 和按窗处理 DPI；
- 首个文本切片所需的固定字体、词典数据与真实实景加载；
- TextInput 的外部替换、本地提交、选择、光标和中文 IME；
- 键盘、焦点、鼠标、滚动和语义树的一致性；
- Todo 所需的常用静态 class、typed 动态样式与深色主题；
- 打开文件对话框（已交付）、worker、任务 scope 与模型提交之间的异步连接。

**完成判据：**

- Todo 可以完成输入、添加、完成状态、筛选、列表重排、删除和键盘操作。
- 中文 IME 的候选确认与表单提交不互相穿透；焦点和文本编辑状态不随数据重排错位。
- 模型提交后同步清理草稿，失败保留草稿；旧异步结果不写入新一代窗口。
- 编译错误定位到具体的属性、样式或回调，而非只暴露宏展开后的内部类型。
- 应用可以在 Windows 上运行和操作，基本工作流具有可复跑行为。

## 阶段三：Windows 完整 Todo

**交付：**愿景所定义的完整 Windows Todo，以及支撑小型本地工具的 SDK 闭环。

这一阶段扩展真实应用需要的平台与服务能力：

- 多窗口声明、activation、显示、隐藏、关闭、重开和关闭确认；应用会话策略与显式退出已交付，`QuitOnLastClose` 为默认，`StayResident` 允许零窗口常驻并由托盘恢复，证据见 [stage-three 会话验收](../实现/stage-three-会话-验收.md)；
- 整页滚动（滚轮与翻页键）已交付，可见证据见 [stage-three 宿主滚动验收](../实现/stage-three-宿主滚动-验收.md)；焦点与 caret 显露已交付，可见证据见 [stage-three 焦点显露验收](../实现/stage-three-焦点显露-验收.md)；覆盖层滚动条（绘制、thumb 拖动与轨道翻页）已交付，可见证据见 [stage-three 滚动条验收](../实现/stage-three-滚动条-验收.md)；窗口化 `For`（10,000 行列表）已交付，可见证据见 [stage-three 窗口化 For 验收](../实现/stage-three-窗口化-for-验收.md)；100%/150% 汇总验收见 [stage-three 滚动总验收](../实现/stage-three-滚动总验收.md)；
- 辅助技术已交付：每窗口 UIA fragment root、只读树、Invoke/Toggle/Value/SetFocus、焦点/状态/结构事件、最小 TextPattern 与窗口根 ScrollPattern；契约见 [ADR-0012](../adr/0012-uia-derived-tree-and-action-queue.md)，三窗口 Inspect/Narrator 与 100%/150% 证据见 [stage-three 辅助技术合同与朗读验收](../实现/stage-three-辅助技术总验收.md)；
- 菜单、快捷键、上下文菜单、应用托盘及应用级任务已交付；契约见 [ADR-0013](../adr/0013-menu-and-tray-host-services.md)，可见证据见 [stage-three 菜单栏验收](../实现/stage-three-菜单栏-验收.md)、[stage-three 快捷键验收](../实现/stage-three-快捷键-验收.md)、[stage-three 上下文菜单验收](../实现/stage-three-上下文菜单-验收.md) 与 [stage-three 托盘验收](../实现/stage-three-托盘-验收.md)；文件对话框家族（打开/保存/文件夹）已交付，可见证据见 [stage-three 保存与文件夹验收](../实现/stage-three-保存与文件夹-验收.md)；
- 文本编辑历史已交付：每个输入保存有界 undo/redo，Ctrl+Z/Y 映射到聚焦启用输入，连续单字符输入合并为至多 64 个字符的撤销步；契约见 [ADR-0014](../adr/0014-text-edit-history.md)，可见证据见 [stage-three 文本编辑历史验收](../实现/stage-three-文本编辑历史-验收.md)；
- 文本编辑血统已交付：每个输入以挂载 origin 与单调 revision 区分结算、stale settlement 与外部替换；外部替换清空历史并按新值夹取或保留 selection，组合中取消组合；契约见 [ADR-0019](../adr/0019-text-edit-origin-and-revision.md)，可见证据见 [stage-three 外部替换与组合验收](../实现/stage-three-外部替换与组合-验收.md)；
- 剪贴板复制、剪切与粘贴已交付：Ctrl+C/X/V 通过可注入的 `ClipboardProvider` 读写 `CF_UNICODETEXT`，复制精确写出已提交选区，剪切只在写入成功后删除选区，粘贴过滤控制字符后走同一插入 reducer，隐藏宿主默认不触碰系统剪贴板；契约见 [ADR-0015](../adr/0015-clipboard-host-capability.md)，可见证据见 [stage-three 剪贴板验收](../实现/stage-three-剪贴板-验收.md)；
- 文件拖放已交付：每个可见且注册 `on_drop` 的窗口拥有 OLE `IDropTarget`，只接受启用窗口的 COPY `CF_HDROP`，路径按源顺序在 `Phase::Event` 以 `DropEvent` 交付；隐藏宿主、模态对话框与关闭确认拒绝拖放，非文件数据不进入处理器。契约见 [ADR-0016](../adr/0016-ole-file-drop-target.md)，可见证据见 [stage-three 文件拖放验收](../实现/stage-three-文件拖放-验收.md)；
- 内容 handle 与本地编辑状态隔离；
- 应用实际需要的文本、布局、样式与主题能力；
- 使用指南、错误处理、最小应用模板和 IDE 中的开发体验；
- 真实工作流中的启动、更新、静止与长时间运行行为验证。

**完成判据：**

- 完整 Todo 在 Windows 上具有可重复的输入、中文 IME、窗口与辅助技术行为验证。
- 小工具所需的核心能力可用，不支持的能力被明确拒绝。
- 外部开发者能够不依赖框架内部的隐含知识，运行、修改并复现应用。
- 这一阶段的试用以了解目标 API 为主，不提前承诺稳定的公共接口。

## 阶段四：三平台一致的开发体验

**交付：**同一开发模型在 Windows、macOS 和 Linux 的已支持能力范围内成立。

这一阶段扩展并验证平台能力：

- Windows、macOS、Linux 的窗口、输入、IME、焦点、DPI、surface 与资源重建；
- Windows UIA、macOS NSAccessibility、Linux AT-SPI 的实际辅助技术路径；
- Linux Wayland 和 X11 的真实行为差异；
- 平台能力、退化路径和明确的类型化 `Unsupported`；
- 字体、词典数据、资源与发布资产的完整性；
- 新开发者从空目录创建、运行、修改和诊断小型应用的完整流程。

**完成判据：**

- 同一 Todo 在所声明的平台与输入、辅助技术组合上实际通过验证。
- 一个平台的结果不替其他平台背书，已知差异不静默改写。
- 形成完整的 SDK 产品形态，而不是将底层探针拼接为平台支持宣称。

## 阶段五：稳定的桌面开发基线

**交付：**经过真实外部使用验证、可以长期维护的桌面开发模型。

这一阶段的工作依据真实应用，而不是预设控件目录：

- 根据小型桌面工具的实际缺口补充控件、主题、布局、文本与工具链；
- 收敛常用公共 API，同时保留具有明确边界的实验扩展；
- 维护跨平台回归、依赖发布和版本迁移质量；
- 以固定场景持续报告性能与资源行为，不提前承诺未经验证的数字；
- 通过外部开发者构建和修改应用，检验语法、生命周期、错误诊断和调试能力。

**完成判据：**

- 外部开发者可以独立完成小型桌面工具，而不需要框架内部知识。
- 公共 API 的变动与迁移可以解释和验证，文档与实现保持一致。
- 版本稳定承诺以实际使用和迁移成本为依据，而不是以曾经发布为依据。

## 独立扩展

以下能力沿核心身份、资源与生命周期边界发展，不阻塞核心桌面产品交付：

- 图像、视频、外部纹理和三维内容接入；
- 完整三维资产管线、材质、动画或场景编辑；
- 大型数据表格、图表与富文本编辑器；
- 更广泛的 Tailwind 风格词汇与自定义样式注册；
- 新平台或新的平台后端。

它们只有在相应能力得到实际实现和验证后才纳入可用范围。

## 路由原则

1. 少量 API 先贯通，再扩展界面与功能表面。
2. Windows 的真实输入、文本与窗口行为尽早进入验证，不留到最后补齐。
3. 生命周期与更新语义是 API 的基础，不是后续优化。
4. 控件与样式根据真实开发场景增长，不以列表长度代表完成度。
5. 新能力保持愿景中三项原则的一致性。
