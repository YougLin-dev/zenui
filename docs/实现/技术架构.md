# 技术架构

本页规定 ZenUI 的目标技术模型。实现进度由[路线图](../产品/路线图.md)管理；尚未实现不改变本页定义的目标边界。

## 系统模型

ZenUI 由一棵保留的界面树和一套响应式更新机制组成。组件、数据、平台服务与渲染围绕同一个界面模型协作，不另设一条重建界面的更新路径。

```text
普通 Rust 组件与数据处理
        ↓
view! → MountPlan → 保留的界面树
                      ↓
            Signal / Memo / Store
                      ↓
            相关字段与结构更新
                      ↓
       布局、文本、绘制、输入、语义与呈现
```

界面树持有节点身份、焦点、选择、光标、composition、命中关系与本地控件状态。布局、字形、绘制缓存和语义快照是已提交界面的派生结果，不成为另一份可独立修改的界面现实。

组件只挂载一次。普通字段更新不重新执行组件，也不比较两棵虚拟界面树；只有显式的结构输入决定挂载、移动、替换和卸载。

## 身份与执行边界

Copy handle 表示轻量身份。复制它既不复制底层数据，也不延长对象生命周期。

身份和存活判断由运行时统一管理。业务键、界面节点、Owner、事件注册、窗口 activation、任务和图形设备属于不同的身份与代际维度，不能以一个可复用整数代替。

运行时在每个调用边界安装明确的执行上下文。挂载、事件、Memo 计算、界面绑定、任务交付、worker、布局和渲染具有不同能力；代码所能读取或修改的状态由该上下文决定，而不是由它恰好持有一个 handle 决定。

普通 UI Signal 在事件内可读取和赋值；计算、布局和绘制不提供这种写入权限。业务模型的失效读取具有类型化结果，不能以默认值或上次值伪装成功。

事件先检查 callback registration 与界面代际，再执行业务命令；模型行与任务资源在各自提交边界另行验证。即使模型行仍存活，已卸载界面的旧事件也不获得分发资格。

## 挂载、释放与暂存

挂载执行组件 setup 并构造 `MountPlan`。计划包含未发布的节点描述、数据 slot、事件与延迟 factory；预设的 Owner 管理 setup 中的订阅和资源。`MountCx` 在创建组件、Children 与结构分支时提供对应归属，不成为由用户任意切换的全局上下文。

计划树完成属性、factory、Owner、key 与依赖检查后才发布保留界面。挂载失败取消整个拟议计划，并释放 setup 已创建的监听、绑定、任务和子 Owner。

释放先撤销事件与任务交付，再从子级到父级释放 Owner；同级 cleanup 按注册逆序执行。 disposing 状态的 Owner 不接受新挂载，重复释放幂等。清理回调仍可访问尚存的父级状态。

模型和界面在各自边界中暂存写入，同一 turn 可以按程序顺序读取本领域的新值，外部只在一次完整提交后观察。提交应用过程中没有用户回调和剩余可失败的领域操作。

暂存中提前产生的业务身份可以保留编号；失败释放预约并让该位置的代际不能被后续对象复用。根暂存的丢弃不是撤销已发生的宿主、GPU 或外部服务操作。

## 组件、结构与样式

`view!` 生成 `MountPlan`。它只描述节点、属性、事件、绑定与延迟构造的结构，不持有已经呈现的另一棵 VDOM。

普通数据位接收 handle、字面量或 `once`。比较、条件推导、格式化与查询留在组件 setup 中命名；事件、具名 slot 与分支 factory 使用与所在位置匹配的类型。宏不根据“表达式是不是闭包”猜测数据语义。

`For` 按业务键管理界面节点。重排保留节点及其编辑状态；key 消失卸载对应 Owner，但不删除业务模型。`Show` 管理分支的挂载与卸载，不用视觉隐藏代替生命周期变化。

样式将静态 class 编译为 ZenUI 的原生属性、状态和优先级；动态样式传递类型化输入。浏览器 CSS 的 selector、DOM 默认值和插件系统不属于这套模型。theme、variant 与 inline style 的规则属于 ZenUI 自身，不因 Tailwind 词汇的相似性而引入 CSS 计算引擎。

## 派生与查询

Memo 在所有依赖达到本次值后再求值，并以新的依赖集一次完成依赖替换。结果变化需要使下游获悉；结果未变化时抑制下游计算。菱形链与分支切换不会暴露不同代际的混合值，失败计算保留可诊断、可恢复的状态。

Store 拥有候选索引与字段反向依赖。过滤查询覆盖真实候选，包括当前不在结果内、但因字段变化可能进入结果的行。所有消费者共享查询 cache 与 revision；`Memo<RowSet>` 只观察这些 revision，不在每个消费方复制候选字段边。

一次模型提交归一化为新的模型 epoch，候选变化与字段变化只标记相关缓存，列表真实读取时按稳定结果构造共享的 identity snapshot。aggregate 与 emptiness 直接读取计数或 membership，不为了回答布尔值物化完整 RowSet。

## 应用与宿主

UI、业务模型、宿主服务和渲染归属不同，但可以通过稳定的 handle 和明确操作连接。

事件在 command turn 中执行。模型事务提交模型，UI 值同步改变界面输入，随后统一计算派生值和提交相关更新。事务不把模型、UI、窗口、文件和 GPU 宣称为可以共同回滚的整体。

窗口、菜单、托盘与系统对话框是宿主服务，不进入 `view!`。目录键标识窗口类型，activation 区分一次实际打开；隐藏、关闭和退出应用具有不同生命周期。

worker 只接收可跨线程的工作与结果。任务归属决定工作能否跨越窗口关闭继续，交付归属决定结果能否影响对应模型或界面。系统对话框的窗口锚点不自动成为后台工作的所有者。

## 布局与绘制

布局只负责几何计算。文本系统负责字形、换行、字体选择与文本测量；TextInput 另行负责选择、光标、composition、编辑提交和输入法。

在同一次已提交布局之后，绘制、命中、焦点、光标与辅助功能消费一致的几何。滚动、裁剪和坐标变换不能只更新绘制而留下旧命中区域或旧辅助行为。

绘制使用明示的格式、颜色、alpha、裁剪、资源归属和设备代际。缓存以影响结果的几何、文本、样式、父级条件和设备状态为依据；子树缓存不承诺光栅化必然局部发生。

动画、滚动瞬态与 frame timestamp 属于呈现过程，可以在渲染边界内调度，不必持续写入业务响应式图。业务模型提供稳定输入，绘制层负责中间状态与空闲停帧。

内容 handle 表示图像、视频、画布、外部纹理或其他内容描述。每个挂载的内容叶节点具有自己的资源和设备生命周期；资源描述的共享不等于原生 attachment 的共享。

## 平台结构

Windows 是首个完整产品平台，真实输入、文本编辑、窗口和绘制在 Windows 上形成完整闭环。

Taffy、Parley、Vello 及相应组件承载布局、文本和绘制工作，不决定 ZenUI 的公共身份、事件或生命周期模型。依赖版本随实际实现验证和锁文件管理，不将研究时版本组合视为永久冻结。

Windows 优先是交付次序，不是让公共模型依赖 Windows 专有生命周期。平台后端在一致语义下实现各自输入、窗口、字体和辅助技术适配，macOS 与 Linux 在对应平台接入后获得真实验证。

## 研究来源与架构吸收

| 研究对象 | 借鉴内容 | ZenUI 的独立边界 |
| --- | --- | --- |
| SolidJS、Leptos | 一次挂载、细粒度依赖、结构 Owner 与 keyed list | DOM、垃圾回收假设、任意闭包数据位 |
| React、Dioxus | 结构表达与类型化组件的可读性 | VDOM、默认重新执行组件、props 重建模型 |
| Slint | 编译期转换、错误定位与开发工具质量 | 独立脚本语言 |
| GPUI、Masonry、Floem | 保留节点、工作阶段划分、复杂控件扩展 | 另一套与界面树竞争的数据通知权威 |
| Flutter、FLUI | 布局与绘制的失效、缓存和提交前检查 | 三棵 UI 树与以 rebuild 为中心的模型 |
| egui、iced | immediate 与消息驱动模型的适用边界 | 每帧重建或全量消息流作为默认界面模型 |
| Web 框架 | 属性与结构的可读性、平台服务的需求清单 | WebView、DOM、CSS 引擎和 JavaScript 运行时 |

deltaui、llimphi、Parley、Taffy 及既有原型提供局部机制研究，不提供 ZenUI 的开箱架构。其依赖组合、生命周期承诺与平台结论需要在自身边界内重新验证。

## 公开接口的独立性

公共接口以 ZenUI 的身份、属性、内容和生命周期为基础。布局节点、设备对象、绘制资源与帧调度属于内部实现，由对应组件封装。

ZenUI 的核心是二维桌面界面；图像、视频与三维内容通过内容叶节点接入。平台支持和控件能力由对应实现与验证决定。
