# 验证重点

本页说明[技术架构](技术架构.md)在实现过程中的关键验证行为。逻辑语义使用可重复测试，平台能力以 Windows 真实应用验证；headless 测试承担相应的逻辑验证。

## 身份与更新

- `Signal<String>` 的 Copy handle 在多层 `move` 分支中可用，不要求数据自身 Copy。
- 身份耗尽、非法重入、递归 Owner / Memo 调用与深层结构使用明确的拒绝或回收路径，不能用序号别名和进程栈溢出表达错误。
- 事件读取不登记依赖，Memo 计算替换不再使用的依赖。
- 字段更新只影响相关计算与节点，不重新运行组件。
- `with` 保持只读；计算、绑定、布局与 worker 不获得 UI 写入能力。
- 非法执行上下文在状态变化和应用后续动作之前被识别，之后的合法命令能够独立运行。
- 一次真实提交的 model Add 后若发生 UI reset 框架 fault，模型与 UI 分别呈现其已提交结果，恢复不会把重试默许为重复插入。
- 模型暂存的身份预约在失败后不能复用成另一对象的代际；不依赖撤销所有计数或分配证明回滚。
- 一个应用派生值可被多个窗口共享，单个窗口的释放不影响其他消费者。

## Store、派生与结构

- `once` 在重新挂载时重新读取，重排不重复读取，过滤返场不复用旧挂载的一次性文本。
- 当前不匹配候选行的字段变化能够使对应过滤查询进入该结果，无关节点不增加额外求值。
- 缓存只归一化模型 epoch 后的相关候选与字段变化，同一 revision 的首个 list 读共享一次 identity 物化。
- `is_empty(filter)` 与聚合标量不请求完整 RowSet，row visits 和 identity 物化保持为零。
- Memo 的菱形链、动态依赖替换、长链、相等结果与失败重算不发布混合 epoch，依赖边和计算 stack 在失败后仍可恢复。
- 正常删除先停止相关消费，不把卸载后的普通变化误报为异常读取。
- `For` 重排保留控件、Owner、焦点和编辑状态；重复 key 在改变界面前被拒绝。
- 窗口化 `For` 只挂载宿主行窗口内的行，上下 spacer 保持完整行范围；窗口外的行没有 Scene 元素与 Node ID，重新进入的行获得新 Owner、`once` 值与本地状态（ADR-0011）。
- 挂载在创建 Memo、监听、任务和局部资源后失败仍释放整个拟议计划及子 Owner，存活的兄弟组件保持原有提交。
- key 消失卸载 UI 而不删除模型；虚拟列表不把一行的 caret、IME 和任务交付带入另一行。焦点行在窗口外一行内保留，更远时 blur 并取消组合，不隐式焦点跳转。
- 长链、共享分支、重复写入和循环引用具有确定的计算与错误行为，不出现中间提交。

## 命令与异步

- `WriteOp` 的创建不改变模型、保留身份或启动 I/O；提交时恰好执行一次。
- 同步模型提交与应用草稿清理在同一个连续 command turn 中结束，统一发布。
- 模型拒绝时保留草稿，之后的合法命令不被旧失败阻塞。
- worker 无法捕获或写入 UI Signal、窗口上下文或渲染 attachment。
- 旧窗口交付被丢弃，旧任务不会写入重新打开的新一代窗口。
- 应用所有权任务可跨窗口工作，模型提交与界面交付分别判断是否有效。
- 异步清理不能消除用户后续输入；错误通道不代替提交、取消或持久化结果。

## 语法与属性

- `view!` 在真实 runtime 上生成 MountPlan，组件尾部的 `?` 保留普通 Rust 控制流。
- 数据位 handle、字面量、`once`，事件、Children、`Show.fallback` 与 `For` factory 都有明确的类型和调用时机。
- 子分支不提前构造；FnOnce 不被当成可重复 factory。
- 每种属性的来源和同步方式由其类型决定，不使用万能闭包绑定协议吞并语义差异。
- 未知 class、属性类型、事件 payload 和资源不兼容具有定位清晰的编译或运行诊断。
- `class` 字面量在展开期解析为类型化声明，简写展开到长手属性；未知 token、复合条件和动态 class 是编译错误。快照携带声明而不是 class 字符串，原始 `class`/`style:*` 属性仍由场景显式拒绝。
- 绘制声明经 `SceneElement::resolved_style()` 暴露；语义颜色角色由调色板解析，圆角只影响绘制，不改变布局、命中测试与 caret 几何，不透明度只作用于元素自身的绘制。GPU 回读验证背景、文本、边框、圆角与不透明度。
- 场景重建可复用 `SceneCache` 的文本 layout 与 Taffy 测量结果。缓存命中、viewport 裁剪与无缓存构建产生相同几何、样式与字形；viewport 外的元素保留几何但不生成 glyph run、caret stops 或绘制。500 行文本导入后的输入重建由 `scene_bench` 提供可复跑测量。
- 条件声明从已提交状态或宿主瞬态（hover、press、键盘模态）选择，瞬态不写回快照；rank 与源码顺序都有测试。状态变体里的布局或文本属性是编译错误，手工构造的快照同样被场景拒绝。
- 类型化 inline 声明保持快照 `Eq` 且不出现 `f32`；`px`/`em` 几何、inline 优先于 class 状态变体、动态更新保留 Node ID 都有测试。未知 `style:` 属性与错误值类型有编译失败用例。
- 字号进入整形、测量与 caret 几何；字重作为整形请求传入 Parley（回退字体可能复用同一字形）。`em` 按元素字号解析。100% 与 150% 缩放下的绘制位置与测量一致，文本不越出自身盒子。
- hover、press 与键盘模态是宿主瞬态：经 `SceneEnv` 进入场景，不进入快照；按钮与复选框在松开同一节点时激活，拖出后松开不激活，捕获丢失、焦点丢失与关闭清除 press。重排后按最后的指针位置重新命中，不残留旧 hover。`focus-visible:` 跟随键盘模态，`aria:pressed` 与按下瞬态分别可读。
- 应用外观是已提交状态：快照携带它并参与相等性；只有依赖外观的 memo 在切换时重算。`dark:` 声明按快照外观选择，内建控件使用对应调色板。主题切换保留焦点、caret 与 selection；宿主接受初始外观。
- 宏生成的调用不依赖调用方额外导入内部实现类型；独立消费者使用别名 facade 时仍能编译，宏与 facade 不匹配有明确诊断。
- 未知 class、属性类型、事件 payload 的多个错误保留稳定次序；Unicode 与 escape 无法精确映射时退化为完整字面量 span 加 token range。

## 编译失败测试

根包的 `cargo test` 运行 compile-fail 套件：trybuild 编译 `tests/compile_fail/`
下的用例，并与同目录、同名的 `.stderr` 比较；`pass/` 子目录的用例必须通过，
用来证明 harness 能构建公开 facade。用例只使用公开 `zenui` API，运行在普通
workspace 测试矩阵中，不依赖 Windows。

新增或修改用例后运行 `TRYBUILD=overwrite cargo test --test compile_fail`
生成期望文件，再人工确认 `.stderr` 指向正确的 token/span；之后用普通
`cargo test` 复跑。诊断不匹配会使测试失败，不会被跳过。

## 窗口与宿主

- 窗口声明不即刻调用内容 factory，重复 show 不重复挂载。
- show、hide、show、close、show 产生正确 activation 和 factory 次数，旧原生事件不命中新代。
- pending close 只接受一次有效决定；Deny、Allow、Escape、旧 reply 与确认窗关闭各自有确定结果。
- 应用任务和窗口任务的取消与交付互不误用。
- 外层主事件循环之外的宿主回调只交付事件；菜单助记键与快捷键、鼠标和辅助激活各只生成一次逻辑命令。
- 对话框锚点失效不自动取消应用所有权的任务，也不把结果重定向到新窗口。
- 退出顺序应取消输入、IME、语义与交付，之后停止呈现和释放对应本地资源。
- 多窗口的可见窗口验收、隐藏 smoke 与 CI WARP 的证据等级分开记录；隐藏窗口通过不表示原生可见验收通过。跨显示器混合 DPI 与实机 device loss 保持 #63 的独立缺口，见 [stage-three 多窗口验收](stage-three-多窗口-验收.md)。
- 只读 UIA 树与场景在同一份快照上提交：根名称取窗口标题，角色映射控制类型，`aria:label` 优先于可见文本，`id` 映射 AutomationId，`disabled`/`checked`/`aria:pressed` 与焦点进入状态；不产生节点的 spacer 只把子元素并入最近父级。
- `WM_GETOBJECT` 只对 `lParam == UiaRootObjectId` 交回当前窗口的 fragment root；provider 按 NodeId 保持 provider 本地 runtime ID，滚动只改变物理边界，不改变存活节点的 ID。隐藏、关闭中或零客户区窗口不发布树，缓存 provider 返回元素不可用。
- 关闭确认的父窗口保留树并报告 IsEnabled=false；确认窗口与 Details 等目录窗口各自拥有独立根。
- Invoke 与 Toggle 的存在性来自快照语义（`Click`；`Change` 加 `checked`/`aria:pressed`）；`ValuePattern` 属于文本输入的读模型，写权限来自 `Input` 语义。provider 线程只入队并唤醒窗口；UI 线程按顺序取动作、读取最新快照重验，再复用 `click_node`/`change_node`/`replace_text_node`/`focus_node`。禁用、过期、隐藏与关闭挂起目标报告不可用且不运行 handler；组合中或禁用的输入为只读。SetValue 整体替换、恰好一次 `on:input`、caret 到末尾并记录一条撤销；新值相同时为静默无操作。SetFocus 只在窗口 HWND 前台时移动运行时焦点，后台窗口不抢前台。
- UIA 事件由相邻两次发布树按 runtime ID 差异产生，顺序为结构、属性、焦点：ChildAdded 发在新增子节点，ChildRemoved 在父节点携带被移除的 runtime ID，ChildrenReordered 在父节点；新子树只报告顶层新增。IsEnabled、ToggleState（`checked` 与 `aria:pressed` 共用）与 Value 只比较两次都存在的节点；根 IsEnabled 由宿主窗口 provider 通知，规划器不重复投递。只有前台窗口投递焦点事件，后台焦点变化不在激活时补发；焦点清空没有 UIA 事件，客户端以 `GetFocus` 为空观察。指针 hover/press 与滚动几何不改变树，因此不产生事件；发布锁释放后才投递，单条失败不阻断后续。
- UIA TextPattern 在 `text-input` 的 Edit 节点上暴露最小 `ITextProvider`/`ITextRangeProvider`：文档取已提交值并排除 preedit，UIA UTF-16 code unit 在 provider 调用线程与运行时字符偏移互换并夹取到字符边界，组合中的显示 caret 映射为被替换区间的文档终点；GetSelection 与 TextEditState 一致，DocumentRange/折叠 caret/非折叠 selection 的矩形分别取元素盒、caret 装饰与逐行 selection 装饰，完全离开视口时返回空数组；Select 只入队，UI 线程重验启用、`on:input` 与组合后调用 `set_selection_node`，不派发 `on:input`；组合中、禁用与只读输入返回元素不可用，查找、移动、扩展、比较、多选与滚动等 range 方法返回 `UIA_E_NOTSUPPORTED`。隐藏测试只覆盖 provider 调用路径与 UTF-16/几何转换，可见进程外客户端、Inspect 与 Narrator 结果仍是验收主证据。
- 窗口根暴露最小 UIA `ScrollPattern`：只报告垂直可滚动状态、view size 与百分比，水平固定为 `NoScroll`；`Scroll` 复用键盘翻页与滚轮行步长，`SetScrollPercent` 把 0..100 四舍五入到最近整数逻辑像素后夹取。provider 只入队，UI 线程按当前场景重验；零最大偏移、隐藏、禁用与关闭中窗口拒绝或丢弃动作。滚动只改宿主偏移，Node ID、焦点、caret、selection、draft、组合、快照相等性与运行时计数不变，也不触发 reveal；不新增 `ScrollItemPattern`、水平滚动、嵌套容器或滚动条 Node ID。隐藏测试只覆盖 provider 与场景接口；进程外客户端与 Inspect 的 100%/150% 结果是主证据，见 [stage-three 辅助技术滚动验收](stage-three-辅助技术滚动-验收.md)。
- UIA 合同由 [ADR-0012](../adr/0012-uia-derived-tree-and-action-queue.md) 固定：每窗口一个 fragment root，provider 只读当前不可变发布树，写操作按每窗口 FIFO 在 UI 线程重验。隐藏、关闭中与零客户区窗口不发布树；关闭确认的父窗口保留树但报告禁用，确认窗口有独立根。未实现 MSAA 桥、SelectionItem、虚拟化 item pattern、水平/嵌套滚动与多显示器验收。Inspect 的三窗口树/属性/边界与 Narrator Speech Recap 的 100%/150% 记录见 [stage-three 辅助技术合同与朗读验收](stage-three-辅助技术总验收.md)。
- 原生菜单栏在 HWND 创建前由目录的 `MenuSpec` 构建：命令 id 按声明前序分配，标签、分隔线、子菜单与默认 enabled/checked 进入 `HMENU`；创建、`Host::resize` 与 `WM_GETDPISCALEDSIZE` 都以菜单存在性计算非客户区，保持逻辑客户区。`WM_COMMAND` 只接受 `lParam=0` 与 `HIWORD=0/1`，宿主把数字 id 映射回声明 id 并调用 `Runtime::dispatch_command`；隐藏、待决关闭与过期窗口不运行。`MenuCommand::bind_shortcut` 在声明期归一化快捷键，同一窗口的重复快捷键是目录错误；宿主为每个窗口构建 `HACCEL`，`run`/`pump` 在 `TranslateMessage` 前调用 `TranslateAccelerator`，一次按键只派发一次 `CommandSource::Accelerator`。聚焦文本输入的 IME 组合与 Ctrl+A/Z/Y/C/X/V 优先于快捷键；禁用项在菜单与快捷键两个入口都不运行，`HACCEL` 随窗口条目注销。`WM_INITMENU`/`WM_INITMENUPOPUP` 用窗口在 factory 登记的只读回调重新求值每个命令的 enabled/checked，再写回原生项；没有回调时使用声明默认值。回调内的 Signal 写与 Store 事务被拒绝并作为 typed error 返回，panic 被 contain，失败时该次菜单初始化保持原状；`WM_COMMAND` 派发前再次求值，禁用项不运行。`WM_ENTERMENULOOP` 取消 IME 组合并清除指针瞬态。创建成功的 `HMENU` 归窗口所有并由 `DestroyWindow` 注销；创建失败时由构建值注销。`resize` 在运行机 DPI 下保持精确客户区，`WM_GETDPISCALEDSIZE` 的 96/144 计算包含菜单栏。隐藏 `GetMenu`/`GetMenuState` 测试是部分证据，100%/150% 可见证据见 [stage-three 菜单栏验收](stage-three-菜单栏-验收.md) 与 [stage-three 快捷键验收](stage-three-快捷键-验收.md)；节点级上下文菜单仍是后续工单。
- 窗口级上下文菜单由 `WindowCatalog::context_menu` 声明：命令与菜单栏共享处理器但 id 不能重复，菜单不声明快捷键，因此不进入 `HACCEL`。宿主在 `WM_CONTEXTMENU` 中把 presenter 与声明移出 `Host`，在借用之外用 `TrackPopupMenuEx(TPM_RETURNCMD)` 打开 `CreatePopupMenu` 构建的菜单；右键的屏幕坐标原样使用，键盘的 `(-1,-1)` 换成客户区中心。菜单关闭后宿主重新借出，presenter 归还，返回命令只在 owner 仍接受输入时以 `CommandSource::ContextMenu` 派发一次；弹窗期间关闭或隐藏的 owner 丢弃返回值。presenter 的 panic 被 contain 为 `HostError::ContextMenuPresenter`。隐藏宿主不安装原生 presenter，CI 用注入的 fake 记录请求；弹窗期间同步投递的宿主唤醒仍交付任务结果，owner 在弹窗期间关闭不产生 stale 命令。上下文菜单的 enabled/checked 使用声明默认值，`on_menu_state` 仍只作用于菜单栏；弹窗期间跳过 `WM_INITMENU`/`WM_INITMENUPOPUP` 的菜单栏状态应用，避免两套从 1 开始的数字 id 互相改写。隐藏测试是部分证据，100%/150% 右键、Shift+F10 与 Apps 的 `#32768` 弹出菜单与状态变化见 [stage-three 上下文菜单验收](stage-three-上下文菜单-验收.md)。
- 应用级命令通过 `Runtime::on_app_command` 在首个窗口打开或根树挂载之前注册，处理器不随窗口关闭释放。`Runtime::dispatch_app_command` 在没有窗口时也能运行，事件通过 `CommandEvent::window` 暴露可选的目标 activation；目标必须是存活的 activation，过期返回 `Stale`，跨 Runtime 返回 `WrongRuntime`，隐藏与待决关闭目标仍合法。菜单栏与上下文菜单的声明项可以由应用级处理器承接，窗口派发只在窗口没有注册同一 id 时回退到应用级处理器，并带上窗口目标；`CommandSource::Tray` 从不运行窗口处理器。处理器在 `Phase::Event` 中可写应用 Signal/Store 并排队 show/hide/close 请求，由 `apply_window_requests` 结算。重复 id 返回 `AlreadyRegistered`，启动后注册返回 `RegistrationClosed`，panic 被 contain 为 `HandlerPanicked`；零窗口派发只做无界面的命令收尾。
- 应用托盘在 `Runtime::declare_tray` 中一次性声明 tooltip 与右键菜单，运行时校验 UTF-16 tooltip 上限、重复命令、快捷键与大菜单；每个菜单命令在宿主启动时必须有应用级处理器。宿主创建独立的隐藏顶层托盘 HWND，`WM_APP + 4` 只从该 HWND 接住通知区域回调，`TaskbarCreated` 广播也只在该 HWND 触发重新添加。`NOTIFYICON_VERSION_4` 的事件在 `lParam` 低字、鼠标位置在 `wParam`；左键/键盘恢复可见焦点窗口、primary 或任一存活窗口，右键菜单在宿主借用之外展示并以 `CommandSource::Tray` 派发一次。默认会话下图标随最后一个窗口关闭移除；常驻会话保留图标，`Host` 析构时幂等移除，`TaskbarCreated` 后重新添加。presenter 的 add/update/remove/menu 调用都 contain panic；隐藏宿主默认没有原生 presenter，fake 记录 add/update/remove 与菜单选择。第一切片使用系统共享 `HICON`，不销毁；Windows 11 溢出面板与自定义图标资产有明确边界。隐藏测试是部分证据，150% 可见的图标、tooltip、菜单、点击恢复、Explorer 重启与最后窗口移除见 [stage-three 托盘验收](stage-three-托盘-验收.md)。
- 应用会话在启动前声明一次 `SessionPolicy`：默认 `QuitOnLastClose` 在最后一个窗口关闭后结束宿主循环；`StayResident` 允许零窗口会话，但原生宿主要求托盘，否则 `Host::open` 返回 `TrayRequired`。`SessionCtx` 在命令处理器中排队 `request_show` 与 `request_quit`；会话动作在窗口请求之后结算，show 可重开已关闭的目录窗口，quit 关闭全部 activation（包括 stage-one `open_window`）、释放待决关闭确认并让之后的 show 返回 `State`；直接调用 `Runtime::quit` 时尚未应用的窗口请求被丢弃，排在同一批 `Quit` 之后的会话动作也随会话结束丢弃。宿主用会话而不是窗口数控制 `run`/`pump`，零窗口常驻时 worker 唤醒回退到托盘 HWND，托盘保留并恢复 primary；shell 的 SendMessage 托盘回调之后补投 `WM_NULL`，确保恢复/退出的 HWND 同步发生。隐藏测试是部分证据，150% 关闭到托盘、点击/菜单恢复与 Quit 移除图标见 [stage-three 会话验收](stage-three-会话-验收.md)。
- 证据等级：进程外原生 UIA 客户端与 Inspect 的 100%/150% 结果是主证据，隐藏 smoke 只覆盖树形状、名称、状态、边界、生命周期、动作排队与事件规划；见 [stage-three 辅助技术验收](stage-three-辅助技术-验收.md)、[stage-three 辅助技术动作验收](stage-three-辅助技术动作-验收.md) 与 [stage-three 辅助技术事件验收](stage-three-辅助技术事件-验收.md)。

## 滚动与长列表

- 滚轮单位与累积：`WHEEL_DELTA` 120、`lines_per_notch × 24` 逻辑像素、page-scroll 哨兵与 0 设置各有确定结果；sub-notch residue 双向对称累积，夹取与滚轮之外的偏移变化清零累加器。
- 边界处被夹掉的距离不形成 phantom offset；重复越界 notch 后第一个反向 notch 立即移动。零最大偏移时滚动键不被消费。
- 键盘翻页为 `max(1, floor(viewport_height − 24))` 并保留重叠行；Home/End 到两端；聚焦编辑器的编辑键优先，组合期间翻页键归 IME。
- 显露最多两遍，caret 几何优先于边框盒，超高元素顶部优先；显式滚动不移动焦点或 caret，也不触发显露。
- 场景的 content extent、applied offset 与 max offset 相互一致；平移只应用一次，绘制、命中、caret、selection、preedit 与滚动条共享同一份几何；Node ID、元素数与快照相等性不随偏移变化。
- 覆盖层滚动条不新增 NodeId，thumb 最小 24 逻辑点；命中优先于内容，拖动夹取到 `[0, max]`，轨道点击翻页，捕获/焦点/隐藏/关闭结束拖动。
- 偏移生命周期：hide/show 保留并重新夹取，close/reopen 归零，resize、DPI 与设备重建保留逻辑值，快照变化保留并重新夹取；没有 anchoring 或 follow-the-end。
- 窗口化 `For` 按行带几何、偏移与视口换算行窗口；行窗口不变时滚动不重建快照，首行变化或视口下缘跨入新行时至多一次重建，成本与总行数无关；聚焦行留在一行 grace 内，更远则清除焦点；Tab 只在已挂载行间遍历；行窗口刷新不重置滚轮 residue。
- 证据等级：隐藏 smoke 与 WARP 只是部分证据；可见 Windows 11 单屏 100%/150% 才是原生验收；模拟设备丢失当前只有单元测试证据，不声称多显示器或混合 DPI。契约见 [ADR-0010](../adr/0010-scroll-is-presentation-state.md) 与 [ADR-0011](../adr/0011-windowed-for-mounting.md)，汇总证据见 [stage-three 滚动总验收](stage-three-滚动总验收.md)。

## Windows 真实闭环

- TextInput 的本地 input 产生匹配 origin 只确认同步，下一次独立外部 reset 仍能按 revision 应用；前一次 origin 不抑制后续无来源清空、撤销或远端值。
- 两个连续本地 edit 在 value delivery 前保持 revision，旧快照不回滚新输入；同 key 重新挂载拒绝旧 origin。
- 外部 replace 在 composition 中的 commit / cancel、selection 夹取或恢复策略通过同一 reducer trace 可观察；IME 候选 Enter 不触发表单提交，之后的普通 Enter 只提交一次。
- 真实中文 IME 在读取或设置组合串时同步派发的窗口消息（`WM_IME_NOTIFY` 等）不会在宿主借出窗口期间重入；主窗口行内输入与详情窗口都能完成 preedit 和提交，不因消息重入退出应用。
- 鼠标、键盘、焦点与辅助操作在滚动、裁剪、DPI 和窗口尺寸变化后作用于相同几何与节点代际，旧几何不能服务于新树。
- 结构变化按焦点类型与可见集合结算一次，用户新焦点取消旧意图，最终 reveal 与辅助 action 使用新布局。
- 外部 texture 与半透明合成在 Windows 后端上具有可判断的结果；同一 pass 不读写同一纹理，producer serial 完成前不消费资源。
- known size、min/max-content、available-space 与受限换行使用各自测量模式；文本与 sibling baseline 使用同一次接受的文本布局，cache 与早退路径也返回完整信息。
- 实际字体、variation、合成字重 / 斜体、字形、基线和 DPI 使用完整缓存身份；固定字体与词典在干净 Windows 环境按交付资产加载，缺失给出诊断。
- UTF-8、UTF-16 与辅助功能 range 在中文、emoji、组合字符和连字输入中往返一致。
- 窗口隐藏、GPU 设备变化、资源重建与应用退出不产生旧资源或旧任务交付。零尺寸和呈现失败保留 damage，成功呈现后才推进 FrameState。
- 焦点来源 modality 区分 focus 与 focus-visible，`active:` 在按下结束后复位，`aria-pressed:` 与对应 toggle 的语义状态保持一致。
- 静止窗口不因为无工作的 renderer 或动画 ticker 持续重绘。
- 初始化和不支持能力返回明确错误，不通过后端 validation panic 代替能力查询。
