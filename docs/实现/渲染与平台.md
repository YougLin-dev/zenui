# 渲染与平台

## 界面树与派生绘制

ZenUI 保留原生界面树作为节点身份和交互状态的归宿。模型与派生值的变化在这里形成 typed patch，布局、文本测量、绘制与命中再消费已提交的描述。

界面树不是随字段更新重建的虚拟节点。布局 cache、文本 shaping cache 和 retained paint record 是从界面树派生的缓存。

## 布局、文本与绘制

布局负责几何计算，文本系统负责字体、字形与测量，绘制层接收已提交的样式、几何与显示内容。

文本测量保留 known dimensions、available space、min-content 与 max-content 的差异，并在几何盒模型中处理 padding、border 与约束。行布局、宽高与首行 baseline 均来自同一次接受的文本布局；缓存命中与已知尺寸路径也返回同一代的完整结果。

一次场景构建先解析 class 与 inline 声明（条件、rank 与 inline origin），再把解析结果交给布局（Taffy `Style`）、文本整形与绘制（`ResolvedStyle`）。hover、press 与键盘模态来自宿主提供的 `SceneEnv`，已提交状态来自快照；两类输入都不写入保留树。场景重建前按最后的指针位置重新命中，避免瞬态指向已移走的节点。为什么瞬态留在宿主、外观却进入快照，见 [ADR-0006](../adr/0006-presentation-transients-and-style-resolution.md)。

字体、字号、variation、合成字重 / 斜体、实际宽度、换行模式与 scale 组成 shaping 与缓存身份。具体的字体合成参与光栅化；fallback 的字体与词典数据由应用交付并支持可检查的加载失败。

选择、光标、composition 与输入法属于文本编辑控件。UTF-8、UTF-16、grapheme、glyph position 与辅助功能 range 由编辑器适配层转换。绘制、命中、焦点和辅助功能在同一代已提交界面上使用一致坐标。

技术组件的版本由实际 manifest 与锁文件记录。当前 `crates/core` 是纯标准库 headless 实现；`examples/native_poc` 与 `examples/desktop_poc` 分别验证局部文本、布局和离屏 GPU 机制，不等同于最终 Windows 桌面链路。

窗口大小、DPI、字体、软件 fallback、driver 与 GPU capabilities 都会影响绘制表现。不假定一个离屏 readback 就能代表真实窗口、不同 DPI 和不同 driver 的最终视觉效果。

## 几何、缓存与呈现

每次布局发布不可变的 GeometrySnapshot：节点及代际、逻辑 rect、累积变换、祖先 clip、z-order，以及所在窗口、scale 和文本布局代际。滚动不是第二份几何：当前由 `Scene` 承担已发布几何，宿主拥有的整页偏移在构建时只应用一次（[ADR-0010](../adr/0010-scroll-is-presentation-state.md)）。未来的 GeometrySnapshot 只能选择“未平移 rect 加一个 applied offset”或“已平移 rect、没有 offset”之一，不能同时暴露两者，以免消费者再次应用偏移。

绘制、hit testing、焦点 reveal、caret、输入法候选区域和辅助动作都使用该份几何。结构变化先撤销已卸载节点的命令与交付，再提交新的树与几何；不会用旧布局匹配新的节点。长列表的可见行窗口见 [ADR-0011](../adr/0011-windowed-for-mounting.md)：声明 `row-height` 的 `For` 只提交已挂载行与两个 spacer，场景报告行带几何，宿主换算行窗口；滚动与窗口化都遵守这一条单一几何规则。

## Renderer 拥有的 transient

frame time、动画插值与 GPU 资源分配由 renderer 管理。整页滚动偏移不是 renderer 拥有的 transient：它是宿主拥有的持久 presentation 环境值，renderer 每帧只应用它；未来的滚动动画可以提出中间增量，但权威值仍在宿主（[ADR-0010](../adr/0010-scroll-is-presentation-state.md)）。tick 只在需要工作的阶段保持活跃，空闲窗口可以停止呈现。

`Signal` / `Memo` 依然可以提供颜色、业务进度或动画目标等稳定输入。测量与绘制的异常保留在渲染边界内处理，模型事务与资源恢复各自保留结果。

隐藏窗口可以保留它的 Owner 和控件状态，但应停止输入、语义动作和 presentation；窗口关闭后，其 renderer lease、surface 与任务交付失效。

## Content handle 与 native attachment

`CanvasContent`、`TextureSource`、`SceneHandle` 等 Copy handle 表示可共享的内容或资源描述。它们可以出现在 `Show` 的两个分支：

```rust
<Show when={streaming} fallback={move || view! {
    <canvas content={chart} />
}}>
    <canvas content={chart} ticker={tick} />
</Show>
```

共享 content 不等于复用 native attachment。每个 mounted leaf 与自己的 window、activation 和 device generation 对应；不同 branch 更替或重新创建控件时，要释放旧 lease，再创建或绑定新 lease。

资源 Copy 只回答 Rust 捕获的便利性，不能证明 GPU attachment 一直有效，也不能跨窗口随意复用设备本地对象。

帧内绑定的资源具有 owner / mount generation、device epoch、已提交 serial、尺寸、格式、颜色空间、alpha 与使用约束。生产者先完成对应提交，消费者才使用该 serial；同一颜色纹理不能在一次 pass 中同时作为写入目标与采样输入。

## 图像、外部纹理与 3D

图像接口显式说明尺寸、格式、颜色空间和 alpha 约定。不能把一处不同 alpha premultiplication 假设的像素缓冲直接当成另一种纹理。

3D 作为布局中的内容叶节点接入，有独立的离屏颜色与深度，再融入 2D 绘制结果。它不是第二套界面树，也不承诺浏览器 scene graph、AR 或游戏引擎功能。

资源加载可以通过 worker 产生 Send 数据与资源 generation，能在 UI 激活状态确认后发布。迟到帧、旧 device 和已卸载 scene 的结局是资源取消或替换，不需要修改模型。

## Windows 平台接入

窗口与输入归一化运行在 UI 主线程。原生回调生成中性输入，由 UI command turn 改变界面；worker 经事件循环桥接交付。每个顶层窗口有独立 surface、scale 与 activation，共用主事件循环，模态不额外创建事件泵。系统的模态拖动/缩放循环直接调用窗口过程而不返回消息循环；宿主在窗口过程里重绘并派发输入，运行时仍是唯一 UI 权威，宿主不保存第二份状态。窗口 surface 经 DirectComposition 视觉承载（wgpu 的 `DxgiFromVisual`）：DWM 合成视觉内容而不是缩放上一帧位图，交互式缩放期间不会出现文字被拉伸再恢复的过程；代价是 RenderDoc 无法抓取这类交换链。

进程在首个 HWND 前建立 per-monitor DPI 感知。指针坐标按所在窗口 scale 转为 logical 坐标；DPI 变化依次更新窗口与 surface、推进字体和缓存代际、重新布局并发布几何。`WM_GETDPISCALEDSIZE` 用新旧 DPI 比例换算物理客户区，保持逻辑客户区不变；该消息不保证送达，系统建议矩形仍是兜底。零物理尺寸跳过呈现并保留待绘制状态。

Windows 键盘区分 physical、logical 与文本输入，处理 dead key 和运行中的布局切换。IME preedit、commit、cancel 进入统一编辑器状态；preedit 由应用按输入框的普通文本样式绘制，系统组合窗口被抑制，候选区由组合起点处的 caret 几何定位。中文候选确认的 Enter 在编辑器前段消费，不生成后续表单提交。

只读 UIA 树由当前节点代际、语义字段与已提交的场景几何派生。每个窗口在场景提交时整体替换自己的树；`WM_GETOBJECT` 只对 `UiaRootObjectId` 交回 fragment-root provider，provider 解析当前发布而不是保留第二棵界面。角色、名称、状态与边界来自同一份快照/场景，滚动只平移边界并保持 Node ID 对应的 runtime ID。写操作经窗口动作队列：provider 线程检查当前树后入队并唤醒 UI 线程，UI 线程按最新快照重验身份、启用与组合状态，再调用与指针、键盘相同的 Runtime 命令；动作 presence 来自 #187 的呈现语义，不从标签推断。相邻两次发布按 runtime ID 比较，聚焦、启用、ToggleState、Value 与子节点增删/重排各投递一次事件；事件在发布锁释放后由发布线程投递，后台窗口不投递聚焦事件，hover/press 与滚动几何不产生事件。文本输入的 Edit 节点暴露最小 `ITextProvider`/`ITextRangeProvider`：文档取已提交值并排除 preedit，UIA UTF-16 偏移在调用线程换算为字符偏移，GetText/GetSelection/GetBoundingRectangles 读取已发布树的文本与场景矩形，Select 经动作队列调用 `set_selection_node` 且不派发 `on:input`，其余 range 方法显式返回 `UIA_E_NOTSUPPORTED`。`ScrollPattern` 仍由后续工单实现。系统高对比度、减少动态、主题与文本缩放以有代际的偏好输入呈现，文本与样式使用统一的处理规则。

## 宿主能力与资源

Windows、macOS、Linux 的窗口、输入法、菜单、托盘、对话框和读屏接口并不完全一样。ZenUI 为共同语义提供统一入口，能力差异使用明确的支持状态，不通过空操作或静态替代品表示成功。

图形能力查询对应实际 adapter 与 surface：格式、usage、颜色空间、present / alpha 模式以及外部纹理支持共同决定是否接受一类工作。CPU 参考路径用于确定性校验与声明的软件路径，不自动证明 GPU 兼容性。

字体与分词数据按应用交付，缺失或损坏有明确诊断；可重复渲染使用固定字体，系统字体按实际能力提供。菜单、托盘、剪贴板、拖放与文件对话框有各自错误与资源生命周期。托盘宿主重启时重建图标，剪贴板和拖放操作具有边界，不无限阻塞 UI。

## 平台验证的对象

局部原型验证各自有界机制：宏的 parser、class lowering 和事件 laziness；headless core 的句柄、Owner、查询与事务；指定文本与 GPU adapter 的离屏绘制。

Windows 完整闭环另行验证输入提交、IME、辅助动作、DPI、显示与 native teardown，行为清单见[验证重点](验证重点.md)。
