# Stage-two 外部开发者试用协议

本页记录 #292 的试用协议、环境清单与执行记录模板。代理准备协议与干净环境；一名非维护者的开发者在只有公开文档的条件下完成任务；主持者记录摩擦并转成 issue。

**状态：协议已准备；外部开发者执行部分待人工完成。执行后在本页补记录，并把摩擦转为 issue。**

## 范围

试用检验新开发者能否从空目录构建、运行、修改并诊断一个小型 ZenUI 应用。它不检验性能、稳定性、跨平台、多显示器或 API 稳定性；这些由各自的验收与边界记录承担。仓库处于 1.0 之前，本试用不构成版本承诺。

## 角色

| 角色 | 要求 | 职责 |
| --- | --- | --- |
| 参与者 | 未参与 ZenUI 开发，未读过 `src/`、`crates/` 与 `docs/实现/`；熟悉 Rust 与 Windows 桌面开发即可 | 按任务单独立操作，说出困惑与预期 |
| 主持者 | 维护者或代理 | 准备环境、注入故障、计时与记录；不解答 API 问题 |

参与者只读模板目录、仓库根 `README.md` 与 `docs/SDK/`。主持者不主动指向具体源码文件，也不给出修复；允许的回答只有「看编辑器诊断」「查公开文档」「这一点没有文档，记录它」。

## 环境

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows 11 x64，全新虚拟机快照，交互式桌面会话 |
| Rust | rustup；模板的 `rust-toolchain.toml` 在首次 Cargo 命令时安装固定工具链 |
| 构建工具 | Visual Studio Build Tools 的 C++ 桌面工作负载，含 MSVC 与 Windows SDK |
| 图形 | 支持 DX12 的适配器；没有硬件适配器时宿主回退 WARP，记录实际路径 |
| 磁盘 | 至少 5 GB 空闲，冷构建约 2.2 GB |
| 网络 | 可访问 GitHub |
| 显示 | 单屏；记录缩放（100% 或 150%） |
| 记录 | 操作系统版本、`rustc -V`、GPU、缩放与开始时间 |

固定修订为 `cd5b432`（#314 合并后的 `main`）。主持者先克隆仓库到参与者可见的路径，例如 `C:\work\zenui`，执行 `git checkout cd5b432`，但不在编辑器打开框架源码。参与者用这个路径改写模板的两个 path 依赖。

## 任务

总时长 90–120 分钟。每项设上限；超时记录阻塞点并进入下一项，不额外提示。

1. **从空目录运行（20–30 分钟）**：按「从空目录开始」路线 A，把模板复制到仓库外的空目录，改写两个 path 依赖，执行 `cargo run --locked`。窗口标题应为 `ZenUI Starter`；按 `Increment` 三次，计数变为 3。记录冷构建时间与磁盘占用。
2. **修改应用（20–30 分钟）**：把窗口标题改为 `Trial Counter`；在 `Increment` 下方增加 `Reset` 按钮，按下把计数归零，样式沿用现有按钮类。重新运行，确认标题、两个按钮与归零行为。
3. **诊断编译错误（15–25 分钟）**：主持者在参与者确认基线后依次注入错误，每次只注入一个，参与者修复后再注入下一个：
   - 按钮的 `class` 写入一个不存在的 token；
   - 按钮使用不支持的事件名 `nope`；
   - 一个视图的 `style:height` 使用字符串值 `"tall"`。

   记录编辑器与编译器读数是否足以定位和修复。
4. **诊断运行期资产错误（10–15 分钟）**：把 `assets/NotoSansSC-Regular.otf` 改名；执行 `cargo run`；观察启动错误；按模板 README 恢复。记录错误消息是否指出缺失路径与恢复方式。
5. **自由修改（可选，10 分钟）**：用公开文档完成一个小改动，例如增加第二个计数器或调整布局；记录查阅文档的路径与卡点。

主持者在注入前备份 `src/lib.rs`，每次注入后只回答「看诊断」或「查文档」，不给出修复。
