# Windows 混合 DPI 检查

**状态：部分执行。** 单显示器上的运行中缩放切换已人工预检通过（见下节）；
跨显示器移动仍未执行，需要一台连接两块不同缩放率显示器的 Windows 11 实机，
CI 的隐藏窗口与单一 DPI 环境无法替代。

## 前置条件

- Windows 11，真实 GPU（非 WARP）。
- 两块显示器，缩放率不同（例如 100% 与 150%），均已登录同一桌面。
- 从当前 main 构建：`cargo run -p zenui-windows --example todo_host`。

## 单显示器预检（已执行）

2026-11-21 在 150% 缩放的可见窗口上，通过设置 → 系统 → 显示 → 缩放，在应用运行中
切换缩放档位（档位序列与截图未记录），人工观察未发现异常。

该预检只覆盖同屏 DPI 变化：宿主显示器 DPI 改变时系统同样发送 `WM_DPICHANGED`
（Microsoft 文档列出的两种成因之一），因此它验证了消息处理、按新 scale 重排与
surface 重配置的路径。它不覆盖两块显示器同时使用不同缩放率、跨边界拖动、系统 DPI
与窗口 DPI 的区分以及拓扑变化，不能替代下面的两显示器步骤。

## 步骤与预期

1. 窗口在 100% 显示器上启动，拖拽边框调整到约 640×480。
   预期：布局按逻辑像素重排，文字不拉伸、不裁剪，没有上一尺寸的残留像素。
2. 把窗口拖到 150% 显示器。
   预期：DPI 变化后重绘；逻辑布局宽度不变，物理像素随 scale 放大，文字清晰，
   caret 与 selection 仍贴合文本。
3. 在 150% 显示器上聚焦输入框，用中文 IME 组合。
   预期：preedit 出现在 caret 处，组合窗口与候选窗口贴近 caret。
4. 保持组合，拖动边框改变窗口大小。
   预期：组合/候选窗口随新的 caret 位置更新，不留在旧位置。
5. 把窗口拖回 100% 显示器。
   预期：scale 回到 1.0，逻辑布局保持稳定，无模糊或错位。

## 记录要求

- 构建的 commit SHA。
- 两块显示器的分辨率与缩放率。
- GPU 型号。
- 每个步骤的通过/失败，附截图（含 caret 与 IME 候选窗口）。
- 若失败：记录实际 scale、客户区物理尺寸与期望值。

## 自动化覆盖的边界

- 隐藏窗口 resize smoke 验证逻辑布局与物理帧尺寸一致。
- `Host::resize` 使用 `AdjustWindowRectExForDpi`，surface 重建测试验证焦点、
  caret、selection 与 Node ID 在恢复后不变。
- 这些测试不切换显示器，也不产生真实 IME 组合，因此不能替代本页的人工检查。
