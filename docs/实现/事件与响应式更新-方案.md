本文规定 ZenUI 的目标事件模型、响应式更新模型、呈现派生和开发者体验。它描述方向、边界和验证方式，不表示已经实现；当前实现的差距集中在[附录 A](#附录-a当前实现差距)。实现进度由[路线图](../产品/路线图.md)管理。

目标只有四条，且都必须可验证：

- **细粒度更新**：一次输入只重算受影响的数据源、派生值和绑定；不重跑组件，不遍历全部节点。
- **高性能**：空闲不做工作；一次 turn 的工作量与命中深度、脏绑定数、结构变化子树成正比；输入不被全量快照或全量布局拖慢。
- **低内存**：每个节点、绑定、处理器、memo 有明确预算；卸载真正回收；窗口化列表的 UI/For 常驻内存与可见窗口成正比；共享 `RowSet` 是 O(总行数) 的单份身份投影，单独计预算。
- **易用性**：普通 Rust 闭包、类型化事件、可 inline 的派生值；常见交互不要求用户手写订阅、冒泡规则或刷新逻辑。

不追求：VDOM、组件反复执行、浏览器 DOM/CSS、第二套可独立修改的界面权威、跨模型/窗口/GPU/文件的事务回滚。

## 1. 结论

1. **保留树是唯一界面权威。** 节点身份、结构、焦点、选择、光标、composition、控件本地状态只在保留树中保存。快照、场景、UIA 树都是不可变、可丢弃的派生结果。
2. **统一节点 arena。** 元素、文本、组件、`Show`、`For` 都是 arena 中的稳定节点，拥有父链和子链。公开 `NodeId` 仍只标识元素；运行时用内部 `NodeRef` 统一处理全部节点，呈现层使用公开的 opaque `PresentationKey`。
3. **响应式图按绑定消费。** 数据源（Signal、Store 字段/行集、Appearance）经 memo 派生，最终订阅到每个绑定槽：一段文本、一个属性、一条 inline style、一个 `Show`、一个 `For`。静态槽（`Static`/`Once`）在挂载时求值一次，不注册 `DepKey`；Signal/Memo/Field 槽注册带 generation 的 `DepKey`。数据位置的闭包变成隐式 memo。绑定槽、part 与补丁的完整类型见 §18.4。
4. **读源统一。** `Read<T>` 同时表达静态值、`Once`、`Signal`、`Memo`、`Field`；`value`、`disabled`、`checked`、`Show.when`、`For.each`、style 和组件 prop 使用同一套来源，不再有“Show 只收 Memo”的特例。
5. **显式快照。** 数据位置只接受字面量、`Once`、`Read` handle；非字面量的 `String`/`bool` 表达式必须写 `once(...)` 或传 handle。裸 `.get()` 不会被静默当成一次性值，而是编译错误并给出替代写法。
6. **事件按意图路由。** 指针、键盘、菜单、托盘、拖放、任务都归一为带 target 的意图。默认路由是最近可处理祖先（closest-wins），不是 DOM 式默认冒泡；需要多个祖先观察时显式使用 capture/bubble 变体。事件载荷类型化，消费与默认动作有明确顺序。UIA 写动作是第二条 typed node command 入口，不走 closest-wins，见 §17。
7. **一个 turn 一次 flush。** 处理器写入立即可见；turn 结束统一解析 memo、结构、绑定、焦点和清理，产生一次提交。嵌套派发进入 FIFO 队列，不重入。
8. **呈现增量派生。** 快照使用持久化结构共享，按脏路径复制；布局保留 Taffy 树并按脏子树重排；绘制使用保留记录与 damage。每次提交同时发布 `PresentationDelta`，renderer 消费 delta、不做自己的新旧树 diff；UIA 仍整树发布并比较相邻发布（delta 不供 UIA，见 §17.4）。
9. **内存按代际回收。** 节点、Signal、Memo、事件槽使用 generation + paged arena；绑定引用携带所属节点或 memo 槽的 generation。卸载先退订再释放；反向依赖边使用 `DepEntry` + 扁平边 arena，而不是每次写入克隆集合。UI/For 持久内存按窗口计；共享 `RowSet` 是 O(总行数) 的单份身份投影，单独计预算（§19.7/§19.8）。
10. **用户闭包全部有 panic 边界。** 事件处理器、memo 计算、binding 求值、Show/For factory、cleanup、窗口/命令/菜单/任务回调都经过统一的捕获与恢复；panic 毒化单个节点或槽位，不毒化整个 runtime。事件槽返回 `HandlerOutcome`，turn 返回 `TurnReport`；见 §16。

## 2. 目标与不变量

### 2.1 四条目标的可验证定义

| 目标 | 可验证定义 |
|---|---|
| 细粒度 | 单行字段变化只求值订阅该字段的绑定；空 Intent 不重建快照；10k 行窗口化列表的 UI/For 持久内存与窗口成正比，共享 `RowSet` 单列为 O(总行数) |
| 高性能 | 派发入口 O(1) + O(深度)；无变化写入不产生快照/布局/绘制；输入不在宿主侧触发全量快照 |
| 低内存 | 槽位、依赖边、处理器、快照节点有 `size_of` 预算；churn 后 live/storage 回到页粒度；无随历史增长的 arena；RowSet 单列 O(总行数) |
| 易用性 | 常见交互不需要手写订阅或刷新；裸值冻结是编译错误；错误带节点、阶段和替代写法 |

### 2.2 不变量

1. **单一界面权威**：只有保留树能修改界面。快照、场景、UIA 树只读、不可变、可丢弃。
2. **单一响应式权威**：只有响应式图能决定派生值和失效。控件本地编辑状态不复制成第二个 Signal 图。
3. **挂载一次**：组件 setup 只在挂载时执行一次。字段变化不重新执行组件，不比较虚拟树。
4. **身份稳定**：`NodeId` 在元素挂载期间稳定；槽位复用必须换 generation；旧身份永远拒绝，不重定向到邻居。
5. **写入有门**：Signal 与 Store 只在 Event/Delivery/Command 阶段接受写入；`Structure` 只允许读与挂载资源、`MenuState` 只读；计算、布局、绘制、快照构建没有写权限。
6. **turn 有界**：一个 turn 内的用户处理器按 FIFO 顺序执行；嵌套派发入队；结构变化后的焦点结算有固定轮数上限；窗口/会话请求结算有每次 turn 的 drain 上限。
7. **flush 一次**：一个 turn 只发布一次响应式结果；同一 turn 内后续处理器能读到前一个处理器的写入；结构和绑定的一致性在 turn 结束保证，而不是处理器之间。
8. **卸载先退订**：节点或 Owner 释放时，先移除事件、绑定、反向依赖和任务交付，再释放子节点和存储。
9. **按脏工作**：默认路径不遍历全部挂载节点；全量工作只出现在显式全量变化（例如外观切换、完整行集重建）并有明确计数。
10. **边界显式**：跨 owner、跨 turn、已卸载、隐藏、关闭挂起、非法阶段都是 typed error；存活上下文内违反 handle 契约是开发期 panic，带节点/owner/generation 诊断。两者不混用默认值或最近目标。一次 turn 的错误通过 `TurnReport.errors` 返回，不静默丢弃（§16.2）。

### 2.3 状态归属

| 状态 | 所有者 | 可写阶段 | 存储 |
|---|---|---|---|
| UI Signal / Memo | 应用 / 组件 / 窗口 owner | Event / Delivery / Command | 代际 arena |
| Store 行、查询、发布 | 应用 owner | Event / Delivery 事务 | core |
| Appearance | 应用 owner | Event / Command | 源 + 快照 |
| 节点结构、焦点、本地编辑 | tree / activation | runtime 操作 / Structure | NodeArena |
| 窗口/菜单/拖放/命令处理器 | activation owner | factory setup 注册，Event 运行 | WindowHandlers |
| hover / press / scroll / 键盘模态 / 指针位置 | 宿主 | 宿主线程 | WindowHost |
| 系统偏好 / DPI / 环境代际 | 宿主 | 宿主线程 | PresentationEnv |
| reveal 请求 / 待决显露 | 宿主 | 宿主线程 | WindowHost |
| 快照 / 场景 / UIA 树 | tree 派生 | 只读派生 | 不可变 `Arc` |
| GPU 资源、surface | renderer / device | renderer 边界 | GPU |

runtime 线程亲和（`!Send`）。UI 写入只在 UI 线程；worker 只接收和返回 Send 数据；UIA provider 线程只读已发布快照，把写动作排队到 UI 线程；renderer 只消费不可变快照与场景。任何跨线程共享的可变 UI 句柄都是设计错误，不提供“内部加锁”的假安全。

```
┌────────────────────────────────────────────────────────────────────┐
│ L0 平台层（Windows / macOS / Linux）                               │
│ 原生消息、IME、DPI、surface、菜单、托盘、对话框、拖放、UIA、worker │
└───────────────────────────────┬────────────────────────────────────┘
                                │ 原始输入 / 服务回调
┌───────────────────────────────▼────────────────────────────────────┐
│ L1 宿主归一化（zenui-windows）                                     │
│ 命中测试、焦点仲裁、IME 状态、hover/press/scroll 瞬态、快捷键      │
│ 输出：Intent { source, target, payload }                           │
│ 宿主瞬态留在宿主，不进入响应式图。                                 │
└───────────────────────────────┬────────────────────────────────────┘
                                │ Intent 队列
┌───────────────────────────────▼────────────────────────────────────┐
│ L2 事件路由（target runtime）                                      │
│ 目标解析 → 路由策略 → 用户处理器 → 默认动作 → turn 结算            │
│ 处理器 panic 被隔离；写入立即生效；嵌套派发入队。                  │
│ 输出：TurnOutcome { consumed, prevent_default } 给宿主默认动作    │
└───────────────────────────────┬────────────────────────────────────┘
                                │ 写入 / 模型事务 / 本地编辑
┌───────────────────────────────▼────────────────────────────────────┐
│ L3 响应式图（target runtime）                                      │
│ Source → Memo → Binding/Structural                                 │
│ 标脏、flush、结构提交、焦点结算、退订、有效变化判定                │
│ 共享源写入标记所有受影响 tree；turn 结束 drain dirty_trees         │
└───────────────────────────────┬────────────────────────────────────┘
                                │ 脏路径 / per-tree revision / delta
┌───────────────────────────────▼────────────────────────────────────┐
│ L4 呈现派生（runtime + renderer）                                  │
│ 持久快照（结构共享 + PresentationDelta）→ 保留布局（脏子树）       │
│ → 绘制记录 → damage；UIA 整树发布 + 相邻发布比较                   │
└───────────────────────────────┬────────────────────────────────────┘
                                │ 不可变帧
┌───────────────────────────────▼────────────────────────────────────┐
│ L5 GPU / surface                                                    │
└────────────────────────────────────────────────────────────────────┘
```

### 3.1 三条并存的图

```
保留树（权威）            响应式图（失效）              派生呈现（只读）
NodeArena                 DepKey → ConsumerRef          PresentationSnapshot（Arc）
  Element                   Signal/Field/Rows             ├─ Arc<SnapshotRoot>
  Text                      Memo                          ├─ Scene（Arc）
  Component                 Binding/Structural            └─ AccessibilityTree
  Show / For
```

三条图通过稳定的 `NodeRef`（保留树内部）、`SourceRef`（响应式图槽位）和 `PresentationKey`（公开呈现）连接，不共享可变状态。保留树变化产生响应式绑定的初始值；响应式图变化只产生保留树的 patch；呈现图只读两者。

### 3.2 一次输入的 turn

```
宿主 Intent
   │
   ▼
Runtime::dispatch_intent(intent)       入 FIFO 队列
   │
   ▼  turn 开始
target = resolve(intent.target)        O(1) 节点校验 + 树归属
route(target)                          direct / closest / capture-bubble
   │
   ├─ handler(s)                        写入 Signal / Store / 本地编辑 / 窗口请求
   │                                    panic → 恢复槽位与 phase，上报，turn 继续
   │                                    handler Err → 停止本事件链并跳过默认动作
   ▼
flush_dirty_trees()
   ├─ 0 quarantine removed rows（标记被删行/过滤出行，暂不删边）
   ├─ 1 dirty memo worklist（只求值仍被 mounted 消费者可达的 memo）
   ├─ 2 structural staging + commit（Show/For/行窗口）
   ├─ 3 binding worklist
   ├─ 3.5 pending edit lineage observe
   ├─ 4 focus settlement（有界轮数，回到 1-3）
   └─ 5 cleanup（退订、释放、生成代际）
   │
   ▼
if effective_change: tree.revision += 1; snapshot path copy; publish delta
if env changed: env_generation += 1; scene/布局/shaping/UIA 按 §15.2 的环境矩阵失效（高对比度不 relayout；文本缩放/DPI 重排；不 bump tree.revision）
   │
   ▼
apply window/session requests           有 drain 上限；可能产生新的 show/hide turn
   │
   ▼  turn 结束
宿主根据 TurnOutcome 决定原生默认；paint dirty trees
```

### 3.3 异步交付

```
worker 完成 → 唤醒 UI 线程 → Delivery turn
   │
   ├─ 校验 task generation / owner / activation
   ├─ 在 Delivery 阶段运行 continuation（可写 Signal/Store）
   ├─ flush 所有受影响 tree
   └─ 结算窗口/会话请求
```

一个 `drive_tasks` 批次**就是一个 Delivery turn**，不是每个 continuation 一个 turn：continuation 之间写入立即可见，UI 只在批次结束 flush 一次；panic/Err 停止后续 step，但保留已写入状态并在批次末报告（§16.10）。continuation 不得读取已发布快照；需要读取 UI 几何的异步结果应回到 Event turn 通过显式命令处理。

### 3.4 多窗口与共享源

```
应用 Owner ──共享──► Signal / Store / Appearance
   │
   ├─ Window activation A ──► Tree A（焦点、本地编辑、快照根、revision、dirty）
   ├─ Window activation B ──► Tree B
   └─ Window activation C ──► Tree C
```

共享数据源的写入标记所有订阅它的 binding，并把消费者所属 tree 放进 `dirty_trees`。turn 结束 drain `dirty_trees`，每个 tree 独立 flush、独立 revision、独立快照根、独立 `env_generation`。未变化的窗口不重建快照、不重排布局、不绘制。应用外观写入把所有 tree 放入 `dirty_trees`；系统偏好/DPI/滚动只推进各自 `env_generation`，不 bump 快照 revision（§15）。

隐藏窗口保留树与本地状态；共享写入仍然标记它，**turn 末的 flush（绑定/结构/revision）与可见窗口同步完成**，只有快照根与场景/布局构建可以延迟到 show 或任何读取其呈现、焦点或编辑状态的入口之前。窗口关闭释放 activation 的树、焦点、任务和事件；旧 activation 的迟到交付被丢弃。

## 4. 身份、存储与生命周期

### 4.1 统一 NodeArena

所有挂载节点进入同一个 arena。节点用槽位 + generation 标识；`NodeRef` 是内部身份，`NodeId` 是公开的元素身份，`PresentationKey` 是公开的呈现身份。

```rust
#[repr(transparent)]
struct NodeRef(NonZeroU64);   // 32-bit slot + 32-bit generation；0 保留为 None 编码
#[repr(transparent)]
struct SourceRef(NonZeroU64); // Signal/Memo 的 slot + generation；不参与 UI 父子链

struct NodeId {
    runtime: u32,
    node: NodeRef,
}

struct PresentationKey(u64); // 对外不透明；NodeRef 的公开编码，所有快照节点都有，包括文本

// 按 repr(C) 固定字段顺序以命中 64 B：3×u32 + 2×u8 + 2 B padding + 6×8 B 指针。
#[repr(C)]
struct NodeSlot {
    payload: u32,          // 该 kind 自己的密集 arena 下标
    generation: u32,
    tree: TreeKey,         // u32；O(1) 树归属
    kind: NodeKindTag,     // u8
    dirty: DirtyFlags,     // u8
    // 2 B padding
    parent: Option<NodeRef>,
    first_child: Option<NodeRef>,
    last_child: Option<NodeRef>,
    prev_sibling: Option<NodeRef>,
    next_sibling: Option<NodeRef>,
    snapshot: Option<Arc<SnapshotNode>>,
}

type TreeKey = u32;        // 单调分配、不复用；耗尽即 fatal

#[repr(u8)]
enum NodeKindTag { Element, Text, Component, Show, For }

struct NodeArena {
    slots: PagedArena<NodeSlot>,
    elements: PagedArena<ElementData>,
    texts: PagedArena<TextData>,
    components: PagedArena<ComponentData>,
    shows: PagedArena<ShowData>,
    forces: PagedArena<ForData>,
    aux: AuxArenas,          // 按树拥有；所有列表/编辑/绑定句柄的宿主
}

/// ≤ 96 B；只存句柄，不内联 attrs/styles/events/edit。
#[repr(C)]
struct ElementData {
    tag: TagId,                 // u16 注册表索引
    flags: ElementFlags,        // u8；1 B padding
    owner: OwnerRef,            // 8 B
    attrs: u32,                 // AttrListId；u32::MAX = 空
    class_styles: u32,          // StyleListId
    inline_styles: u32,         // StyleListId
    events: u32,                // EventListId
    edit: u32,                  // EditStateId（共享 edit arena）
    bindings: u32,              // BindingListId（§18.4）
    semantics: u32,             // SemanticsId
}                               // 4 + 8 + 7×4 = 40 B，余量留给对齐与扩展

struct AuxArenas {
    attrs: PagedArena<AttrList>,
    class_styles: PagedArena<StyleList>,
    inline_styles: PagedArena<StyleList>,
    events: PagedArena<EventList>,
    edits: PagedArena<TextEditState>,
    binding_lists: PagedArena<BindingList>,
    semantics: PagedArena<SemanticsData>,
}
type TagId = u16;
#[repr(transparent)] struct ElementFlags(u8);
```

`Option<NodeRef>` 用 `NonZeroU64` 编码为 8 字节。`NodeSlot` 的固定布局为 64 B：3 个 `u32`（12 B）+ 2 个 `u8`（2 B）+ 2 B padding + 6 个 8 B 指针（48 B）；`TreeKey` 必须是 `u32`、`DirtyFlags` 必须是 `u8`，字段顺序必须按上面 `repr(C)` 固定，否则预算不成立（§19.7）。payload 不内联，避免被最大的 `ElementData` 撑大。每种节点有独立密集 arena，热数据连续。Signal/Memo 不在 UI NodeArena 中：它们是响应式图节点，没有父子链，使用独立的 `SourceRef` 和槽位 arena，避免为无链节点支付 `NodeSlot` 的链开销。槽位 generation 用尽时 retire 该槽，不得回绕复用；arena 耗尽返回 typed fatal。

选择父链 + 兄弟链而不是每个节点一个 `Vec`：

- 子节点遍历、插入、移动、删除是 O(1) 指针操作，不产生每节点 Vec 头。
- 父链直接服务最近祖先路由、焦点结算、脏路径上溯和快照路径复制。
- `For` 的 keyed 重排移动节点，不移动子树数据。
- 元素、文本、结构节点使用同一套引用，不需要为文本/Show/For 另造身份。

元素特有的数据分成两层：`ElementData` 只存 tag、owner、flags 和外部 arena 句柄（attrs、class styles、inline styles、事件槽、本地编辑、binding list、语义）；真正的列表与编辑状态在 `AuxArenas` 中，按树拥有、按 id 释放。组件节点只持有 owner 和子链；`Show` 在 `ShowData` 中持有 `when` 的 `BindingRef` 和活动分支；`For` 在 `ForData` 中持有擦除后的 `ErasedForSource` + `ForDriver`、`each` 的 `BindingRef`、key 映射、行窗口和行带元数据（类型擦除见 §18.6）。`ElementData` 不内联 `Vec`/`SmallVec`/`Arc<str>`/`TextEditState`，否则 96 B 预算不成立（§19.7）。

公开身份不变：`NodeId` 只由元素分配，文本/结构节点只有内部 `NodeRef` 和公开 `PresentationKey`。宿主和 UIA 看不到 `NodeRef`。

### 4.2 绑定引用

绑定消费者不是堆对象。它是一个打包的引用：

```rust
// 16 B 打包值：NodeRef/SourceRef 8 B + PartId 2 B + kind 1 B + reserved 1 B。
enum ConsumerRef {
    Binding { node: NodeRef, part: PartId },     // PartId 是 BindingPart 的 u16 注册值
    Structural { node: NodeRef, part: PartId },
    Memo { memo: SourceRef }, // memo 消费者，见 §6.1
}
```

`DepKey → DepEntry` 是唯一的反向订阅表；`DepEntry { first_edge: u32, len: u32 }` 指向扁平的 `EdgeArena`（§19.9）。不使用每个 Dep 一个 `SmallVec<[ConsumerRef; 4]>`：空容器会为每个 Field Dep 常驻 72 B。Binding/Structural 消费者带 `NodeRef` 的 generation，`tree` 从节点查得；Memo 消费者带 `SourceRef` 的 generation，没有 tree，进入 runtime 全局的 dirty memo worklist。因此 source 写入可以同时标记节点、tree 和 memo。

绑定槽**不在 `ElementData` 内联**：每个 tree 有一组按值类型分表的 `BindingTable`（§18.4）；`ElementData.bindings` 指向 `BindingList`（`(PartId, BindingRef)` 的稳定有序表），`ShowData`/`ForData` 直接保存 `BindingRef`。`BindingRef` 是 `{ table: u8, slot: u24, generation: u32 }` 的 8 B 打包值；`BindingSlot.current` 是最后已提交值的唯一权威。part/槽类型见 §18.4。

这样：

- 静态槽（`Static`/`Once`）不需要 deps Vec、不注册 `DepKey`，也不需要闭包；`Signal`/`Memo`/`Field` 槽只保存带 generation 的源引用。
- 数据位置的闭包先由 `memo` 变成 memo 节点，再以 memo 句柄进入绑定；动态边只存在于 memo 内部。
- 一个元素有 4 条绑定，就只增加 4 条 `ConsumerRef` 边，而不是 4 个堆节点。
- memo 消费者也在同一张表里，`source → memo → memo → binding` 的链可以逐级传播。

### 4.3 Signal / Memo

```rust
struct Signal<T> { runtime: u32, slot: SourceRef, _marker: PhantomData<fn() -> T> }
struct Memo<T>   { runtime: u32, slot: SourceRef, _marker: PhantomData<fn() -> T> }

struct SignalCell {
    value: Option<Rc<dyn Any>>,
    writes: u64,
    disposed: bool,
}

#[repr(C)]
struct MemoCell {
    compute: Option<Rc<dyn MemoCompute>>, // call + 类型擦除 eq，见 §18.1；16 B
    value: Option<Rc<dyn Any>>,          // 16 B
    revision: u64,                       // 8 B
    deps: DepListId,                     // 4 B；指向 MemoDepsArena，不内联
    flags: MemoFlags,                    // 1 B + padding；48 B 总计
}

struct MemoDepsArena { lists: PagedArena<DepList> } // DepList 内联 SmallVec<[DepId; 4]> 或切片
```

`memo(f)` 是唯一的公开派生构造；数据位置的闭包由宏降为隐式 `memo(f)`。不新增第二个名字指同一机制。memo 是惰性、缓存、动态依赖替换、值相等抑制下游的图节点。`T` 必须实现 `ReactiveValue`；`MemoCell` 的 `compute` 是同时提供 call 与类型擦除 eq 的 `MemoCompute`（§18.1）。`rowset` 的 `equivalent` 走 `shares_with`/query revision 快路径。

释放顺序：

1. 标记 disposed，拒绝新读取。
2. 从反向表移除该 memo 的全部 dep 边，并清理它作为消费者的边。
3. 清空 value、compute，并把 deps 列表归还 `MemoDepsArena`。
4. 槽位进入 free list；generation 递增。空页释放回页池。

Signal 释放同样清空 value。arena 使用分页 free list，`storage` 只能回到页粒度，不能承诺逐槽收缩；预算按页粒度计算。

### 4.4 事件槽

元素持有 `SmallVec<[EventId; 2]>`；事件本身在全局事件 arena：

```rust
enum Event {
    Click(Box<dyn FnMut(&mut ClickEvent) -> HandlerOutcome>),
    ClickCapture(Box<dyn FnMut(&mut ClickEvent) -> HandlerOutcome>),
    ClickBubble(Box<dyn FnMut(&mut ClickEvent) -> HandlerOutcome>),
    DblClick(Box<dyn FnMut(&mut ClickEvent) -> HandlerOutcome>),
    Input(Box<dyn FnMut(&mut InputEvent) -> HandlerOutcome>),
    Change(Box<dyn FnMut(&mut ChangeEvent) -> HandlerOutcome>),
    Submit(Box<dyn FnMut(&mut SubmitEvent) -> HandlerOutcome>),
    KeyDown(Box<dyn FnMut(&mut KeyEvent) -> HandlerOutcome>),
    KeyDownCapture(Box<dyn FnMut(&mut KeyEvent) -> HandlerOutcome>),
    KeyDownBubble(Box<dyn FnMut(&mut KeyEvent) -> HandlerOutcome>),
    Focus(Box<dyn FnMut(&mut FocusEvent) -> HandlerOutcome>),
    Blur(Box<dyn FnMut(&mut BlurEvent) -> HandlerOutcome>),
    CompositionStart(Box<dyn FnMut(&mut CompositionEvent) -> HandlerOutcome>),
    CompositionUpdate(Box<dyn FnMut(&mut CompositionEvent) -> HandlerOutcome>),
    CompositionEnd(Box<dyn FnMut(&mut CompositionEvent) -> HandlerOutcome>),
    CompositionCancel(Box<dyn FnMut(&mut CompositionEvent) -> HandlerOutcome>),
    // Drop 不是元素事件；它是窗口/activation 处理器，见 §16.9。
}
```

- 事件槽返回 `HandlerOutcome`（§16.3），以便承载 `Result`/`WriteOp` 与 `Err` 语义。`Drop` 不属于元素事件槽。
- 处理器接收 `&mut ClickEvent` 等具体载荷，可以在 handler 内调用 `consume()` / `prevent_default()`，runtime 在返回后读取同一份 flow。`&mut` 的生命周期限制在调用内，用户不能把事件存起来稍后消费。
- 零参数闭包由宏包装为 `|_event: &mut ClickEvent| handler()`（按实际事件类型）；零参数形式不能 consume。需要控制传播或默认动作时写一参数。
- 同一元素同一事件种类最多一个直接处理器；capture/bubble 变体各自独立。`view!` 字面量重复在宏期报错；程序化 `MountPlan` 重复在挂载期返回 typed `DuplicateHandler`。
- 事件槽随元素释放；处理器是 `FnMut`，状态随槽位保留；重挂载得到新槽位。
- 处理器调用统一经过 `take → catch_unwind → put → resume/报错`，panic 不留下空槽或 Event 阶段。

### 4.5 内存预算

预算是实现门禁，不是产品承诺；Phase 1 用 `size_of` 与每树槽位计数建立基线，再收紧。目标量级：

| 项 | 目标 | 说明 |
|---|---:|---|
| `NodeSlot` | 64 B（固定） | 父/子/兄弟链 + kind + payload + gen + `dirty: u8` + `tree: u32` + 快照引用；布局见 §19.7 |
| 元素 payload | ≤ 96 B | tag、owner、flags、外部 arena 句柄（attrs/styles/events/edit/bindings/semantics）；不内联列表 |
| `NodeRef` | 8 B | packed slot + generation；`Option` 8 B |
| `NodeId` | 12–16 B | runtime + NodeRef |
| `PresentationKey` | 8 B | 公开 opaque，所有快照节点 |
| `ConsumerRef` | ≤ 16 B | 节点 + part/kind，或 memo 槽 |
| 每条反向边 | 16 B + 8 B/DepEntry | `DepEntry` + 扁平 `EdgeArena`；不用每 Dep 的 SmallVec 头（§19.9） |
| 事件槽 | 16 B + 闭包捕获 | 每个处理器 |
| Signal 槽 | ≤ 32 B + 值 | disposed 清值 |
| Memo 槽 | 48 B（含 value 句柄；deps 在独立 `MemoDepsArena`） | 预算上限 64 B；disposed 归还 deps 列表 |
| 快照节点（元素） | 64–96 B 头 + 文本 | attrs/styles/children 必须外置；内联会到 ~350 B（§19.7） |
| 场景/布局节点 | 按 renderer 实测 | Taffy 节点、layout、绘制记录 |
| 运行时每行（典型 8 节点） | 以实测为准，目标 ≤ 4 KiB | NodeSlot + payload + attrs + owner + reactive |
| 每行含快照/布局/场景 | 以实测为准，目标 ≤ 12 KiB | 32 行窗口约 400 KiB 量级 |
| `For` 持久簿记 | O(窗口) | 只保存已挂载行 |
| `RowSet` | 8 B/行 + `Arc<RowSetData>` 头 | newtype 包裹共享身份投影；头含 `StoreId`；与 UI/For 的 O(窗口) 分开计（§19.8） |

不要在未测量时宣称“1.5 KiB/行”。owner 粒度必须收紧：组件和结构节点持有 owner，普通元素只挂资源；owner 使用密集 arena。渲染侧的 Taffy/Scene/字体缓存单独列预算，不混入 runtime 结构。本表是目标值；§19.7 是实现版逐字段预算，冲突时以 §19.7 为准。

`DEFAULT_WINDOW_ROWS = 32` 只是默认值，不是内存保证；未声明 `row-height` 的 `For` 仍会全量挂载，文档和诊断必须说清楚。

### 4.6 `For` 的 O(窗口) 簿记

行集投影变化时：

1. 遍历完整 `RowSet` 执行一次 key 映射和重复 key 校验；这是 O(总行数) 的**瞬时**工作，使用可复用的 scratch，不保留全量映射。
2. 只把落在当前**已挂载窗口**内的 `(RowId, row_index, NodeRef)` 保存在持久表里；`For` 持有 `ForSource<R>`（`Store<R>` + `Read<RowSet>`），业务 key 通过 `Store::key_of(RowId)`、行数据通过 `Store::get(RowId)` O(1) 取得，不复制进表。
3. 完整顺序由共享 `RowSet` 提供；重排不重建全量映射。行根节点或 owner 保存自己的 business key，焦点 grace 通过节点到行的映射查得。
4. 焦点行在窗口内或窗口外一行时仍已挂载，因此它的行索引从持久表可得；更远的行已被卸载，焦点按 ADR-0011 直接清除，不做邻行接任。
5. 行窗口变化只挂载/卸载进出窗口的行；卸载前先退订该行的绑定。

这样 10k 行的 UI/For 持久内存不再包含全量 `BTreeMap<key, row_index>`，只剩可见行元数据；完整顺序由共享 `RowSet` 提供（顺序是 Store 当前用户顺序，不是业务 key 排序），For 不另存第二份。共享 `RowSet` 是 O(总行数) 的单份身份投影，预算单列（§19.8）。

### 4.7 Owner 与释放顺序

每个挂载组件/结构子树有 owner。事件处理器、Signal、Memo、任务、关闭/拖放/命令处理器、行带和绑定消费者都登记在 owner 上。普通元素不再各自创建 owner；资源挂到最近的结构 owner。公开 `Owner`/`OwnerRef` 携带 slot + generation；任务、行带、WindowCtx 与延迟交付必须按 generation 校验，槽位复用不得命中新 owner（§18.5）。应用级共享源挂 `Runtime::app_owner()`，窗口关闭后仍存活。

释放顺序固定：

1. 标记 disposing，拒绝新挂载、新订阅和新事件。
2. 取消任务交付与唤醒；窗口任务随 activation 失效。
3. 先注销事件处理器、绑定消费者和反向边；消费者带 generation，迟到的 flush 直接跳过。
4. 后序释放子 owner；同层 cleanup 按注册逆序执行，每个 cleanup 有 panic 边界。
5. 释放本地编辑状态、撤销历史、组合和行带请求。
6. 清 Signal value、Memo value/deps/compute；槽位 generation 递增并进入 free list；空页归还页池。
7. 清空 `NodeSlot.snapshot`，释放快照/场景缓存引用；共享 `Arc` 由最后一个引用回收。

dispose 期间不允许用户写入。cleanup 回调可以读取仍存活的父级状态，但不能挂载新节点或写 Signal/Store；违反者是 typed error，不是静默忽略。

## 5. 事件模型

### 5.1 事件源

| 源 | 宿主侧事实 | 进入 runtime 的意图 |
|---|---|---|
| 指针移动/离开 | hover、指针位置 | 不进入；宿主保存逻辑指针位置并重命中，更新 `hover_path` |
| 滚轮/滚动条拖动 | applied scroll offset | 不进入；只更新宿主呈现环境；跨行时由宿主发起结构 turn（§15.5） |
| 左键按下 | press target、capture | `Press`（焦点/caret 的 runtime 默认；不是用户事件） |
| 左键松开 | press target、capture | `Activate`（松开且命中同一目标） |
| 键盘 | key、code、modifiers、IME 状态 | `Key` |
| 文本输入/IME | WM_CHAR、composition | `Composition` intent；可打印字符由宿主调用直接原语 `type_text_node`（Event turn，不形成 `Input` intent） |
| 焦点 | 焦点转移原因 | `Focus` / `Blur` |
| 菜单/快捷键/上下文菜单/托盘 | 稳定命令 id + 来源 activation | `Command { id, window, source }` |
| 文件拖放 | 路径列表 | `Drop { window, paths }` |
| UIA 动作 | Invoke/Toggle/SetValue/SetSelection/SetFocus/Scroll | 同一个 per-window FIFO：node action 是 `UiAction` typed command（不走 closest-wins）；Scroll 是 `ProviderAction::Scroll`，由宿主执行 applied-offset（§17） |
| worker 交付 | task generation、value | `Delivery` turn |

指针移动、hover、press 视觉、滚动偏移是**宿主瞬态/环境值**，不进入响应式图，也不产生用户事件。这是 ADR-0006 与 ADR-0010 的既有边界，必须保持。宿主必须在每次场景构建前用最后指针位置重命中，并在捕获丢失/焦点丢失/隐藏/关闭/失活/目标失效时清除 press；焦点/caret/IME 显露走宿主两遍协议（§15.3/§15.4）。

### 5.2 意图与结果

```rust
struct Intent {
    source: EventSource,       // Pointer | Keyboard | Menu | Tray | Accessibility | Window
    target: Target,            // Node(NodeId) | Command { id, window } | Window(WindowCtx) | App
    payload: Payload,          // 类型化事件载荷
    modifiers: Modifiers,
}

struct TurnOutcome {
    consumed: bool,            // 停止后续捕获/冒泡和默认动作
    prevent_default: bool,     // 只跳过默认动作
}

struct TurnReport {
    outcome: TurnOutcome,
    errors: SmallVec<[TurnError; 4]>,
    reveal: RevealFlags,
    changed: bool, // set_row_windows/set_appearance 等宿主命令的“是否改变”
}
```

Intent 是运行时唯一**路由型用户输入**入口。指针、键盘、菜单、托盘、拖放、任务都只是不同的 source；它们共享目标校验、turn 队列、写入门、flush 和错误通道。命令 target 必须携带来源窗口 activation；旧 activation 在路由前拒绝。可打印字符是宿主默认，由 `type_text_node` 在已解析目标上执行（内部是 Event turn），不经过 Intent 路由；UIA 写动作是另一条 typed node command 入口，不走 closest-wins；它们共享校验/turn/flush，见 §16.6/§17。

`dispatch_intent` 返回 `Result<TurnReport, DispatchError>`；宿主用 `report.outcome` 决定原生默认动作，用 `report.errors` 决定是否允许默认动作：

- `consumed`：不再产生后续 `WM_CHAR`、滚动、提交、激活或焦点遍历，也不再运行 capture/bubble 的后续阶段。
- `prevent_default`：后续传播照常，但跳过控件/表单/宿主的默认动作。
- handler 返回 `Err` 或 panic：写入保留，停止本事件剩余 handler 和默认动作；错误进入 `report.errors`，宿主不得执行原生默认动作。
- flush 期间的结构/绑定/焦点错误也进入同一个 `report.errors`；它们不阻止其他 tree 的 flush。

任务交付不是 Intent，但使用同样的 turn 结算规则。TurnReport/TurnError 的完整定义与 panic 策略见 §16.2/§16.4。

### 5.3 路由策略

| 事件 | 默认路由 | 说明 |
|---|---|---|
| `Click` / `Activate` | **closest-wins**：目标自身有处理器则运行；否则沿父链找最近的有 `Click` 处理器的祖先；遇到交互控件但没有处理器时停止 | 行点击、父容器统一处理；不产生双重动作 |
| `DblClick` | **closest-wins**（同 Click） | 双击动作；每次物理点击仍派发 Click |
| `Change` | 直接目标 | checkbox 的 proposed value 与 `on:change` 属于同一控件 |
| `Input`（事件槽） | 直接目标 | 由 `type_text_node` 或 IME 组合提交触发；不是 WM_CHAR 的独立 Intent；不冒泡 |
| `Submit` | 最近的 `form` 祖先 | 宿主解析表单；处理器在表单上 |
| `KeyDown` | **closest-wins**：焦点节点优先，找不到处理器时沿父链 | 文本框的处理器优先；表单/对话框可以兜底 |
| `Focus` / `Blur` | 直接目标 | 焦点结算产生；不冒泡 |
| `Composition*` | 直接目标 | 只属于文本输入；取消是挂起/禁用门的例外 |
| `Drop` | 窗口 | 窗口级处理器 |
| `Command` | 指定窗口的 handler，回退应用级；托盘只走应用级 | 稳定 id + activation |
| `Scroll`（UIA） | 宿主 applied offset | 不进 runtime；与滚轮同路径 |

**为什么默认不是 DOM 式冒泡。** 默认冒泡会让“行点击 + 行内删除按钮”执行两次动作，用户必须记得 `stop_propagation`；漏一次就是业务 bug。closest-wins 只运行一个处理器，覆盖行点击和父容器兜底，且没有双重动作。

**显式传播矩阵。** 需要多个祖先观察时使用 capture/bubble 变体。锚点必须固定，否则同一棵树会因实现不同产生不同结果：

```
hit       = 命中测试后归一化的最深元素（文本上溯、Show/For/组件透明、spacer 跳过）
normal    = hit → 根路径上最近一个有普通 handler 的节点；没有则为 None
capture   = 根 → hit 路径上所有 *_capture 处理器
target    = normal 有值时运行 normal 的普通 handler 一次；否则 target 阶段为空
bubble    = hit 的父节点 → 根路径上所有 *_bubble 处理器
```

- capture/bubble 阶段只在路径上存在对应变体时运行；“有显式声明”指 `hit → 根` 路径，不是整棵树，也不是只到 `normal`。
- `normal` 可以不是 `hit`；`hit` 下方的 capture 处理器仍然按“根 → hit”运行，因此不会被 closest-wins 跳过。
- 普通 `on:click` 不在 bubble 阶段重复参与；要参与 bubble 必须显式写 `on:click_bubble`。
- `consume()` 停止后续阶段和默认动作；`prevent_default()` 只跳过默认动作。
- capture 处理器可以消费事件，使 target/bubble 不运行。
- 每个阶段每个处理器一个 turn 内最多运行一次。
- 禁用控件/祖先禁用：在目标解析时一次性判定，**整次派发不运行**（包括 capture/bubble），返回 no-op。交互控件无 handler：只阻断普通 handler 的祖先穿透；显式 capture/bubble 仍按路径运行（它们是显式观察者）。
- 窗口级 keydown 是根 fallback：没有焦点时 `hit = 窗口根`；有焦点时根处理器参与 capture/bubble。完整规则见 §16.9。

**目标解析：**

1. 宿主命中测试得到最深节点；UIA/命令直接给出 target。
2. runtime 校验 runtime、slot、generation、窗口可见性、关闭挂起：O(1)。
3. 元素节点直接取 `NodeRef`；文本节点上溯到最近的元素；`Show`/`For`/组件在父链上透明。
4. closest-wins 沿 `parent` 上溯，最多到窗口根；深度远小于节点总数。
5. 交互控件（button/checkbox/text-input）即使没有对应处理器也阻断穿透；禁用控件同样阻断，不激活也不穿透。无处理器的交互控件在开发模式给出警告，避免静默死区。
6. 隐藏、关闭挂起的窗口不参与；祖先禁用同样阻断。

**直接 API 与路由 API。** `Runtime::dispatch_intent` 走上述路由。`click_node`/`change_node`/`submit_node`/`keydown_node`/`replace_text_node`/`set_selection_node`/`focus_node`/`type_text_node` 是已解析 target 的直接原语：运行节点自己的 handler 与**节点本地默认**（checkbox 切换、文本替换/插入、selection、focus），不回溯祖先、不执行 capture/bubble、不执行表单/窗口默认（例如 `type=submit` 不提交）。它们返回 `TurnReport`；测试、宿主和 UIA 在 target 已确定时使用。`activate_node` 是路由原语：等价于 `dispatch_intent` 一个 `Activate` Intent，走 closest-wins 与完整默认动作。需要路由/表单语义时用 `dispatch_intent` 或 `activate_node`。

直接原语只允许在 turn 外（宿主/UIA/测试）或 turn 边界调用；在 `Phase::Event/Delivery/Structure/Binding/Memo` 内调用返回 `DispatchError::Reentrant`。这既保留“不重定向”的身份契约，也避免事件槽 `take` 后同步重入。UIA 动作使用直接原语，不从 closest-wins 路由（§17）。

### 5.4 事件载荷与闭包 arity

载荷是拥有所有权的类型化值，字段私有，提供只读访问器和 flow 方法；结构体标 `#[non_exhaustive]`，后续加字段不破坏下游。

```rust
struct ClickEvent {
    source: EventSource,
    target: NodeId,          // 原始命中目标
    current_target: NodeId,  // 实际运行处理器的节点
    position: Option<Point>, // UIA 调用没有坐标
    button: Option<MouseButton>,
    click_count: u8,         // 1=单击，2=双击；UIA 为 1
    modifiers: Modifiers,
    flow: EventFlow,
}

enum EventTarget {
    Node(NodeId),
    Window(ActivationId),   // 窗口根；没有元素身份；ActivationId 定义见 §17.2
}

struct KeyEvent {
    key: Key,                // 逻辑键
    code: Code,              // 物理键；快捷键使用
    modifiers: Modifiers,
    repeat: bool,
    target: EventTarget,     // 无焦点时为 Window(activation)
    current_target: EventTarget,
    flow: EventFlow,
}

struct PressEvent {
    target: NodeId,
    position: Point,
    caret: Option<usize>,   // 宿主从当前场景计算的字符偏移；runtime 不依赖 render
    modifiers: Modifiers,
    flow: EventFlow,
}
struct InputEvent { value: String, source: EventSource, flow: EventFlow }
struct ChangeEvent { proposed: bool, source: EventSource, flow: EventFlow }
struct SubmitEvent { form: NodeId, source: EventSource, flow: EventFlow }
```

`EventFlow` 提供 `consume()` 与 `prevent_default()`，两者都是 `&mut self`；handler 接收 `&mut ClickEvent` 等具体载荷，所以示例不需要额外的 `mut` 绑定：

```rust
on:click={|event: &mut ClickEvent| {
    delete(todo);
    event.consume();
}}
```

宏按闭包字面量的参数个数选择调用形式：

```rust
on:click={|| select(row)}                   // 零参数；不能 consume
on:click={|event: &mut ClickEvent| { ... }} // 一参数；可 consume/prevent_default
```

零参数形式只适合不需要控制传播/默认动作的处理器；需要对 flow 做决定时必须写一参数。命名函数按一参数处理；零参数命名函数写成 `|| f()`。不要在 trait 层用重叠 impl 猜测 arity。处理器可以返回 `()`、`Result<(), E>` 或 `WriteOp<T>`；槽位实际返回 `HandlerOutcome`，`Result::Err` 在 turn 边界停止本事件剩余 handler 与默认动作，写入保留（§16.3）。含 `?` 的闭包必须显式写返回类型，例如 `|event: &mut ChangeEvent| -> Result<(), WriteError> { ... }`。

**按键类型。** `Key` 是逻辑键，至少覆盖字符、Escape、Enter、Tab、Space、Backspace、Delete、方向键、Home/End、PageUp/PageDown、Insert、F1–F12；`Code` 是物理键，供快捷键和布局无关的绑定使用。菜单 `Shortcut` 与 `on:keydown` 共用同一套 `Code`/`Modifiers`，不出现两个同名 `Key`。

**双击。** 每次物理点击都派发 `click`（`click_count` 为 1 或 2）；宿主识别双击时额外派发 `on:dblclick`。单击处理器必须幂等，或使用 `on:dblclick` 承担双击动作；runtime 不引入延时队列。

### 5.5 默认动作与表单协议

用户处理器之后执行默认动作；`consume()` 跳过传播和默认，`prevent_default()` 只跳过默认。

| 事件/场景 | 默认动作 | 执行者/时机 | 可跳过 |
|---|---|---|---|
| 指针按下 | 焦点转移到可聚焦目标；text-input 放置 caret | runtime，turn 内 | consume/prevent |
| 指针松开 | 运行 click；`type="submit"` 且在 form 内提交 | runtime，turn 内 | consume/prevent |
| 键盘按键 | IME → L1 保留键 → accelerator → 用户 keydown → 控件默认 → 窗口/宿主默认 | 见 §16.7 | consume/prevent |
| Enter | 组合确认；按钮/复选框激活；文本输入提交最近 form | runtime，turn 内 | consume / prevent_default |
| Space | 按钮/复选框激活 | runtime，turn 内 | consume / prevent_default |
| Escape | 组合取消；确认窗口 Deny；其他交给窗口默认 | runtime/宿主 | consume（组合/确认窗口除外） |
| Tab / Shift+Tab | 焦点遍历 | runtime，turn 内 | consume |
| PageUp/PageDown/Home/End | 文本输入内 caret；否则滚动 | runtime/宿主 | consume/prevent |
| Backspace/Delete/方向键 | 文本编辑 reducer/caret | runtime，turn 内 | consume/prevent |
| 可打印字符 | 文本插入（WM_CHAR）→ `type_text_node` 直接原语；内部是 Event turn | 宿主，L5 | consume/prevent + 抑制令牌 |
| 按钮松开 | 运行 click 处理器；`type="submit"` 且在 form 内时，handler 未 consume/prevent 则提交最近 form | runtime，turn 内 | consume / prevent_default |
| 复选框 | 宿主产生 proposed value；先运行 `on:change`；未 consume/prevent 时应用本地切换；受控在 flush 后以 `checked` 绑定为准；非受控无 handler 时直接切换 | runtime，turn 内 | consume / prevent_default 阻止切换 |
| 提交 | 运行 form 的 `on:submit` 一次；没有浏览器式后续默认，`prevent_default()` 无实际效果 | runtime | consume |
| UIA Invoke/Toggle/Value | typed node command，与指针/键盘同源校验，但不走 closest-wins | UIA turn（§17） | 由节点 action 决定 |

默认动作的完整分层、执行者与 WM_CHAR 抑制令牌见 §16.6/§16.7。关键修正：Enter 提交同时接受 `consume` 与 `prevent_default`；可打印字符插入是宿主默认，但由 `type_text_node` 在 Event turn 内完成并返回 `TurnReport`，不形成 `Input` intent；Backspace/Delete/方向键不是不可路由的保留键，而是 L4 控件默认，用户可以先用 `on:keydown` 观察/consume。

**表单协议。** 按钮默认 `type="button"`，只有显式 `type="submit"` 且在 form 内才触发提交。点击流程：click handler → 若未 consume/prevent 且 `type=submit`，提交最近 form。Enter 流程：焦点在按钮/复选框时激活控件；焦点在文本输入时 keydown handler → 若未 consume/prevent，提交最近 form。`on:submit` 只运行一次；它没有“浏览器导航”默认动作，因此 `prevent_default()` 在 submit 上没有实际效果，需要停止后续处理时用 `consume()`。API 保留统一的 `EventFlow` 方法，但文档不把 submit 的 `prevent_default` 当作语义。demo 与 tour 必须统一到这条协议，测试“点击/Enter 恰好插入一次”。现有 `type` 只是呈现属性、`type=submit` 点击不提交的代码是附录 A 的现状差距，Phase 3 一并修正。

**文本编辑。** 编辑器 reducer 不是 `on:input` 之后的第二个默认动作；它生成一次 `on:input`。可打印字符由宿主在 `WM_CHAR` 中调用 `type_text_node`（不形成 `Input` intent）；Backspace/Delete/方向键由 `Key` intent 形成编辑或移动。Backspace/Delete/方向键属于 L4 控件默认：用户 keydown 可以先观察并 consume；consume/prevent 后 runtime 跳过编辑默认，宿主通过 `CharSuppression` 令牌跳过对应 WM_CHAR（§16.7）。Ctrl+A/Z/Y/C/X/V 属于 L1 不可路由保留键，用户 keydown 不能拦截。

**复选框状态机。** `checked` 绑定存在时为受控：宿主产生 proposed value，先运行一次 `on:change`；未 consume/prevent 时应用 pending 本地值；handler 失败或模型写入相等/失败时，flush 强制重新对齐 `checked` 绑定，UI 回到模型值。无 `checked` 绑定为非受控：有 handler 时先运行 handler，未 consume 时本地切换；无 handler 时直接本地切换。不存在第二次 `on:change`。`ChangeEvent.proposed()` 是建议值，不是当前绑定值。程序化 Store/Signal 变化不派发 `on:change`；只有用户或 UIA 产生的 Change intent 派发。

**菜单 accelerator 优先级。** L0 的 IME/组合与 L1 的不可路由编辑器保留键（Ctrl+A/Z/Y/C/X/V）优先；其后是 L2 已声明菜单 accelerator；再后是 L3 节点 keydown；L4 控件默认（Backspace/Delete/方向键/Home/End、Enter/Space 激活、Tab、form 提交）；L5 宿主默认。声明为菜单快捷键的组合不再同时作为节点 keydown 派发；需要节点级快捷键时不要声明为菜单命令。完整表见 §16.7。

### 5.6 指针、焦点与 IME

**指针。** 宿主保存**逻辑指针位置**、hover 路径、press 目标、capture 状态和滚动偏移。每次场景构建前、指针输入派发前和 UIA 动作前，用当前场景对最后指针位置重新命中；命中失效（Stale、隐藏、禁用、行窗口卸载）不得继续使用旧 `NodeId`。hover/press 只影响 `SceneEnv`/`InteractionPaths` 与样式条件，不进入响应式图。按下产生 `Press` 意图，runtime 默认完成焦点转移与 text-input caret 放置；松开且命中同一启用目标时产生 `Activate`；拖动离开后松开不激活。press 目标从按下时的 activation target 解析，包含最近可点击祖先；交互控件（包括禁用控件）阻断穿透。捕获丢失、焦点丢失、隐藏、关闭、失活或 press 目标失效时立即清除 press（§15.4）。

**hover / active 路径。** 宿主保存命中的最深 `NodeId` 与最后指针位置，不猜样式。场景构建时把该节点到根的路径作为 `hover_path`；`hover:` 条件对路径内任意元素成立，因此整行 hover 不需要给每个子节点声明样式。`active:` 使用 press target 的路径；`focus-visible:` 只在宿主最近输入来源是键盘时匹配焦点节点（ADR-0006 的 modality 语义，不得简化为“焦点节点恒真”）；`focus:` 无条件匹配焦点节点；`focus-within:` 对焦点路径内的祖先成立。路径长度是树的深度，不是节点数。`SceneEnv` **保持 `Copy + Eq`**；`hover_path`/`press_path`/`focus_path` 放在独立的 `InteractionPaths`，按引用传给场景构建（§15.1）。

**焦点。** 每个 tree 独立保存焦点。可聚焦元素包括 button/text-input/checkbox、声明 `focusable` 的自定义元素，以及显式挂载 focus/blur 处理器的元素。焦点转移先 blur 旧目标、再 focus 新目标；相同目标不派发。结构变化后做一次有界结算：先同 tag 的下一/上一控件，再任意仍可聚焦的下一/上一控件；本帧新挂载的控件不参与接任。结算轮数有硬上限，剩余目标被清除并上报诊断。**行窗口卸载导致的焦点失效直接清除，不参与邻行接任**（ADR-0011）；在节点仍存活且宿主仍能操作时，宿主应在应用新行窗口前对焦点节点执行 Blur 并取消组合（ADR-0011），已卸载节点不再派发 Blur。窗口失活保留焦点，恢复时继续。

每 tree 维护可聚焦节点的有序索引；结构增删/重排时更新。next/prev 目标是 O(log n)，不是每轮全树收集。

**键盘优先级。** 固定顺序（完整表见 §16.7）：

```
L0 IME/组合中的按键（不路由；组合取消例外）
L1 不可路由的编辑器保留快捷键：Ctrl+A / Ctrl+Z / Ctrl+Y / Ctrl+C / Ctrl+X / Ctrl+V
L2 菜单 accelerator
L3 用户 keydown：capture → closest/target → bubble
L4 控件默认：Backspace/Delete/方向键/Home/End 编辑或 caret、
   Enter/Space 激活、Tab 焦点遍历、form 提交
L5 宿主默认：可打印字符 WM_CHAR → type_text_node、滚动、原生焦点遍历/激活
```

任一步 consume 停止后续；prevent_default 只停止默认动作。没有焦点时，keydown 的 `hit` 是窗口根，窗口 `on_keydown` 作为根 fallback handler 运行；窗口可以声明 Escape/Enter 的窗口级处理器，避免焦点丢失后按键无响应。确认窗口的 Escape 是模态默认，先于子控件 keydown；组合取消是唯一例外。Backspace/Delete/方向键是 L4，不是 L1，因此 `on:keydown` 可以先观察/consume；Ctrl+A/Z/Y/C/X/V 是 L1，用户不能拦截。

**IME。** 组合状态属于文本编辑器本地状态，不属于响应式图。组合中的 Enter/Escape 先由编辑器消费；候选确认走一次 `on:input`；取消恢复组合前状态。外部值替换在组合中取消组合并丢弃 preedit。**组合取消是挂起/禁用门的例外**：父窗口等待关闭确认或输入被禁用时，仍允许取消已有组合，避免 OS preedit 卡住。UIA 的 SetValue 走整体替换 reducer，不派发组合事件。

### 5.7 菜单、托盘、UIA、任务

- **命令**：菜单栏、上下文菜单、快捷键、托盘都使用稳定字符串 id + 来源 activation。窗口 factory 注册的处理器在窗口 activation 关闭时释放；应用级处理器在应用 owner 上，不随窗口释放。窗口菜单声明项必须有窗口或应用级处理器；缺失是打开失败，不是运行时静默。托盘命令只走应用级处理器。
- **UIA**：每个窗口一个 fragment root，树由快照与场景派生；发布保持整体替换，事件由相邻两次发布按 runtime ID 比较产生（§17.4）。写动作经窗口动作队列回到 UI 线程，按逐动作矩阵重验（§17.2）：`Invoke`/`Toggle` 调 `click_node`/`change_node`，`SetValue` 调 `replace_text_node`（整体替换、一次 `on:input`、caret 末尾、单条 undo），`SetSelection` 调 `set_selection_node`（不派发 `on:input`，组合中拒绝），`SetFocus` 调 `focus_node`（要求前台），同一 FIFO 中的 `Scroll` 由宿主执行 applied offset。UIA **不走** closest-wins/capture/bubble；它不是普通 Intent。UIA 以可操作语义节点为 target；纯文本子节点不伪装成独立可操作控件。同一个 per-window FIFO 的元素是 `ProviderAction::{Node(UiActionRequest), Scroll(ScrollRequest)}`；两者都是 Send POD，不含 `WindowCtx`/`NodeRef`。完整动作表见 §17.2。
- **任务**：worker 只接收 Send 数据；一个 `drive_tasks` 批次是一个 Delivery turn，内含有序 delivery steps；每步前重新校验 task generation、owner generation、activation、可见性、关闭挂起和节点存活。窗口任务在窗口关闭后取消交付；应用任务可以继续提交共享模型；隐藏窗口允许交付；关闭确认挂起的窗口延迟到 epoch 解除；迟到结果不写入新 activation（§16.10）。

### 5.8 turn 队列与重入

- 每次外部输入、命令、任务批次形成一个 turn；UIA 动作每条形成一个 Event turn（§17.3）。
- 一个 turn 内的处理器按路由顺序同步执行；写入立即可见，后续处理器能读到前面的写入。结构和绑定的一致性在 turn 结束 flush 时保证，不在处理器之间保证；处理器内不要依赖“另一个处理器已经 flush”。
- 处理器内再次产生的派发进入 FIFO 队列，在当前 turn 结束后执行；不允许同步重入同一 tree 的 flush。直接原语在 turn 内调用返回 `DispatchError::Reentrant`（§16.5）。
- 每个 turn 有处理器预算（例如最多 1024 个处理器、64 个窗口/会话请求、8 轮结构/焦点结算）。超限产生 `TurnError::BudgetExceeded`，停止继续 drain 并上报；不静默丢弃。
- turn 结束：flush dirty trees（step 0 quarantine → memo → 结构触发/staging → binding → lineage → focus → cleanup）→ 有效变化判定 → 快照/delta → 结算窗口/会话请求（有上限）→ 再次 flush 受影响的 tree → 宿主根据 `TurnReport.outcome/errors` 执行原生默认 → 按 env 写入显露/绘制 dirty trees。
- 焦点结算产生的 blur/focus 处理器在当前 turn 内运行；它们造成的结构变化进入下一轮结算，受轮数上限约束。
- 任务批次**就是一个** Delivery turn；continuation 之间写入可见，批次结束 flush 一次；panic/Err 停止后续 step 但仍 flush 并报告。
- 滚动跨行产生的 `set_row_windows` 是一个 `Phase::Structure` 的宿主 turn，与输入 turn 分离；不得在场景构建调用栈内运行行 factory（§15.5）。

### 5.9 panic、错误与读取契约

**用户闭包 panic 边界。** 所有用户代码入口统一使用 `catch_unwind` + 状态恢复：

| 入口 | panic 后处理 |
|---|---|
| 事件处理器 | 恢复事件槽、phase；保留 panic 前已设置的 flow；停止本事件剩余 handler 与默认动作；`TurnReport.errors` 记录 `HandlerPanicked`；flush 继续，runtime 可继续 |
| Memo 计算 | 恢复 `computing`/phase；memo 标 `poisoned`：有最后已提交值时 `get` 返回最后值并报 typed fault；没有最后值时 `get` panic、`try_get` 返回 `ComputedPanicked`；组件可重挂载恢复 |
| Binding 求值 | 只可能来自用户 memo/Field；由 memo 边界处理；binding 保留最后值并记录 `FieldFault`/`ComputedPanicked` |
| Show/For factory | 捕获；释放拟议 owner/fresh 行；保持旧结构；记录 `FactoryPanicked` |
| cleanup | 捕获；继续释放其余资源；记录 `CleanupPanicked`；不让 panic 穿过析构链 |
| 窗口 factory / on_close / on_drop / on_command | 捕获；恢复阶段；转 typed error；不穿过窗口过程 |
| on_menu_state | 捕获；保持菜单原状；不改变 `TurnOutcome` |
| task continuation | 捕获；停止批次后续 step；保留已写入状态；批次末 flush 并报告 |

要求构建使用 `panic = "unwind"`；`panic = "abort"` 下不承诺 containment。所有 scope 恢复（`current_owner`、`phase`、`read_only`、`take_tree`）使用 RAII `Drop` guard（§16.4）。

**错误分层。**

| 层 | 类型 | 典型值 | 处理位置 |
|---|---|---|---|
| 输入/派发 | `DispatchError` | UnknownNode、StaleNode、Hidden、Suspended、WrongKind、Reentrant、TargetClosed、BudgetExceeded | turn 边界；宿主区分预期与程序错误 |
| turn 内 | `TurnError` | HandlerFailed、HandlerPanicked、Reactive、FactoryPanicked、FactoryFailed、CleanupPanicked、StructureWriteRejected、FieldFault、CloseConfirmationNotShown、BudgetExceeded | `TurnReport.errors` |
| 写入 | `WriteError` | Context、Fatal、Rejected、Missing | 命令边界；模型不变 |
| 窗口 | `WindowError` | WrongRuntime、Stale、Hidden、Suspended、Close | 宿主/应用 |
| 模型事务 | `Fatal`/`ValueError` | 阶段违规、值拒绝、图环 | 事务边界 |
| 响应式/结构 | `ReactiveError` | DuplicateKey、FactoryPanicked、ComputedPanicked、GraphCycle、TurnBudgetExceeded | flush/turn 边界 |
| 呈现 | `SceneError`/`RenderError` | 布局、字体、GPU、surface | 宿主恢复或上报 |

用户处理器可以返回 `()`、`Result<(), E>` 或 `WriteOp<T>`；`HandlerOutcome` 适配三种返回。`Result::Err` 在 turn 边界进入错误通道并停止本事件剩余 handler/默认动作；`WriteOp<T>` 立即执行，`T` 丢弃，需要返回值时用 `WriteOp::finish()`。

**读取契约。** `Signal::get`/`Memo::get` 用于确定存活的同 owner 上下文；同一 owner 内违反 handle 契约（disposed/未挂载）是开发期契约 panic，带节点、owner、generation 诊断。可能跨 owner、跨 turn 或目标可能消失的边界使用 `try_get() -> Result<T, HandleError>`，返回 `Disposed`/`WrongOwner`/`ComputedPanicked`/`GraphCycle` 等 typed error；`Field::get` 保持 `Result`。这样不会把每个普通读取都变成 `Result`，也不会用默认值掩盖边界错误。binding 层使用 `try_get`/`ReadValue`，保留最后值并报 `FieldFault`（§18.2/§18.3）。

### 5.10 多窗口语义

- `WindowCtx` 绑定 runtime + catalog key + `ActivationId` + owner；`ActivationId` 是 §17.2 的 runtime 全局窗口槽 + generation，不是 per-key 的裸 u32；旧 activation 的 Intent 被拒绝。
- 每个 tree 独立焦点、本地编辑、快照根、revision、脏集、`env_generation`。共享源写入把消费者所属 tree 放入 `dirty_trees`；turn 结束统一 drain。
- 隐藏窗口保留树与本地状态，但停止输入、语义动作和呈现；共享写入仍标记它，**turn 末 flush 与可见窗口同步完成**；只有快照根/场景构建延迟到 show 或任何读取其状态的入口之前。隐藏窗口的 Delivery 允许运行。
- 关闭窗口释放树、owner、事件和任务；重开得到新 activation。关闭确认挂起期间，窗口任务交付延迟到 epoch 解除；Allow 后继续、Deny 后继续、Close 后丢弃。
- 关闭确认期间父窗口输入挂起；确认窗口自身的 Escape/X 表示 Deny。组合取消是挂起门的例外。拖放、菜单、UIA、键盘遵守同一挂起门。
- 应用外观写入把所有 tree 放入 `dirty_trees`；系统偏好/DPI/滚动只推进各自 `env_generation`，不 bump 快照 revision。未变化窗口不重建快照/布局/场景。
- 窗口/会话请求在 turn 后结算，每次 drain 有上限；请求产生的嵌套 show/close 进入下一轮，不允许无界递归。
- `show`/`hide`/`set_row_windows`/`set_appearance` 等宿主入口如果会运行用户 factory（show 挂载）或改变结构，必须在 turn 边界执行或走命令 turn；不能在 flush 中间重入用户代码。

### 5.11 flush 与 paint 的边界

- runtime 的 flush 在 turn 结束同步完成，保证下一个 turn 开始时状态、绑定和结构一致；同一 turn 的处理器之间只保证写入可见，不保证结构已 flush。
- 快照/场景/布局的构建可以推迟到宿主需要时：`tree.revision` 变化后按需构建一次，未变化时复用 per-tree 根；`env_generation` 或 `InteractionPaths.generation` 变化时按 §15.2 的环境矩阵重建场景/缓存，但不重建快照。`InteractionPaths` 只有在解析后的样式改变布局属性时才标布局脏。
- 宿主输入命中始终使用当前 applied offset 与当前环境的场景；场景过期时先更新场景再做命中，不用旧几何派发新输入（ADR-0010）。
- 焦点/caret/IME 变化由 runtime 产出 `RevealFlags`；宿主按 §15.3 的两遍协议显露。显式滚轮/翻页/UIA Scroll 清除待决显露；滚动本身不触发展露。
- 滚动跨行时先由宿主发起 `set_row_windows` 批量结构 turn，再构建 pass 2 场景；不得在 `Scene::build`/`ensure_scene` 内运行行 factory（§15.5）。
- 连续输入可以在一个消息批内形成多个 turn；每个 turn 同步 flush，但绘制合并到帧边界。输入 turn 不等待绘制。
- 动画、ticker、滚动惯性属于 renderer 的呈现调度，不写入响应式图；业务只提供目标值。
- 空闲窗口停帧；没有 revision 变化、没有 `env_generation`/路径变化、没有 damage 的窗口不做任何呈现工作。

### 5.12 平台映射

| 能力 | Windows | macOS | Linux |
|---|---|---|---|
| 窗口/输入 | HWND/WM_*、DPI、DirectComposition | NSWindow/NSEvent、NSTextInputClient | Wayland/X11、输入法协议 |
| 辅助技术 | UIA | NSAccessibility | AT-SPI |
| 菜单/托盘 | HMENU、Shell_NotifyIcon | NSMenu、NSStatusItem | 桌面环境协议 |
| 拖放 | OLE IDropTarget | NSDraggingDestination | XDND/Wayland DnD |

平台层只负责把原生事实归一为 Intent、宿主瞬态和 typed capability；公共事件、路由、响应式和生命周期语义不依赖平台。平台缺失的能力返回 `Unsupported`，不以空操作或替代控件伪装成功。

### 5.13 明确边界

本方案不提供：

- 指针移动/进入/离开的业务事件（只有 `hover:` 样式和 activation）；需要延迟预览/悬停加载时，后续增加带 enter/leave 的 `on:hover`，不在首版伪装。
- `focusin`/`focusout` 事件；用 `focus-within:` 条件覆盖“组高亮”，需要业务监听时后续增加焦点路径事件。
- 节点级上下文菜单；当前用窗口级菜单 + 选中行 Signal，后续增加 `on:contextmenu`。
- 可变行高虚拟列表；窗口化 `For` 只支持固定 `row-height`，未声明时全量挂载并给出诊断。
- 多指、压力、指针捕获等扩展指针事件；首版只有主键 activation 和宿主 capture。

## 6. 响应式更新

### 6.1 图节点

```
Source                          Derived                     Consumer
Signal<T> ────────────────┐
Store Field(row, kind) ───┼──► DepId ──► Memo ──► DepId ──► ConsumerRef
Rows(filter) ─────────────┤                    │            Binding / Structural / Memo
Appearance ───────────────┘                    └───────────► ConsumerRef
```

- **Source**：Signal、Store 字段（按行 + 字段种类）、行集（按 filter）、Appearance。
- **Derived**：Memo；命名或 data-position 隐式创建。每个 memo 持有 `deps: DepListId`（指向独立 `MemoDepsArena`），重算时整体替换列表。
- **Consumer**：`ConsumerRef::{Binding, Structural, Memo}`。消费者不是堆节点，只有引用和缓存值。Binding/Structural 消费者属于某个 tree；Memo 消费者属于 runtime 全局图，不归 tree。

`DepKey` 是语义键，必须带源槽的 generation：`Signal { slot, gen }`、`Memo { slot, gen }`、`Field(FieldKey { row: RowId, field })`、`Rows(filter)`、`Appearance`。`RowId` 是 `{ slot, generation }` 的 arena 身份，业务 key 单独存在行数据中；删除后同业务 key 重建行产生新 `RowId`，不得命中旧绑定（§18.6）。`DepKey → DepId` 使用 intern 表；memo/节点释放时移除对应边，最后一个消费者离开且源已释放时移除 intern 条目。反向边是 `DepEntry { first_edge, len }` + 扁平 `EdgeArena`，按 DepId 索引；一次写入只遍历该源的消费者，不克隆集合（§19.9）。

`ConsumerRef::Memo` 让 source→memo、memo→memo、memo→binding 三类边都存在；三级链条和菱形共享都走同一张表。共享 memo 的消费者可以跨 tree；它的值变化时，Memo 消费者进入全局 dirty memo worklist，Binding/Structural 消费者标脏并把各自所属 tree 放入 `dirty_trees`。

### 6.2 读源与绑定槽

```rust
enum Read<T> {
    Static(T),          // 语法字面量
    Once(Once<T>),      // 显式快照；与 Static 同样无 DepKey，但保留诊断来源
    Signal(Signal<T>),
    Memo(Memo<T>),
    Field(Field<T>),    // 可读字段；bool 属性常用
}

enum ReadValue<T> { Value(T), Fault(ReadFault) }
```

`Read<T>` 是公开的读源；`From` 覆盖 `&'static str`、`Once<T>`、`Signal<T>`、`Memo<T>`、`Field<T>`。绑定槽持有 `Read<T>` 或由它导出的槽类型（§18.2/§18.4）；`T` 必须实现 `ReactiveValue`。`Read::Field` 的求值可能返回 `ReadFault`；绑定层保留最后值并按 part 策略处理（§18.3）。

| 用户写法 | 槽类型 | 静态依赖 |
|---|---|---|
| `<text>{"title"}</text>` | `Read::Static` | 无 |
| `<text>{once(title)}</text>` | `Read::Once` | 无 |
| `<text>{title_signal}</text>` | `Read::Signal` | `Signal(id, gen)` |
| `<text>{\|\| format!("{}", count.get())}</text>` | `Read::Memo`（隐式 memo） | `Memo(id, gen)` |
| `value={draft}` | `Read::Signal` | `Signal(id, gen)` |
| `disabled={busy}` | `Read::Memo/Signal` | `Memo/Signal` |
| `checked={completed}` | `Read::Field/Memo` | `Field/Memo`；Field 可失败 |
| `style:color={tint}` | `Read::Memo` | `Memo(id, gen)` |
| `<Show when={when}>` | `Read<bool>` | `Memo/Signal/Field` |
| `<For each={source}>` | `ForSource<R> { Store<R>, Read<RowSet> }` | `Memo/Signal` 经行集；裸 `Read<RowSet>` 必须同时给 `store` |

**值位置规则。** 数据位置只接受：

1. 语法字面量（字符串、bool、数值），宏降为 `Static`；
2. `Once<T>`，显式快照；
3. `Read<T>` handle（Signal/Memo/Field）；
4. 闭包字面量，降为隐式 `memo`。

非字面量的 `String`、`bool`、`.get()` 不实现读源 trait，直接编译错误，诊断提示 `once(...)` 或传 handle。`em(1.75)`/`Color::...` 等 typed 常量不是语法字面量，必须写 `once(...)` 或显式 `static_` 构造；SDK 示例同步修正（§21.2）。这与[技术架构](技术架构.md)“普通数据位接收 handle、字面量或 once”一致，消灭“能编译但永远不更新”的最大一类问题。

**闭包糖的位置表。** 只在这些位置把闭包字面量降为 memo：

| 位置 | 闭包字面量 |
|---|---|
| 文本子节点 `{...}` | 隐式 memo |
| intrinsic 的 `value`/`disabled`/`checked`/`aria:*`/`style:*` | 隐式 memo |
| `Show when={...}` | 隐式 memo |
| `on:*` | 事件 handler，不降为 memo |
| `Show fallback={...}`、`For` 行 factory | factory，不降为 memo |
| `Children`/`ChildrenFactory`、具名 slot | factory，不降为 memo |
| 组件数据 prop | 类型导向；传 `Read<T>`/`Once`/handle，不按闭包猜 |

宏只在这张表内应用闭包糖；组件属性保持 `.prop(expr)` 的类型导向，避免把 factory 误包成 memo。`For each` **不接受闭包字面量**：它需要 `ForSource<R>`（`Rows` 自带 store）或 `Read<RowSet>` + `store`，否则 key/item 工厂没有行数据入口。

### 6.3 动态绑定

```rust
<text>{|| format!("{} remaining", remaining.get())}</text>

<button disabled={|| remaining.get() == 0}>"Clear"</button>

let label = memo(|| format!("{} ({})", draft.get(), count.get()));
<text>{label}</text>
```

数据位置的闭包字面量由宏降为 `memo(|| ...)`；非闭包表达式用显式 `memo(|| ...)` 包装。宏不需要知道闭包内部读了什么，memo 在求值时通过求值栈登记依赖。

动态规则：

- memo 是缓存派生：失效不立即重算；flush 时按依赖顺序重算仍被 mounted 消费者订阅的脏 memo，未被订阅的留到下次读取或释放。读取一个仍 dirty 的 memo 会先求值；flush 的 worklist 只是提前做同样的事，保证消费者看到一致值。值相等不推进 revision，不标记下游。
- 每次重算整体替换依赖集，支持分支切换（这次读 A，下次读 B）。
- 同一个 memo 句柄被多个槽共享时只算一次；同一表达式写两次就是两个 memo，和手写 memo 的规则一致。
- 闭包必须捕获 handle，不能捕获值；捕获值只在挂载时读一次。文档和诊断要明确这一点。
- 不要给简单 handle 包一层 memo：`value={draft}`、`disabled={busy}` 直接绑 handle；只有计算、组合、分支或格式化才写闭包。每个隐式 memo 都是一个图节点，无差别包装会增加内存和求值层。
- memo 创建发生在挂载/结构分支挂载期间；事件处理器或 memo compute 内创建 Signal/Memo 默认拒绝（`CreationError::NoOwner`），除非显式传 `signal_in(owner, ...)`/`memo_in(owner, ...)`。隐式 memo 的 owner 是产生它的节点/组件 owner，卸载时先退订再释放（§18.5/§18.10）。

### 6.4 写入与标脏

**Signal 写入：**

```
set(value):
  writes += 1
  if value != current:
      current = value
      mark all direct consumers dirty
      invalidate dependent memos
  else:
      mark only write-epoch observers dirty   // 文本 value 绑定
```

相等写入只标记声明了 `observes_writes` 的 value 绑定（文本编辑血统），不标记所有直接消费者，也不使 memo 失效。这样 `set(相同值)` 不会把 10k 行全部拉进 worklist；文本编辑器仍能观察写入。

**Store 提交：**

事务提交产出精确变更集：

```rust
struct ChangeSet {
    inserted: SmallVec<[RowId; 8]>,
    removed: SmallVec<[RowId; 8]>,
    fields: SmallVec<[(RowId, FieldId); 8]>,
    membership: SmallVec<[FilterId; 8]>,
    order: bool,
}

struct PendingChanges {
    stores: SmallVec<[StoreChange; 4]>,
}

struct StoreChange {
    store: StoreId,
    changes: ChangeSet,
}
```

这里的 `RowId` 是 **arena 身份** `{ slot: u32, generation: u32 }`（8 B），不是业务 key；业务 key 存在行数据中并由 Store 的 key→slot 索引解析（§18.6）。`FieldId`/`FilterId` 由模型定义注册；不能使用 Todo 专用 `FieldKind` 或 `[bool; 3]`。`Store::commit` 返回 `ChangeSet`；Runtime 把**自上次 flush 以来的所有提交**累积为 `PendingChanges`（不是只保留当前 turn 的最后一个提交），flush 的 step 0 读取其中的 `removed`（§18.7/§18.8）。`StoreId` 是 runtime 内的 store 槽，只用于把 `StoreChange` 路由到对应 store；`RowId` 来自 runtime 全局 row arena，本身已全局唯一。Store 必须维护“变化字段 → 候选 filter”的反向索引，对不在当前结果内的候选行也重新求值 predicate，产出 membership 迁移；否则标题搜索/优先级过滤会漏行。

只标记实际变化的字段/行集/顺序依赖；未变化的写入不产生 touch。删除行时先在 flush step 0 把该行标记为 quarantined，再求值其他字段绑定；结构提交确认卸载后才撤销该行元素的绑定和订阅。被删除元素的迟到绑定引用按 generation 拒绝（§6.5/§18.8）。

`Field` 读取失败（行已删除）不得用 `.ok()` 静默丢掉属性。绑定保留最后已提交值，并在 turn 边界报告 `FieldError::Missing`；如果元素仍在其他窗口且绑定无法恢复，标记该 binding 为 error 态，直到行重新出现或元素卸载。UI 不把 Missing 当作 `false`/空字符串。首次求值失败的 part 策略见 §18.3：文本为空、bool 属性缺席、Show 不挂载、For 空行集，但都记录 fault，不把 fault 解释成业务值。

受控 checkbox 在每次 `Change` turn 后强制按 `checked` 绑定对齐一次，即使 Store 写入相等或失败；对齐直接读取绑定当前值，不依赖 source touch。这样 handler 未接受 proposed value 时，本地 pending 不会与模型分叉。

**Appearance 写入：** 标记 `Appearance` 源，把所有 tree 放入 `dirty_trees`，每个 tree 更新 `SnapshotRoot.appearance` 并 bump `revision`。不能降级为“只影响订阅外观的 memo/binding”：`dark:` 是场景条件，快照携带 appearance，主题切换必须重绘所有窗口（ADR-0006/ADR-0022）。

**本地编辑状态：** caret、selection、composition、checkbox 本地 pending 不进入响应式图；它们直接标记节点 dirty 和 tree revision。文本编辑血统（origin/revision/settlement）继续由编辑器本地保存，绑定只负责把已提交值分类为结算、stale 或外部替换。

**行集相等。** `Memo<RowSet>` 的比较通过统一 `ReactiveValue::equivalent`；`RowSet` 的 impl 先使用 `shares_with`/query revision，不相等地才做深比较；深比较**包含 ids 顺序**，纯 reorder 不能被判等。避免每次过滤变化都 O(总行数) 比较整个切片。过滤重建使用复用 scratch，瞬时 O(R) 但不保留全量映射。`RowSet` 是唯一一份全量 keyed order（O(总行数)），For 不另存第二份（§19.8）。

### 6.5 flush 算法

```
flush(dirty_trees, pending: &PendingChanges):
  0. quarantine removed rows
     对 pending 中每个 StoreChange.changes.removed 的 RowId：标记为 retired/quarantined；
     本 turn 的 liveness 跳过只服务这些行的 memo。**暂不删除边**，等结构提交确认该行确实卸载。
  1. dirty memo worklist（runtime 全局）
     只取仍被 mounted 消费者可达的脏 memo；跳过 quarantined 行；按依赖顺序求值；
     值变化 → Memo 消费者加入全局 worklist，
     Binding/Structural 消费者标脏并把所属 tree 加入 dirty_trees；
     相等 → 不标记下游。
  2. for each tree in dirty_trees（稳定顺序）:
     2a. structural trigger evaluation
         对每个脏的 ShowWhen/ForEach binding：读取 source → 写 BindingSlot.current/fault →
         记录 BindingPatch → 标记该 part 已求值；失败按 §18.3 保留旧 current 并报 fault。
     2b. structural staging + commit（使用 2a 刚写入的 current）
         Show: 预挂载新分支，校验通过后替换；失败释放拟议分支，保持旧分支。
         For: 预校验 key/新行，预挂载 fresh 行，提交 order/items；失败释放 fresh，保持旧映射。
         提交成功：对确实卸载的 quarantined 行执行预退订并移除边；
         提交失败：释放拟议结构，旧结构保留，取消该批 quarantine（行仍挂载，边不删）。
         提交后把新挂载节点及其绑定加入 binding worklist（初值求值）；
         未提交的拟议绑定不进入 worklist。
         焦点 grace/行窗口变化在此处理。
  3. binding worklist
     对每个脏 ConsumerRef：求值 → 与 current 比较 → 变化则写回并记录 BindingPatch。
     跳过 2a 已求值的结构 part；一个 part 一个 turn 最多应用一次。
     文本 value 绑定同时标记 lineage pending。
  3.5 pending edit lineage observe
     本 turn 有 pending edit 或 turn_epoch 的文本输入，无论 value binding 是否脏，
     都执行一次 lineage observe；分类 settlement/stale/external reset 后再清 epoch。
  4. focus settlement
     结构提交后，结算发生结构变化或焦点元素失效（disabled/隐藏/卸载）的 tree；
     行窗口卸载直接清除焦点；blur/focus 处理器写入产生的新脏工作回到 1-3，轮数有上限。
  5. cleanup
     释放已卸载节点/owner；先退订事件/绑定/反向边，再清 value，再回收槽位。
  6. effective change
     只要有可见值、结构、焦点、本地编辑或外观变化，tree.revision += 1；
     没有变化则保持 revision 和快照根不变。
```

步骤 2 处理中新标记的 tree 加入本轮 `dirty_trees`；步骤 3-6 按 tree 分组处理，每个 tree 独立 revision 和快照根。

worklist 使用去重位图或 epoch 标记；同一个 binding 一个 turn 最多求值一次，除非焦点结算产生新一轮。脏 memo 只包含仍被 mounted 消费者**可达**的节点（liveness 定义见 §18.8）；卸载时已经退订。memo 失效但重算相等时，binding 不重求值、不产生 patch；同一 turn 内被再次标脏的 memo 必须重新入 worklist，不得因“已算过”跳过。删除行的 **quarantine** 必须在 memo worklist 之前完成；实际退订只在结构提交确认卸载后执行。焦点/结构提交产生的新的 Store 提交合并进 quarantine，并在回到 1 之前重新执行 0/2a；`PendingChanges` 只在 step 6 之后清空。

求值顺序保证：

- memo 在消费者之前；
- 结构预挂载在提交之前，父节点的结构变化在子节点绑定之前；
- 焦点结算在结构提交之后；
- cleanup 在 patch 之后，但在下一次读取之前；
- lineage observe 在 value binding 求值之后、turn 结束之前；
- 同一个 turn 的可观察结果与“先写完所有状态，再做一次全量一致性检查”等价。

### 6.6 结构更新

**Show：**

- `when` 是 `Read<bool>`；值变化才切换分支。
- 挂载新分支：创建 owner、运行 factory、登记绑定和事件；factory panic/Err 时释放拟议 owner，保持旧分支。
- 卸载旧分支：先注销事件/绑定/任务，再释放子 owner；旧 NodeId 变 Stale。
- 分支挂载失败：释放整个拟议分支，保持旧分支，返回 typed error。

**For：**

- `each` 是 `ForSource<R>`（`Store<R>` + `Read<RowSet>`）；`Rows<R, F>` 自带 store，可直接传入；裸 `Read<RowSet>` 只有在同时给 `store={...}` 时才接受；`Static` RowSet 必须由 `Store::rowset(...)` 构造（携带 `StoreId`）。不再只收 `Memo`。
- `RowSet` 投影变化时做一次 O(总行数) key 映射和重复 key 校验；`RowSet` 的顺序是 Store 当前用户顺序（受 order revision 驱动），不是业务 key 排序；重复 key 是 typed `ReactiveError::DuplicateKey`，不提交任何行变化。
- keyed 重排移动节点，不重建行组件；行内 caret/selection/composition 跟随 `RowId`（slot + generation），不跟随裸业务 key；业务 key 由 `Store::key_of(RowId)` 解析，行数据由 `Store::get(RowId)` 解析。
- 未声明 `row-height`：全量挂载，文档明确 O(总行数) 内存，并在超过阈值时给诊断。
- 声明 `row-height`：只挂载宿主行窗口内的行；上下 spacer 保持总高度；行窗口由宿主从场景几何和 applied offset 换算；焦点行在窗口外一行内时扩大窗口，更远则卸载并清除焦点。
- 持久簿记 O(窗口)，完整顺序由共享 `RowSet` 提供。
- 结构提交是 per-For 原子的：先预校验/预挂载，再一次性提交 order/items；失败释放 fresh，旧映射不变。其他节点的 binding patch 不回滚，但 turn 报告错误。

### 6.7 有效变化与 revision

以下变化必须计入 effective change：

- binding 值变化（文本、bool、字段、style）；
- Show 分支切换、For 行挂载/卸载/重排/行窗口变化/spacer 高度；
- 焦点转移（snapshot.focus 变化）；
- 文本编辑器的 caret/selection/preedit/组合状态变化；
- checkbox 本地 pending 值变化与 reconciliation；
- appearance；
- 行带元数据、窗口可见性、激活；
- `once` 文本在重挂载时的值变化；
- 结构提交成功或失败导致的可见结构变化。

没有以上变化时，不 bump revision、不重建快照、不重排布局、不绘制。每次 turn 在测试模式下用**独立的参考实现**（绕过 binding 缓存、从源重新求值、重算全部 memo）与增量快照对照，验证 changed 判定没有漏项；不能复用生产缓存，否则漏标脏会被同样复制（§20.4）。

binding 的 fault 状态本身不自动计入 effective change；只有它改变可见文本/属性/结构时才计入。文本缩放、高对比度、DPI、滚动、hover/press/focus 路径属于宿主环境，走 `env_generation`/`InteractionPaths.generation`，**不** bump `tree.revision`（§15）。外观是已提交状态，计入 revision。

### 6.8 文本编辑的 equal-write 语义

- `value` 绑定为 `Signal<String>`：`writes` 每次写入推进（包括相等写入）；编辑器据此识别“处理器处理过这次编辑”，即使值归一化后没变。
- `value` 绑定为 `Memo`：只有值变化才推进 revision；相等写入无法与“推迟写入”区分。这是 ADR-0019 已有语义。
- 可编辑值推荐直接绑定 `Signal`，不要用 `memo(|| draft.get())` 或 `memo(|| draft.get().trim())` 包一层；如果绑定是 `Memo` 且同时有 `on:input`，开发模式给出警告并给出 Signal 写法。
- 外部替换清空历史、组合中取消组合、stale settlement 的规则保持 ADR-0019 不变。
- 每个有 pending edit 的输入在 turn 结束时都必须 observe，即使它的 value binding 没有脏；这是 ADR-0019 “every refresh reads committed value” 在增量刷新下的等价物。

### 6.9 复杂度

| 操作 | 目标复杂度 |
|---|---:|
| Intent 目标解析 | O(1) + O(深度) |
| 命中测试 | O(可见元素) 或场景空间索引 O(log n + hits)；大列表必须窗口化 |
| 一次 Signal 写入标脏 | O(该源消费者数) |
| 一次相等 Signal 写入 | O(write-epoch 观察者数)，通常只有聚焦文本输入 |
| 一次 turn 的 binding 求值 | O(脏绑定数) |
| memo 重算 | O(脏 memo 数 × 依赖数) |
| 单行字段更新（窗口化） | O(订阅该字段的绑定数 + 快照路径) |
| 行窗口滑动 | O(进出窗口的行 × 行内节点) |
| 行集投影变化 | O(总行数) 瞬时校验 + O(窗口) 持久 |
| 主题/外观切换 | O(订阅外观的绑定 + 可见节点布局) |
| 空 Intent / Store no-op | O(1)，不重建快照 |
| 未窗口化大列表单行更新 | O(兄弟数) 快照/布局；文档不承诺 O(1) |
| 全量结构替换 | O(被替换子树) |

最坏情况是外观广播、完整行集重建、大子树挂载/卸载和布局失效；这些是实际工作，不伪装成 O(1)。未声明 `row-height` 的 `For` 不享受“单行 O(1)”承诺，诊断和文档必须明确。

## 7. 呈现派生

### 7.1 持久化快照与 delta

```rust
enum SnapshotNode {
    Element(SnapshotElement),
    Text(SnapshotText),
}

struct SnapshotElement {
    key: PresentationKey,
    id: NodeId,
    tag: &'static str,
    attrs: AttrSlice,          // 共享 attr arena 的 offset/len
    styles: StyleSlice,        // 共享 style arena
    edit: Option<EditId>,      // 共享 edit arena；不内联 TextEditState（88 B）
    semantics: SnapshotSemantics,
    children: PersistentChildren, // 分块持久序列
    revision: u64,
}

struct SnapshotText {
    key: PresentationKey,
    text: Arc<str>,
    revision: u64,
}

struct SnapshotRoot {
    nodes: PersistentChildren,
    focus: Option<NodeId>,
    appearance: Appearance,
    row_bands: SmallVec<[SnapshotRowBand; 2]>,
    revision: u64,
    env_revision: u64,          // 诊断用；不参与呈现相等性
}

struct PresentationDelta {
    from_revision: u64,
    to_revision: u64,
    changed: SmallVec<[PresentationKey; 16]>,
    inserted: SmallVec<[PresentationKey; 8]>,
    removed: SmallVec<[PresentationKey; 8]>,
    removed_subtrees: SmallVec<[PresentationKey; 4]>,
    layout_roots: SmallVec<[PresentationKey; 4]>,
    focus_changed: bool,
    appearance_changed: bool,
    row_bands_changed: bool,
}
```

- **每个**快照节点（包括文本）都有 `PresentationKey`。它是 `NodeRef` 的公开编码；renderer 用它作为 Taffy/布局/绘制缓存的键。槽位复用必须换 generation；runtime 的 `NodeRef` 不暴露。
- `children` 使用持久化分块序列（chunked persistent vector / rope），替换一个子节点只复制 O(log n) 的 chunk 路径，不复制整段兄弟列表。快照节点头与 attrs/styles/children 必须分离；内联 `SmallVec<[SnapshotAttr;4]>` 会把节点撑到约 350 B（§19.7）。
- 每次有效变化只重建从变化节点到根的路径；未变化子树共享 chunk 和节点。
- 每个 tree 一个 `Arc<SnapshotRoot>` 数据根；**对外发布与持有的是 `PresentationSnapshot`**（包裹 `Arc<SnapshotRoot>` + revision，§19.1/§19.2）；宿主、UIA、renderer、测试都持有 `PresentationSnapshot`，旧根在最后一个引用释放时回收。
- 快照构建不执行用户闭包、不修改保留树；它只读取 `BindingPatch`/结构提交的已提交结果，不重新读取绑定源。
- 没有变化时根指针不变；宿主比较 `Arc::ptr_eq` 或 per-tree revision，跳过重建。
- 每个**可见且存在发布消费者**的 turn 同步构建 `PresentationUpdate { snapshot, delta }`；`delta.from_revision` 是**上次成功发布的 revision**（不要求等于 `snapshot.revision()-1`，批量提交时是累计 delta），`delta.to_revision == snapshot.revision()`。隐藏窗口只在**快照/场景构建**上延迟，flush 与 revision 已在 turn 末同步完成；show 前构建完整根，`delta: None` 表示全量。UIA **不消费** delta；delta 只服务 renderer（§17.4/§19.4/§19.5）。
- delta 应用协议：`applied_revision` 存在于 **renderer/host 的 per-tree 视图**，不在 runtime tree；runtime 只维护 `last_published_revision`。renderer 只接受 `from_revision == applied_revision` 的 delta；断档时丢弃 delta、按最新根全量重建（合法回退）。`changed` 包含祖先路径；`removed` 包含被移除子树的每个 key；`removed_subtrees` 是根，供快速清理（§19.3/§19.4）。

`SnapshotNode::Text` 也携带 `PresentationKey`；结构节点在快照中透明，但它们的子树节点保留 key。

### 7.2 增量布局与场景

- 保留 Taffy 树以 `PresentationKey` 为键；节点保存 last layout、resolved style、文本上下文。renderer 不读取 runtime 私有 `NodeRef`，依赖方向保持 `windows → render → presentation types`。
- 场景缓存键 = `(tree_key, snapshot.revision, env_generation, interaction_paths.generation)`（§15.2）。`SceneEnv` 保持 `Copy + Eq`；`hover_path`/`press_path`/`focus_path` 在独立 `InteractionPaths`，不把 `SceneEnv` 改成 `Clone`。
- 样式、文本、结构变化标记节点及必要的祖先布局脏；Taffy 只重排脏子树，未变化子树复用 layout。父容器的 flex 重排和兄弟位移是实际工作，计入复杂度，不宣称单节点 O(1)。
- 文本 shaping 缓存以文本、字体、字号、variation、可用宽度、换行模式、window scale、`text_scale_percent` 为键；缓存按字节/LRU 管理，只保留可见窗口加预取行；命中返回 `Arc<Layout>`，不 clone 完整 glyph。
- 场景使用**未翻译内容坐标 + 一个 applied offset**；hit-test、caret、IME、绘制共用同一份，不在绘制时二次叠加偏移（ADR-0010）。
- 焦点/caret/IME 变化不直接改偏移；宿主按 §15.3 的两遍 reveal 协议夹取 offset 并重建场景；显式滚动清除待决显露。
- 滚动跨行由宿主发起 `set_row_windows` 批量结构 turn，再构建 pass 2 场景；不得在 `Scene::build`/`ensure_scene` 内运行行 factory（§15.5）。
- 每个节点保存绘制记录；变化节点的旧/新矩形以及被推挤的兄弟矩形合并为 damage；窗口只重绘 damage，或按后端能力整帧重绘。damage 不完整时回退整帧，不留下幽灵像素。
- 布局/场景仍是派生结果，不可修改保留树；ADR-0002 修订为允许“不可变、可丢弃、结构共享的派生缓存”。

窗口化把可见 V 压到约 32 行，但大表单、深层嵌套和整页布局仍随 N 增长；保留 Taffy 是长线方案。Phase 4 前用基准确认布局占比，不以窗口化代替增量。

### 7.3 UIA

- 每个窗口的 UIA 树由该窗口快照与场景派生；发布时整体替换 window root，节点身份沿用 `NodeId`。**UIA 不消费 `PresentationDelta`**：delta 缺 parent/子序/旧值，不能替代相邻发布比较。
- 相邻两次发布按 provider-local runtime id 比较，投递结构/属性/焦点事件；顺序固定为结构 → 属性 → 焦点；后台窗口不投递焦点事件。结构事件规则见 §17.4。
- 写动作经窗口动作队列回到 UI 线程，重验后执行 **typed node command**（`click_node`/`change_node`/`replace_text_node`/`set_selection_node`/`focus_node`），不走 closest-wins；同一 FIFO 中的 `Scroll` 由宿主执行 applied-offset 路径。UIA 以可操作语义节点为 target；纯文本子节点不作为独立可操作控件。完整动作表见 §17.2。
- 滚动只改变宿主 applied offset 与场景平移，不重建快照、不改变 NodeId。
- UIA 树构建的成本必须可度量；首版允许 O(可见节点) 构建 + 相邻发布比较，之后按基线决定是否持久化。不得为了“增量”引入第二棵可修改界面树。

### 7.4 绘制调度

- 宿主只绘制有 `tree.revision` 变化、`env_generation`/`InteractionPaths.generation` 变化、damage 或动画的窗口。
- 空闲窗口停帧；滚动/悬停/按压只重建场景的瞬态部分（或按 `SceneEnv`/`InteractionPaths` 重绘），不进入 runtime。
- 系统偏好/DPI/外观变化按 §15.2 标记 scene dirty 并重绘；文本缩放/高对比度/DPI 都不 bump `tree.revision`。文本缩放与 DPI 重建布局、shaping、行带与 UIA bounds；高对比度只重建调色板/场景/UIA bounds，不重排布局。
- 焦点/caret/IME 变化按 §15.3 处理 reveal；显式滚动清除待决显露。
- 设备丢失、surface 重建走现有恢复路径；派生快照与场景在设备恢复后仍可复用，但按 ADR-0017 的最新快照重建场景，不承诺旧场景缓存跨设备代数复用。
- damage 区域、delta 长度、重建快照节点数、relaid 节点数是可观测计数器；绘制优化以这些计数为准，不以平均帧时间掩盖最坏情况。

## 8. 开发者体验

### 8.1 语法

以下使用目标语法；`WriteOp::finish`、handler 返回 `Result`、数据位置闭包、`Read<T>` 等属于本方案的新增面，当前实现尚未全部具备。当前 [视图语法参考](../SDK/视图语法参考.md) 记录的是现有语法；Phase 2/3 落地时同步修订其中的值位、闭包和事件规则，并补 compile-fail 用例。

```rust
#[component]
fn TodoItem(row: RowView<TodoRow>, todos: Store<TodoRow>) -> MountResult<MountPlan> {
    let todo = row.id();                          // RowId，行身份；不是业务 key
    let title = row.get().title.clone();          // 挂载快照
    let completed = row.field::<bool>(TodoField::Completed); // Field<bool>，响应式
    let editing = signal(String::new());

    view! {
        <view role="listitem" on:click={|| select(todo)}>
            <checkbox
                checked={completed}
                aria:label={once(format!("Complete {title}"))}
                on:change={|event: &mut ChangeEvent| -> Result<(), WriteError> {
                    todos.set_completed(todo, event.proposed()).finish()?;
                    Ok(())
                }}
            />
            <text style:color={|| {
                if completed.get().is_ok_and(|done| done) {
                    Color::Role(ColorRole::TextMuted)
                } else {
                    Color::Role(ColorRole::TextDefault)
                }
            }}>
                {once(title.clone())}
            </text>
            <text-input
                value={editing}
                on:input={|event: &mut InputEvent| editing.set(event.value().to_owned())}
            />
            <button on:click={|| delete(todo)}>"Delete"</button>
        </view>
    }
}
```

- 数据位置写闭包就是隐式 memo；不需要先命名 memo。
- 事件处理器支持零参数或一参数；一参数拿到 `&mut ClickEvent`/`&mut KeyEvent` 等具体载荷，可 consume/prevent_default。零参数不能控制 flow。
- 处理器可以返回 `()`、`Result<(), E>` 或 `WriteOp<T>`；`Result::Err` 在 turn 边界上报并停止本事件剩余默认动作。含 `?` 的闭包必须显式写返回类型（如上例 `-> Result<(), WriteError>`）；`HandlerOutcome` 不能修复 Rust 的返回类型推断。
- 行点击写在容器上；最近的 handler 胜出，子元素自己的 handler 阻断穿透。行内按钮的 handler 已经阻断行，不需要再写 `consume()`；需要显式停止 capture/bubble 时才用。
- 需要多个祖先观察时使用 `on:click_capture` / `on:click_bubble`，规则见 §5.3。
- 共享或昂贵的派生值用 `memo(|| ...)` 命名一次，多个绑定共享。
- 数据位置的闭包是**位置语法**，不是按类型猜测：只在 §6.2 的位置表内降为 memo；`on:*`、factory、slot、组件 prop 不参与。这与[技术架构](技术架构.md)中“宏不根据表达式是不是闭包猜测数据语义”的现有写法冲突，按本方案修订为位置规则。

### 8.2 组件与 props

组件挂载一次；props 是挂载时值或 `Read<T>` handle。

```rust
#[component]
fn Label(text: Read<String>) -> MountResult<MountPlan> {
    view! { <text>{text}</text> }
}

// 静态：Read::Static
<Label text="Hi" />

// 动态：Read::Signal
<Label text={title} />

// 显式快照：Read::Once
<Label text={once(format!("{count} items"))} />
```

- `Read<T>` 统一接受字面量、`Once`、`Signal`、`Memo`、`Field`；组件作者不再为“静态/动态”写两个 prop。`Read::Field` 可能返回 `ReadFault`；组件用 `read_once()?`/`bind()`/`try_get()` 显式处理，不把 Missing 当默认值（§18.2/§18.3）。
- 回调 prop 是 `FnMut`/`FnMut(&mut ClickEvent)` 等具体载荷；捕获 handle，不捕获大值。
- 组件不因父组件刷新而重跑；需要子组件响应的数据必须通过 `Read<T>` handle 进入。
- 传非字面量的 `String`/`bool` 不是响应式 prop；它必须包成 `once(...)`，否则编译错误并提示。这样迁移自 Dioxus/React 的用户不会误以为 props 会自动更新。

### 8.3 状态与事务

- `signal(value)`、`memo(f)`、`Store` 字段、`Transaction`。
- `Read<T>` 用于绑定和 prop；`signal` 用于可写 UI 状态；`Store` 用于业务记录。不要把 Store 行复制成 Signal 再双向同步，那会造出第二套模型权威。
- `WriteOp::finish()` 是单操作提交的便捷入口，返回 `Result<T, WriteError>`；多操作使用 `Transaction::new().write(...).write(...).finish()`。
- handler 返回 `WriteOp<T>` 时由 `HandlerOutcome` 在当前 turn 执行，`T` 丢弃；需要新行身份时用 `.finish()`。
- 模型、UI、窗口、任务各自提交；不承诺跨域回滚。失败保留已提交的领域结果，按 typed error 上报。
- `read_once()` 只用于挂载快照；持续依赖用 `get()`/`try_get()`。

**泛型模型。** 当前 `Store`/`Filter`/`For` 仍是 Todo 专用形状；目标 SDK 必须提供 `Store<R: Row>`、`Field<T>`（erased handle：runtime + `FieldKey` + `PhantomData<T>`）、`Rows<R, F: FilterSpec<R>>`、`ForSource<R> { Store<R>, Read<RowSet> }`、`For<R, K>` 与 app 定义的 filter/key selector。`Row` 是 app 行数据的 trait（`type Key: RowKey; fn key(&self) -> Self::Key`），`RowId` 是 `{ slot, generation }` 的 arena 身份，业务 key 存在行数据中。**`For` 同时持有 store 句柄与行集**；key selector 接收 `&R`，item factory 接收 `RowView<R>`。事件与响应式架构不依赖 Todo 类型；通用行模型必须在 **Phase 1 开始前**定型，Todo 作为第一个实例化（`TodoRow`）；否则 Phase 1 的 `ForData`/行键会固化 Todo 形状，Phase 5 再改会造成破坏性迁移（§18.6/§20.1）。

### 8.4 错误与诊断

编译期：

- 未知事件名、class token、样式属性、非法 slot；
- 重复同类事件处理器（`view!` 字面量）；
- 不支持的属性/条件；
- 类型不匹配；
- 裸 `String`/`bool`/`.get()` 在数据位置：提示 `once(...)` 或传 handle；
- 闭包字面量出现在非糖位置（factory/slot/组件 prop）且类型不匹配；
- `Show`/`For` 缺少必需输入。

运行时开发模式：

- 非法阶段写入；
- 释放后使用 handle；
- 重复 key；
- 未声明 row-height 的 `For` 超过阈值；
- 交互控件没有处理器（默认警告，避免静默死区）；
- handler/memo/factory/cleanup panic；
- 未退订/未释放的代数计数异常；
- 全量刷新或全量布局被意外触发；
- `value` 绑定到 Memo 且有 `on:input`（equal-write 风险）；
- 绑定类型是 `Static`/`Once` 但在高频数据源旁（冻结风险提示）。

错误文本包含操作、节点/tag、阶段和可执行建议；不使用“未知错误”或静默默认值。

### 8.5 可观测性

计数器（每 runtime / 每 tree）：

```

memos_dirty, memos_recomputed, memos_changed, memos_poisoned, memos_orphan_skipped
bindings_dirty, bindings_evaluated, bindings_changed, binding_faults
nodes_mounted, nodes_unmounted, nodes_live, nodes_storage, nodes_pages
signals_live, signals_storage, memos_live, memos_storage
dep_entries_live, dep_entries_storage, consumer_edges_live, consumer_edges_storage, edge_pages
snapshot_nodes_rebuilt, snapshot_copy_bytes, snapshot_shared_chunks
delta_len, delta_applied, delta_gap_full_rebuilds, layout_nodes_relaid

env_generation, reveal_requests, reveal_passes, pointer_rehits, press_invalidations
rowset_bytes, rowset_shared_count, mounted_rows
```

开发模式提供：

- `ZENUI_TRACE=events,bindings,flush,layout,lineage` 结构化日志；
- “为什么更新”链：source 写入 → memo → binding → 节点 → 快照路径；
- “为什么没更新”：绑定类型（`Static`/`Once`/`Signal`/`Memo`/`Field`）、source、最后一次 revision、fault 状态、是否被 equal-write 抑制；
- 响应式图 DOT/JSON 转储；
- 快照 diff 与 delta；
- 内存高水位、页数、槽位分布；
- 基准结果与预算对照。

“为什么没更新”从 Phase 2 就提供最小版本，不推迟到完整 devtools。裸值冻结、Once、Memo equal-write 是这套模型的一号支持问题。

### 8.6 心智模型

文档必须用一页讲清：

1. handle 是身份，不是值；捕获 handle，不要捕获值；需要快照时写 `once(...)`。
2. 组件挂载一次；数据变化更新绑定，不重跑组件。
3. 数据位置的闭包是隐式 memo；共享派生用命名 `memo`。
4. 事件默认最近祖先；需要多个祖先用 capture/bubble；`consume` 停止传播和默认，`prevent_default` 只停默认。
5. 一个 turn 一次 flush；处理器写入立即可见，UI 在 turn 结束更新。
6. 指针 hover/press/scroll 是宿主瞬态，不进入业务状态。
7. `Read<T>` 是统一的读源；静态/动态/字段不再有三套规则。

### 8.7 自定义控件

自定义控件用组合实现，不引入第二套控件树：

- **结构**：一个根元素加子元素；外观用静态 class 与类型化 inline style。
- **状态**：局部 `signal` / `memo`；跨组件共享时传 `Read<T>`/Signal handle，不复制值。
- **焦点**：使用原生可聚焦 tag，或显式挂载 `on:focus`/`on:blur`；新增 `focusable` 语义属性供自定义控件声明键盘可聚焦性。`focus-within:` 覆盖组高亮。
- **键盘**：`on:keydown` 处理自定义键；默认动作只对 button/checkbox/text-input 等内建控件生效。
- **语义**：`role` 与 `aria:*` 映射到 UIA；自定义 Invoke 动作必须落到它的 `on:click`，没有处理器就没有 Invoke。
- **绘制**：普通元素加样式；复杂自绘走 content leaf，不复制第二套命中或事件树。
- **边界**：本阶段不引入 widget trait；控件目录稳定后再抽象，避免过早建立不完整协议。

### 8.8 常见任务

以下为目标语法：

| 目标 | 写法 |
|---|---|
| 按钮点击 | `<button on:click={\|\| save()}>"Save"</button>` |
| 行点击 | `<view on:click={\|\| select(row)}> ... </view>` |
| 行内删除不触发行 | `<button on:click={\|\| delete(row)}>`（按钮 handler 已阻断行） |
| 需要观察所有点击 | 在根容器写 `on:click_capture={\|e\| trace(e.target())}` |
| Escape 关闭 | 窗口级 `window.on_keydown` 或焦点容器 `on:keydown={\|e\| if e.key()==Key::Escape { close(); e.consume(); }}` |
| Enter 提交 | 表单内 text-input + `<button type="submit">`；keydown handler 可 consume |
| 受控输入 | `<text-input value={draft} on:input={\|e\| draft.set(e.value().to_owned())} />` |
| 派生文本 | `<text>{\|\| format!("{} left", remaining.get())}</text>` |
| 条件分支 | `<Show when={\|\| expanded.get()}> ... </Show>`，也接受 `Signal<bool>` |
| 窗口化列表 | `<For each={todos.rows(Filter::Active)} key={\|row\| row.id} row-height={32}> ... </For>`（`Rows` 自带 store；裸 `RowSet` 必须配 `store={todos}`） |
| 菜单命令 | `window.on_command("save", \|_\| save())?` |
| 拖放到窗口 | `WindowCtx::on_drop`；不是 `<view on:drop>` |
| 自定义控件可聚焦 | `<view role="button" focusable on:keydown={...}>` |
| 异步交付 | 在 task scope 中启动 worker；continuation 在 Delivery turn 写 Store/Signal |

## 9. 性能与验证

### 9.1 目标

不承诺未测量的绝对数字；以下是对实现的硬性方向要求：

- 空 Intent、Store 无变化写入：不重建快照、不重排布局、不分配新快照节点。
- 10k 行窗口化列表，单行字段变化：只求值该行相关绑定；不遍历全部行；UI/For 持久内存 O(窗口)，共享 `RowSet` O(总行数) 单列。
- 文本输入每个字符：只更新一个文本绑定与本地编辑状态；不重建整份快照。
- 滚动未跨行：runtime 零工作；场景只应用偏移与 `env_generation`。
- 滚动跨行：一次结构 turn，最多两次场景构建。
- 多窗口：未变化窗口零快照/零布局/零绘制。
- 主题切换：所有窗口重建场景/调色板并重绘；没有外观订阅者但使用 `dark:` 的窗口也必须重绘；不重建业务快照中未变化的部分。
- 文本缩放/DPI 切换：重建场景/布局/shaping/行带/UIA bounds，不 bump `tree.revision`，不重建业务快照。
- 高对比度切换：重建调色板/场景/UIA bounds，不重排布局，不 bump `tree.revision`。
- 焦点/caret/IME 变化：宿主按两遍 reveal 处理；显式滚动清除待决显露。
- UIA 发布：整树构建 + 相邻发布比较；不把 delta 当 UIA 事件来源。
- 所有默认路径没有 `BTreeSet`/全树集合的每次写入克隆。
- 每次 turn 的分配次数、快照复制字节、delta 长度、relaid 节点数、binding 求值数有计数门禁，不只测平均时间。

### 9.2 基准

固定工作负载，输出计数与时间：

- `intent_noop`：空 click、Store 无变化写入。
- `signal_equal_write`：一个被 10k 行直接绑定的 Signal 的相等写入（只应触达 write-epoch 观察者，通常 0 或 1 个，不是 10k 个绑定；仍不是 O(1)）。
- `typing_10k`：10k 行窗口化列表中的连续输入。
- `toggle_row_10k`：单行完成状态切换。
- `filter_churn_10k`：反复切换过滤，记录瞬时分配与 RowSet 比较成本。
- `scroll_10k`：滚动跨行与未跨行。
- `multi_window_3`：三窗口共享状态，验证未变化窗口根指针不变。
- `theme_switch`：外观切换。
- `siblings_1k`：1k 平级兄弟中改一个，记录 children 复制字节与布局节点数。
- `reveal_10k`：Tab/点击 caret 在窗口化列表中的显露，记录 reveal_passes 与 scene_builds。
- `env_switch`：文本缩放/高对比度/DPI 切换，记录 snapshot_rebuilt、layout_nodes_relaid、revision 变化。
- `delta_apply`：连续 delta、断档回退、隐藏后 show 的全量重建。
- `uia_publish`：整树构建与相邻发布事件数。
- `memory_soak`：长时间随机交互后的 live/storage/pages/dep_entries/consumer_edges 高水位，并分别报告 mounted nodes、For 簿记、RowSet 字节。

CI 记录趋势；硬阈值必须放在固定 runner、基线文件与 `perf` job 中，不以开发机数字作为产品承诺（§20.3）。

### 9.3 正确性门禁

1. **独立差分快照**：每个 turn 后，绕过 binding/attr 缓存，从每个已挂载 `Read` 源重新求值、重算全部 memo，生成参考快照与参考绑定值，与增量结果规范化后逐节点比较；不相同即失败。参考实现不能复用生产缓存，否则漏标脏会被同样复制（§20.4）。
2. **随机事件序列**：确定性 RNG 生成点击、输入、焦点、滚动、过滤、窗口操作；与独立参考状态机比较可见状态、焦点、caret/selection、行身份。
3. **生命周期**：stale NodeId、旧 activation、关闭挂起、隐藏窗口、owner 释放、任务迟到、panic 后继续派发。
4. **文本编辑**：equal-write settlement、stale settlement、外部替换、组合取消、undo/redo、剪贴板；每个 turn 的 lineage observe 不论 value binding 是否脏。
5. **结构**：Show/For 预挂载失败、重复 key、factory panic、cleanup panic 后旧结构保持不变；焦点不跨行窗口接任。
6. **响应式**：三级 memo 链、菱形共享、共享 memo 跨窗口、source 槽复用后旧 deps 不进新源、equal write 只标脏 write-epoch 观察者、delete+reinsert same key 不复用旧行身份。
7. **内存**：反复挂载/卸载/滚动/过滤后，live/storage/pages/dep_entries/consumer_edges 有界；`size_of` 预算测试；soak 高水位不随历史增长；RowSet 字节单列。
8. **环境/显露**：文本缩放/高对比度/DPI 不 bump revision 但重建场景；reveal 最多两遍；显式滚动清除；指针重命中与 press 失效。
9. **UIA**：整树发布 + 相邻比较的结构/属性/焦点事件；SetSelection 不派发 on:input；Scroll 只改 applied offset。
10. **可见 Windows 验收**：真实 IME、焦点、hover/press、DPI、UIA、菜单、托盘、拖放、多窗口、系统偏好、窗口化 For；headless 只作为部分证据。逐 Phase 矩阵见 §20.5。

### 9.4 反例测试

必须覆盖：

- 空 click 不 bump revision；
- 相等 Signal 写入不重建快照，但文本编辑器能观察到写入；
- 10k 行共享 Signal 的相等写入不拉入 10k 绑定；
- 行点击命中子文本，最近祖先处理器运行；
- 行内按钮有自己的处理器时不触发行处理器；
- 无处理器的交互控件阻断穿透并产生开发警告；
- 禁用按钮不激活也不穿透；
- `consume` 的 Enter 不提交表单；`type=submit` 的按钮恰好提交一次；
- click 的 handler Err 停止后续默认，写入保留；
- handler/memo/factory/cleanup panic 后 runtime 可继续；
- 重复同类处理器在编译期（view!）或挂载期（MountPlan）被拒绝；
- 10k 行滚动后 `signals_storage` / `memos_storage` / `nodes_pages` / `dep_ids_live` 有界；
- 多窗口只有一个窗口变化时，另一个窗口的 snapshot 根指针不变；
- 隐藏窗口共享写入后 show 前 flush，外部替换清除历史；
- 组合取消在挂起/禁用父窗口仍可用；
- 指针点击 text-input 聚焦并放置 caret；点击 button/checkbox 聚焦行为一致；
- 过滤/重排/滚动/行窗口卸载后 hover/active 不残留，press 目标失效时取消；
- 文本缩放切换不 bump revision 但重建场景/布局/shaping/行带/UIA bounds；高对比度切换只重建调色板/场景/UIA bounds，不重排布局；
- 删除后同业务 key 重建行不复用旧 Field/For 状态；
- UIA SetSelection 不派发 on:input，UIA Scroll 不改快照；
- delta 断档回退到最新根后仍与独立参考一致；
- handler 返回 Err/panic 后默认动作不执行，flush 仍完成。

## 10. 迁移计划

不要求一次交付；每一阶段都可以独立验证和回滚。方向不变，阶段只控制风险。

### Phase 0：正确性与止血

- 所有用户处理器边界加 panic containment；所有 scope 恢复改 RAII guard（`refresh_tree_once` 的 take/put、`with_owner`、component setup）。
- 元素缓存所属 tree；派发/焦点/可见性 O(1)，删除全树扫描。
- Field 读取走 key 索引，O(log n) 或 O(1)。
- 宿主输入路径使用 revision 缓存的语义查询，不在每次击键重建快照。
- 删除 `refresh_for` 末尾对每个已挂载行的无条件刷新；`settle_focus` 每轮只刷受影响的 tree。
- 反向依赖边去掉每次 bump 的整集合克隆。
- 释放时清 Signal value、清 Memo deps 并从反向表移除；增加 live/storage 计数器。槽位代际复用与回收在 Phase 1 完成。
- **change tracking 前置**：refresh 返回 changed/patch，或先做最小脏集合；否则“空 click 不 bump”无法验收。
- `SubmitEvent` 保留 `EventFlow::prevent_default`，但明确它是 documented no-op；测试只覆盖 `consume`。`KeyEvent::consume` 实现；重复同类处理器编译期/挂载期拒绝；文档与代码的 consume 差异修正。
- 全局 `presentation_revision` 不再混入 core counters；per-tree revision 骨架。
- 计数器与 trace 骨架；Phase 0 退出前补 `KeyEvent::consume` 的 compile/pass 测试。

**退出**：现有测试全绿；panic 后可恢复；空 click 不 bump（含 Store 无变化写入不推高 revision）；churn 后 value/deps/反向边不累积；storage 基线记录（槽位复用待 Phase 1）。

### Phase 1：统一 NodeArena 与代际 arena

- **通用行模型设计门禁**：`Row`/`RowId`/`FieldId`/`FilterId`/`Store<R>`/`Rows<R,F>`/`ForSource<R>`/`For<R,K>` 先定型；Todo 作为第一个实例化（§20.1）。
- 元素、文本、组件、Show、For 进入统一 arena；父子兄弟链；NodeRef/NodeId/PresentationKey。
- `TreeKey=u32`、`DirtyFlags=u8`、`NodeSlot=64B` 固定布局；`PresentationKey` 由 `NodeRef` 派生。
- Signal/Memo/事件槽使用 generation + paged arena；释放清值并退订。
- Owner 公开 + `OwnerRef` generation；普通元素不再各自创建 owner；事件槽、绑定引用、owner 资源映射迁移。
- 反向边改 `DepEntry` + `EdgeArena`；空依赖 8 B。
- 挂载、刷新、卸载、焦点遍历、结构重排迁移。
- 行为保持不变；内存预算测试。

## 11. 被否决的方向

| 方向 | 否决理由 |
|---|---|
| VDOM / 组件反复执行 | 丢失挂载身份、本地编辑状态和 Owner 生命周期；与愿景冲突 |
| 完整 DOM 式默认冒泡 | 行点击与行内按钮容易双重执行；用户必须处处 `stop_propagation`；closest-wins 已覆盖常见组合 |
| 跨域 turn journal / ChangeSet 回滚 | 窗口、文件、GPU、外部服务不可回滚；回滚承诺只能是局部的，容易误导 |
| 为每个静态槽建堆绑定节点 | 静态槽只有一个来源，`ConsumerRef` + 元素缓存已足够；堆节点只增加内存和分配 |
| 动态依赖追踪用于静态槽 | 静态槽的依赖在挂载时已知；动态追踪只属于 memo |
| 快照作为可变第二棵界面树 | 违反单一权威；只允许不可变、可丢弃、结构共享的派生缓存 |
| 永远全量重建场景 | 隐藏 O(N) 成本；窗口化只是缓解，不是增量方案 |
| 全局 presentation revision | 一个窗口变化导致所有窗口重建；必须 per-tree |
| `BTreeSet` 反向边每次克隆 | 每次写入的隐藏分配；改为 `DepEntry` + 扁平 `EdgeArena` |
| 全量 `For` key→row 映射常驻 | 10k 行常驻内存不随窗口收敛；改为瞬时校验 + O(窗口) 持久 |
| 静态值隐式接受 `String`/`bool` | 能编译但永远不更新；改为字面量/`Once`/handle，裸值编译错误 |
| 两个名字指同一派生机制（memo/computed） | 用户无法判断何时用哪个；只保留 `memo`，数据位置闭包是隐式 memo |
| 全局事件总线 / 字符串自定义事件 | 失去类型与所有权；用回调 prop、Read/memo 和命令 id |
| 浏览器式 submit 默认 | 桌面没有导航语义；`type=submit`/Enter 显式定义，`prevent_default` 在 submit 上保留为 documented no-op |
| UIA 写动作走 closest-wins Intent | 会改变 SetSelection/SetValue/Scroll 语义；UIA 用 typed node command |
| 把系统偏好快照化进 presentation revision | 会迫使文本缩放/高对比度重建业务快照；用 `env_generation` |
| 每个 Dep 一个 `SmallVec<[ConsumerRef;4]>` | 空容器 72 B/行；用 `DepEntry` + 边 arena |

## 12. 需要新增或修订的 ADR

**新增：**

- **ADR-0023：响应式绑定图与通用行身份。** `ReactiveValue`/`MemoCompute`、`BindingSlot`/`BindingPart`/`BindingPatch`、`RowId`/`FieldKey`、`ChangeSet`/`FilterSpec`/候选投影、flush 顺序、liveness、lineage observe。

- **ADR-0027：响应式/事件/绑定的代际 arena 与订阅释放。** Signal/Memo/事件/绑定/OwnerRef 的 generation、`DepEntry`+`EdgeArena`、页粒度预算、DepId generation。

- **ADR-0005：** 固定 `perf-windows` runner、`bench/baselines/*.json`、Phase 验收矩阵与可见 Windows 证据归属。
- **ADR-0006：** `SceneEnv` 保持 `Copy + Eq`；`InteractionPaths`；hover/press/focus 路径；`focus-visible` 键盘 modality；每次场景构建前重命中；press 失效；外观进入快照；高对比度只换调色板、不重排布局。
- **ADR-0010：** 显露两遍协议、`reveal_requested`、显式滚动清除、行窗口结构 turn；**reveal 与 window sync 的顺序及每帧 scene-build 预算**；滚动仍不进入 runtime。
- **ADR-0011：** `RowSet` 承担 full keyed order（顺序 = Store 当前 order）；For 持有 `ForSource<R>` 与持久簿记 `(RowId, row_index, NodeRef)` O(窗口)；行身份带 generation；焦点 grace；**window sync 与 reveal 的先后**。

- **ADR-0014：** Ctrl+Z/Y 属于 L1 不可路由保留键；编辑键在 L4。
- **ADR-0015：** Ctrl+C/X/V 属于 L1；粘贴走同一插入 reducer。
- **ADR-0016：** Drop 只属于窗口 activation，不是元素事件；panic 边界与隐藏/挂起规则。
- **ADR-0019：** `value` 绑定为 Signal/Memo 的 equal-write；pending edit 每 turn observe；Field fault 策略。

## 13. 代码组织与边界

目标模块（名称可调整，职责边界不变）：

```
src/
  reactive/      Signal / Memo、ReactiveValue/MemoCompute、MemoDepsArena、DepId、DepEntry/EdgeArena、求值栈、dirty worklist、lineage
  node/          NodeArena、NodeRef/NodeId/PresentationKey、ElementData/AuxArenas、TextData/ShowData/ForData、OwnerRef
  event/         Intent/UiAction/ProviderAction、ActivationId、payload、routing、默认动作、turn 队列、TurnReport/HandlerOutcome、WindowHandlers
  runtime/       lifecycle、window/session/task、focus settlement、flush 编排、Structure turn、reveal 上报
  presentation/  PresentationSnapshot、SnapshotRoot/SnapshotNode::Element/Text、PresentationDelta、persistent children、per-tree revision、EnvGeneration
  view.rs        MountPlan、Read<T>/Once、BindingPart/ReadSlot、BindingTable/BindingRef/BindingList、ForSource<R>/RowView<R>/For<R,K>
crates/
  macro/         view! 展开；位置规则；arity/HandlerOutcome adapter；不依赖 runtime 内部
  core/          模型、Store<R>、Rows<R,F>、RowSetData、FilterSpec、事务；不依赖 UI runtime/Read
  render/        快照 → 布局/场景/绘制；只依赖公开呈现类型；SceneEnv Copy + InteractionPaths
  windows/       原生输入 → Intent、宿主瞬态/环境、重命中/reveal、UIA ProviderAction queue；不依赖响应式图
  style/         类型化样式
  demo/          真实应用
```

依赖方向：

```
windows ──► render ──► presentation types ──► runtime public types
runtime ──► core
macro/view ──► runtime public types
```

- runtime 不依赖 render 或 windows；render 只依赖公开快照/`PresentationKey`，不读取 runtime 内部。
- 快照类型可以暂时留在 SDK 的 `presentation` 模块；如果依赖边界变模糊，拆成 `zenui-presentation` 类型 crate，由 runtime 与 render 共同依赖。
- 内部允许引入 `smallvec` 作为小集合存储；它不进入公共 API。若坚持零新增依赖，第一版可以用 `Vec` 落地，预算按 SmallVec 目标记。
- `src/runtime.rs` 当前是单文件；Phase 1/2 按节点、事件、响应式、窗口、任务、快照拆分，禁止继续扩张成 god file。
- 每个 Phase 用 feature flag 或独立分支落地；测试按行为分组，不按实现文件分组。

## 附录 A：当前实现差距

以下用函数/模块名定位；实现时以最新代码为准。

| 问题 | 位置 | 影响 | 处理 |
|---|---|---|---|
| `click_node`/`change_node`/`submit_node`/`keydown_node` 直接调用 handler，无 panic containment | `runtime` 派发函数 | panic 后事件槽永久为 `None`、phase 停在 Event，控件静默失效 | 统一为 `take → catch_unwind → put → resume/上报` |

| `MountedElement` 内联 attrs/class styles/inline styles/events；无 `BindingTable`/`AuxArenas` | `runtime::MountedElement`/`MountedInlineStyle` | 与 `ElementData≤96 B`、`BindingSlot` 唯一权威冲突，Phase 1 预算无法通过 | §4.1/§18.3/§19.7 的外部 arena 与 BindingTable |

两套响应式机制（SDK Signal/Memo 与 core MemoGraph）和两套 Owner 结构（SDK `OwnerRecord` 与 core `OwnerTree`）是历史分层的产物。本方案不要求立即合并；Phase 1/2 先把 SDK 层的身份、订阅和释放做对，合并作为后续独立评估。

## 附录 B：事件路由速查

```
Click:
  hit → deepest node
    ├─ 自身有 Click handler → 运行
    ├─ 祖先有 Click handler → 最近祖先运行
    └─ 遇到交互控件（含禁用）→ 停止，不穿透

Click capture/bubble（显式）:
  hit:     命中测试后归一化的最深元素
  normal:  hit → 根最近一个有普通 handler 的节点；没有则 None
  capture: 根 → hit，只运行 *_capture
  target:  normal 有值时运行其普通 handler 一次
  bubble:  hit 父 → 根，只运行 *_bubble
  consume(): 停止后续阶段与默认动作
  prevent_default(): 只跳过默认动作
  disabled/祖先禁用: 整次不派发；交互控件无 handler: 只阻断普通 handler 穿透

KeyDown:
  hit = focused node（无焦点 = 窗口根）；normal = closest 祖先/窗口 fallback
  优先级：L0 IME → L1 Ctrl+A/Z/Y/C/X/V → L2 accelerator
          → L3 keydown → L4 控件默认 → L5 宿主默认

Focus/Blur/Input/Change/Composition:
  直接目标，不冒泡；CompositionCancel 在挂起/禁用窗口仍可用

Command:
  window handler → app handler（Tray 只走 app）；target 带 activation

Drop:
  只属于窗口 activation（WindowCtx::on_drop）；不是元素事件

UIA:
  Invoke/Toggle/ReplaceValue/SetSelection/SetFocus → typed node command
  Scroll → 宿主 applied offset
  不走 closest-wins；整树发布 + 相邻发布比较
  以可操作语义节点为 target；纯文本子节点不伪装成独立控件

Press / Reveal:
  Press: 焦点转移 + text-input caret（runtime 默认）
  Reveal: runtime 上报 RevealFlags；宿主两遍协议；显式滚动清除
```

## 附录 C：术语

- **Intent**：宿主归一化后的**用户输入**语义，带 source、target 和类型化 payload。
- **UiAction**：UIA provider 产生的 typed node command；不走 closest-wins，与 Intent 共享 turn/flush/校验。
- **TurnOutcome**：一次派发返回给宿主的 consumed/prevent_default 结果，用于原生默认动作。
- **TurnReport**：一次 turn 的 `TurnOutcome + errors + RevealFlags`；同步入口返回它，不静默丢错。
- **HandlerOutcome**：事件槽返回的 `Ok`/`Err`；承载 Result/WriteOp 适配与默认动作停止语义。
- **turn**：一次输入或交付的提交单位；写入立即可见，结束统一 flush。
- **ConsumerRef**：绑定、结构节点或 memo 在反向依赖表中的打包引用。
- **DepEntry / EdgeArena**：反向依赖的紧凑存储；空 Dep 8 B，边 16 B，不用每 Dep 的 SmallVec。
- **Read<T>**：统一读源，覆盖字面量/Once/Signal/Memo/Field；Field 可失败。
- **BindingPart / BindingPatch**：绑定槽的稳定 part 判别式与一次 flush 的值/结构补丁。
- **memo**：唯一公开派生构造；数据位置闭包是隐式 memo。
- **closest-wins**：目标没有处理器时沿父链运行最近一个有处理器的祖先，只运行一个。
- **effective change**：任何影响快照可见结果的改变；只有它推进 tree revision。
- **env_generation**：宿主呈现环境（系统偏好/DPI/滚动等）的代际；不推进 tree revision，但使场景缓存失效。
- **InteractionPaths**：hover/press/focus 路径；独立于 `SceneEnv`，不进入快照。
- **PresentationKey**：公开、opaque 的呈现节点身份（NodeRef 编码）；renderer 用它做布局/绘制缓存键。
- **PresentationDelta**：一次提交中变化的节点集合，只供 renderer 增量消费；UIA 不消费。
- **持久化快照**：不可变、结构共享的派生快照，不是第二棵可修改界面树。

### 15. 宿主呈现环境、显露与指针瞬态

#### 15.1 三层环境值

宿主环境拆成三层，避免把逐帧瞬态混进快照 revision，也避免把持久环境值误当业务状态：

```rust
/// 宿主拥有、随窗口 activation 持续的呈现环境；Copy + Eq。
/// 不进入 presentation snapshot，不进入响应式图。
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct SceneEnv {
    hovered: Option<NodeId>,    // 最深命中元素；驱动内建 hover 视觉
    pressed: Option<NodeId>,    // press target；驱动内建 pressed 视觉
    focus_visible: bool,        // 键盘 modality；ADR-0006
    scroll_offset: i32,         // applied scroll offset，ADR-0010
    text_scale_percent: u16,    // 100–225；ADR-0022
    high_contrast: bool,        // 系统高对比度开关
}

/// 逐帧交互路径；由宿主从最后一次命中重建。
/// 用 Arc<[NodeId]> 避免每次场景构建复制整条路径。
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct InteractionPaths {
    pub hover_path: Arc<[NodeId]>,   // 最深命中节点 → 根
    pub press_path: Arc<[NodeId]>,   // press target → 根
    pub focus_path: Arc<[NodeId]>,   // 焦点节点 → 根
    pub generation: u64,             // 路径变化时递增
}

/// 每个窗口一个；任一宿主环境输入变化时递增。
/// 快照 revision 不变时，场景缓存仍必须因 env_generation 失效。
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct EnvGeneration(pub u64);
```

约束：

- `SceneEnv` 必须保持 `Copy + Eq`。**不得**为了携带路径把它改成 `Clone`；路径在 `InteractionPaths` 中按引用传入。目标 API 同时提供三个入口：`Scene::build(snapshot, viewport)`（便利、默认环境）、`Scene::build_with(snapshot, viewport, env, paths)`（无缓存）、`Scene::build_cached(snapshot, viewport, env, paths, &mut SceneCache)`（宿主路径）。`window_scale` 属于 `Viewport`，不在 `SceneEnv` 中重复；DPI 变化使该窗口 `env_generation += 1` 并重建 `Viewport`。
- `SceneEnv.hovered/pressed` 是 `InteractionPaths` 的派生值，只驱动内建 hover/pressed 视觉；`hover:`/`active:` 条件一律读 `InteractionPaths`，不读单个 NodeId。焦点 modality（`focus_visible`）变化必须使 `env_generation += 1`，否则键盘/鼠标切换会复用旧场景。
- `SceneEnv` 的 `appearance` 不在这里：外观是已提交应用状态，进入快照（ADR-0006）。高对比度是宿主调色板覆盖，不进入快照；它通过 `high_contrast` 与宿主 `HighContrastColors` 影响 `RenderPalette`。
- `InteractionPaths` 可以在一次场景构建内被多个节点共享；不进入快照、不进入响应式图、不产生 `on:hover` 业务事件。
- `EnvGeneration` 每个窗口独立；窗口目录、隐藏窗口和多窗口各自维护。它不是 `tree.revision`，也不得被业务代码读取为状态。

#### 15.2 环境变化的失效规则

| 输入 | 变化来源 | 是否进入快照 | 失效范围 |
|---|---|---|---|
| 应用外观 `Appearance` | 应用通过 `Runtime::set_appearance` 写应用 owner | 是（`SnapshotRoot.appearance`） | 所有 window tree 标脏；各自 `revision += 1`；重绘 |
| 系统高对比度 | 宿主采样 `SPI_GETHIGHCONTRAST` / `WM_SETTINGCHANGE` | 否 | 所有窗口 `env_generation += 1`；重建调色板/场景/UIA bounds；**不重排布局**；仍重绘 |
| 辅助功能文本缩放 | 宿主采样 `TextScaleFactor` | 否 | 所有窗口 `env_generation += 1`；重建场景、**布局**、文本 shaping、行带、UIA bounds；保留焦点/caret/编辑值；夹取 applied offset；**不改变 `tree.revision`** |
| DPI / window scale | `WM_DPICHANGED`、窗口创建 | 否 | 该窗口 `env_generation += 1`；重建 `Viewport`/场景/布局；不改变快照 |
| 滚动偏移 | 滚轮/翻页/滚动条/UIA Scroll | 否 | 该窗口 `env_generation += 1`；只平移场景；不重建快照；跨行时另起结构 turn（§15.5） |
| hover/press/focus 路径 | 指针、焦点、捕获 | 否 | 该窗口 `InteractionPaths.generation += 1`；重新解析样式；布局属性变化时标布局脏 |
| 焦点 modality（focus_visible） | 键盘/指针切换 | 否 | 该窗口 `env_generation += 1`；重建场景（焦点环/条件） |
| 设备丢失/恢复 | renderer | 否 | GPU 资源重建；快照与场景缓存可复用；见 ADR-0017 |

**外观写入。** `Runtime::set_appearance(appearance)` 是宿主/应用命令入口，必须在 turn 边界调用，或在 `WindowCtx` 命令处理器中排队。它把 `Appearance` source 标脏，把所有 tree 放入 `dirty_trees`；每个 tree 在 flush 时更新 `SnapshotRoot.appearance` 并 bump `revision`。没有外观订阅者的窗口也必须重建，因为 `dark:` 是场景条件。不得把外观变化降级为“只影响订阅外观的 binding”。

**环境代际与场景缓存。** 场景/布局/文本 shaping 的缓存键至少是：

```
scene_key = (tree_key, snapshot.revision, env_generation, interaction_paths.generation)
```

`snapshot.revision` 只在已提交界面有效变化时推进；`env_generation` 在系统偏好/DPI/滚动/焦点 modality 等宿主环境变化时推进；`interaction_paths.generation` 在 hover/press/focus 路径变化时推进。外观单独走快照 revision（因为 `appearance` 在快照里）。三者独立，避免“主题切换重建业务快照”或“滚动推进 revision”。

#### 15.3 焦点、caret 与 IME 显露

`RevealFlags` 由 runtime 在 turn 结算时产出，宿主消费：

```rust
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub struct RevealFlags {
    pub focus_changed: bool,
    pub caret_changed: bool,
    pub composition_changed: bool,
}
```

宿主协议（ADR-0010 的增量版本）：

1. runtime 只做焦点结算、caret/selection 更新、composition 状态更新；**不直接改 applied scroll offset**。
2. 宿主在 turn 结束后收到 `RevealFlags`；若有任一位置变化且没有显式滚动，置 `reveal_requested = true`。
3. 下一次场景构建后，按以下顺序处理显露：
   - 若焦点节点有 caret 几何，用 caret rect；否则用焦点元素边框盒；
   - 把目标 rect 与视口比较，夹取 `scroll_offset`；
   - 若偏移变化，重建场景一次；
   - 首遍使用边框盒且重建后出现 caret rect 且与边框盒不同，再夹取并重建一次；**最多两遍**；
   - 超高元素顶部优先；剩余越界接受并记录诊断。
4. 显式滚轮、翻页、滚动条拖动、UIA Scroll 清除 `reveal_requested`；显式滚动不触发展露。
5. 行窗口变化：若显露目标行不在当前窗口，宿主先按 §15.5 发起结构 turn 扩大窗口，再执行显露；结构 turn 与显露合计的 scene build 仍受“每帧最多两次”的预算约束（首遍算行带、结构 turn 后第二遍算 caret；超过则下一帧继续）。
6. IME 候选窗：每次场景构建后按翻译后的 caret/preedit 重锚；目标完全离屏时隐藏候选窗；组合取消/提交后清除锚点。

**不得**在焦点 handler 内直接改滚动偏移；**不得**在绘制阶段运行用户代码或结构刷新。

#### 15.4 指针瞬态与重命中

宿主必须保存**逻辑指针位置**，而不是只保存上一次命中的 `NodeId`。协议：

1. 每次场景构建前、每次指针输入派发前、每次 UIA 动作前，用当前场景对最后指针位置重新命中。
2. 命中结果按以下顺序归一化：文本节点上溯到最近元素；`Show`/`For`/组件透明；跳过 `role="spacer"`。
3. 校验 `NodeId` 的 runtime、slot、generation、tree、窗口可见性、关闭挂起和祖先 disabled；失败则视为无命中。
4. 命中变化时重建 `hover_path`；`InteractionPaths.generation += 1`。
5. `press` 是 capture-based 的，不因滚动重新评估；但以下任一情况立即清除 press 与 capture：
   - 捕获丢失（`WM_CAPTURECHANGED`）；
   - 焦点丢失；
   - 窗口隐藏、关闭、失活；
   - press target 在最新场景中不存在、已卸载、被禁用或不在同一 tree；
   - 行窗口卸载。
6. 滚动后只重命中 hover，不清除 press；hover 变化导致布局属性变化时，场景必须再构建一次（ADR-0010 的 hover-after-scroll 预算）。
7. `hover:`/`active:` 条件对路径内任意元素成立；`focus-visible:` 只在宿主最近输入来源是键盘时成立；`focus-within:` 对焦点路径内祖先成立。`focus-visible` 不得简化为“焦点节点恒真”。

#### 15.5 行窗口：结构 turn，而不是场景构建中的副作用

滚动跨行时的顺序固定为：

```
宿主滚动输入（不进入 runtime）
  → 更新 applied offset（env_generation += 1）
  → 场景构建 pass 1（当前快照，仅用于行带几何）
  → 计算目标 (first, count)
  → 若任一 band 的窗口变化：
        Runtime::set_row_windows(window, &[(BandKey, RowWindow)])   // 一个结构 turn，原子
        - Phase::Structure
        - 预校验全部 band；预挂载/卸载行，运行行 factory
        - panic 边界；写入 gate；焦点结算；flush
        - 返回 Result<TurnReport, WindowError>
  → 场景构建 pass 2（新快照）
  → 绘制
```

约束：

- `set_row_windows`（以及单带便捷形式 `set_row_window`）**不得**在 `Scene::build`、`ensure_scene`、`render_snapshot` 的调用栈内运行用户 factory；宿主必须先返回，再发起结构 turn。
- 结构 turn 的用户代码只能读 Signal/Store，不能写；创建的资源挂到新行 owner。违反是 typed `StructureWriteRejected`。
- 结构 turn 推进 `tree.revision`；行窗口变化本身是 effective change。
- 每帧最多两次场景构建：pass 1 用于行带，pass 2 用于新窗口。若显露还需要一次，顺延到下一帧；不得在单帧内无界循环。
- 滚动未跨行：runtime 零工作；只更新 `SceneEnv.scroll_offset` 与 `env_generation`，一次场景构建。

宿主状态机必须显式，不能藏在 `ensure_scene` 里；pending 是**按 band 的集合**，不是单个 `Option<RowWindow>`：

```rust
type BandKey = PresentationKey; // For 结构节点的稳定身份；宿主从 SnapshotRoot.row_bands 取得
struct PendingRowWindows { bands: SmallVec<[(BandKey, RowWindow); 4]> }

enum RowWindowSync {
    Idle,
    Pass1 { pending: PendingRowWindows, scene: Arc<Scene> },
    Applying { pending: PendingRowWindows },
    Pass2 { pending: PendingRowWindows },
    Deferred,
}
```

1. `ensure_scene` 只做纯构建，返回 `(Arc<Scene>, Option<PendingRowWindows>)`；不调用 `set_row_windows`/`set_row_window`。
2. 消息循环在 `ensure_scene` 返回后、派发输入/绘制前处理 `PendingRowWindows`：
   - 无 pending：直接使用当前场景；
   - 有 pending 且所有 band 与当前窗口相同：清除 pending，直接使用；
   - 有任一 band 不同：进入 `Phase::Structure`，调用批量 `set_row_windows(window, &pending.bands)`；校验失败（`WindowError::Stale`/`WrongRuntime`）整批不应用，宿主继续用旧场景并报告；成功且 `TurnReport.changed` 则构建 pass 2，unchanged 则复用场景。
3. `render_snapshot` 发现 `PendingRowWindows` 时不得绘制旧行几何；设置 deferred paint，回到消息循环完成结构 turn 后再绘制。
4. 命中测试只在 pass 2 完成后使用新场景；输入不得落到旧行窗口的几何。
5. 每帧 `scene_builds` 计数包含 pass 1、pass 2 和 reveal 重建；超过 2 时，把 reveal 或绘制顺延到下一帧，并记录 `deferred_scene_builds`。
6. 行 factory panic/Err：结构 turn 保持旧窗口与旧行，panic 记录 `FactoryPanicked`、`Err` 记录 `FactoryFailed`；宿主继续使用旧场景，并在诊断中报告。
7. `TurnReport.changed` 为真当且仅当：任一行带挂载/卸载、行 spacer 高度变化、焦点被清除、组合被取消、或 tree revision 被推进。仅环境/偏移变化不算。

#### 15.6 验收

必须新增或重跑：

- 文本缩放在 100/150/225 下改变字号、行高、caret、命中、滚动范围、布局、行带与 UIA bounds，且 `tree.revision` 不变；
- 高对比度切换重绘所有窗口、更新调色板与 UIA bounds，但**不重排布局**；显式 `Color::Literal` 不被改写；
- 外观切换在没有 `Appearance` 订阅者、但使用 `dark:` 的窗口上也重绘；
- Tab 到视口外输入、点击放置 caret、IME 候选窗重锚、窗口化 For 中的显露；
- 过滤/重排/滚动/行窗口卸载后 hover/active 不残留，press 在目标失效时取消；
- 滚动未跨行 runtime 零工作，跨行恰好一次结构 turn、最多两次场景构建。

### 16. turn、处理器结果、错误与默认动作

#### 16.1 入口分类

运行时只有五类入口，共享 turn 队列、写入门、flush 与错误通道：

| 入口 | 来源 | 路由 | Phase | 备注 |
|---|---|---|---|---|
| `Intent` | 指针、键盘、IME、焦点、菜单、托盘、拖放 | direct/closest/capture-bubble | `Event` | 唯一**路由型**用户输入入口 |
| `HostTextInput` | `WM_CHAR` 可打印字符 | 已解析 text-input，不路由 | `Event` | 宿主默认 `type_text_node`；运行 `on:input` 并返回 `TurnReport`；不形成 `Intent` |
| `UiAction` | UIA provider 动作队列 | **node direct / window**，不路由 | `Event` | typed node command；见 §17 |
| `Delivery` | worker 完成 | 无路由 | `Delivery` | 一个批次一个 turn；见 §16.10 |
| `HostCommand` | `set_appearance`、`set_row_windows`、`show/hide/close` 结算 | 无路由 | `Command`/`Structure` | 宿主边界；不得在 flush 中间重入 |

`Intent` 是唯一**路由型**用户输入条目；`HostTextInput` 是宿主默认的已解析目标入口；`UiAction` 是 UIA 的 typed 条目，**不**冒充 Intent 的 closest-wins。它们共享目标校验、turn 队列、写入门、flush、panic 边界和错误报告。Part I §5.2 的“唯一用户输入入口”按此限定为“唯一路由型入口”。

#### 16.2 TurnReport、TurnOutcome 与错误

```rust
pub struct TurnReport {
    pub outcome: TurnOutcome,
    pub errors: SmallVec<[TurnError; 4]>,
    pub reveal: RevealFlags,
    pub changed: bool, // set_row_windows/set_appearance 等宿主命令的“是否改变”
}

#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub struct TurnOutcome {
    pub consumed: bool,
    pub prevent_default: bool,
}

pub enum DispatchError {
    UnknownNode, StaleNode, Hidden, Suspended, WrongKind, Reentrant,
    TargetClosed, BudgetExceeded,
}

pub enum TurnError {
    HandlerFailed(HandlerError),
    HandlerPanicked(PanicInfo),
    Reactive(ReactiveError),       // DuplicateKey / ComputedPanicked / GraphCycle / ...
    FactoryPanicked(PanicInfo),
    FactoryFailed(MountError),     // Show/For factory 返回 Err；拟议结构释放，旧结构保留
    CleanupPanicked(PanicInfo),
    StructureWriteRejected,
    FieldFault(FieldError),
    CloseConfirmationNotShown { window: ActivationId, key: String }, // Pending 但关闭 turn 内没有可见的确认窗口；epoch 按 Deny 结算
    BudgetExceeded(TurnBudget),
}
```

规则：

- `dispatch_intent` **与所有直接原语**（`click_node`/`change_node`/`replace_text_node`/`type_text_node`/`set_selection_node`/`focus_node`/`keydown_node`）返回 `Result<TurnReport, DispatchError>`；`TurnOutcome` 只表达 flow，不承载错误。
- handler 返回 `Err` 或 panic：写入保留，**停止本事件剩余 handler 与默认动作**（fail closed），flush 仍执行；错误进入 `TurnReport.errors`。宿主看到 `errors` 非空时不得执行原生默认动作。
- flush 期间的结构/绑定/焦点错误进入同一个 `TurnReport.errors`；它们不阻止其他 tree 的 flush。
- 宿主驱动入口：`set_row_windows(window: WindowCtx, bands: &[(BandKey, RowWindow)])` 返回 `Result<TurnReport, WindowError>`；`window` 提供 activation/owner/可见性/关闭挂起校验，并拒绝其他窗口的 `BandKey`（`WrongRuntime`/`Stale`）。批量原子——任一行带校验失败则整批不应用。`TurnReport.changed` 表示是否需要 pass 2：任一行带应用/卸载、焦点清除、组合取消或 revision 改变。`set_row_window` 是单带便捷形式，语义相同。`set_appearance`/`drive_tasks` 返回同构的 `TurnReport` 或批次报告；异步错误不得静默丢弃。
- `HandlerError` 是用户 handler 错误的擦除容器，至少提供 `From<WriteError>`、`From<ReactiveError>` 与消息；`IntoHandlerResult` 的 `Result<(), E>` impl 要求 `E: Into<HandlerError>`。
- `TurnBudget { handlers: 1024, window_requests: 64, structure_rounds: 8 }`；超限产生 `BudgetExceeded`，停止继续 drain，但已执行写入保留。

#### 16.3 HandlerOutcome 与事件槽

事件槽必须能携带 handler 结果；Part I §4.4 的槽签名已是 `Box<dyn FnMut(&mut Payload) -> HandlerOutcome>`，这里给出 `HandlerOutcome` 与适配规则：

```rust
pub enum HandlerOutcome {
    Ok,
    Err(HandlerError),
}

pub trait IntoHandlerResult {
    fn into_handler_outcome(self) -> HandlerOutcome;
}
impl IntoHandlerResult for () { ... }
impl<E: Into<HandlerError>> IntoHandlerResult for Result<(), E> { ... }
impl<T> IntoHandlerResult for WriteOp<T> { /* 立即执行，T 丢弃 */ }
```

槽位：

```rust
enum Event {
    Click(Box<dyn FnMut(&mut ClickEvent) -> HandlerOutcome>),
    // ... 所有变体同构
}
```

宏适配：

- 零参数 `|| expr`：包装为 `|_event: &mut Payload| HandlerOutcome::from(expr())`；零参数不能设置 flow。
- 一参数 `|event: &mut Payload| expr`：要求 `expr: IntoHandlerResult`；`Result` 必须显式标注返回类型，例如 `|event: &mut ChangeEvent| -> Result<(), WriteError> { ... }`。
- 命名函数按一参数处理；零参数命名函数写 `|| f()`。
- `WriteOp<T>` 在当前 turn 内执行一次；`T` 丢弃；需要返回值时在 handler 内 `.finish()`。
- 捕获/冒泡各阶段消费同一个 `HandlerOutcome`；`Err` 停止后续阶段与默认动作。

> 注：`?` 不能被 `IntoHandlerResult` 自动修复。闭包返回 `Result` 时必须写返回类型；这是 Rust 类型推断的限制，不是宏可绕过的。

#### 16.4 panic 策略与恢复

- 所有用户闭包入口使用 `catch_unwind(AssertUnwindSafe(...))`；要求构建使用 `panic = "unwind"`。`panic = "abort"` 下不承诺 containment，文档必须写明。
- 事件处理器 panic：恢复事件槽与 phase；保留 panic 前已设置的 `consume/prevent_default`；停止本事件剩余 handler 与默认动作；`TurnReport.errors` 记录 `HandlerPanicked`；runtime 继续处理后续 turn。
- `memo` compute panic：恢复 `computing`/phase；memo 标 `poisoned`；有最后已提交值时 `get` 返回最后值并报 typed fault；没有最后值时 `get` panic（同 owner 契约），`try_get` 返回 `ComputedPanicked`；组件可重挂载恢复。
- binding 求值 panic：只能来自用户 memo/Field；由 memo 边界处理；binding 保留最后值并记录 `FieldFault`/`ComputedPanicked`。
- Show/For factory panic：释放拟议 owner/fresh 行；保持旧结构；记录 `FactoryPanicked`。
- Show/For factory 返回 `Err`（`MountResult`）：不 panic；释放拟议 owner/fresh 行，保持旧结构；记录 `FactoryFailed`。`FactoryFailed` 与 `FactoryPanicked` 都只影响拟议结构，不回滚其他节点的 binding patch。
- cleanup panic：继续释放其余资源；记录 `CleanupPanicked`；不让 panic 穿过析构链。
- 窗口 factory、`on_close`、`on_drop`、`on_command`、`on_menu_state`、task continuation：全部纳入同一 panic 表；`on_menu_state` 在 `Phase::MenuState` 中运行，失败保持菜单原状。
- 所有 scope 恢复（`current_owner`、`phase`、`read_only`、`take_tree`）使用 RAII `Drop` guard；不得只在正常返回路径恢复。

#### 16.5 重入与直接 API

- `dispatch_intent` 在 handler 内再次调用时，把 Intent 放入当前 turn 的 FIFO 队列，返回 `Ok(TurnReport { .. })` 的“已排队”结果；不得同步重入同一 tree 的 flush。
- `click_node`/`change_node`/`replace_text_node`/`type_text_node`/`set_selection_node`/`focus_node`/`submit_node`/`keydown_node` 是**直接原语**：不回溯祖先、不执行 capture/bubble、不执行路由。它们执行目标节点的**本地默认**（checkbox 切换、文本整体替换/插入、selection、focus），但不执行表单/窗口默认（例如 `type=submit` 不提交）。它们只允许在 turn 外（宿主/UIA/测试）或 turn 边界调用；在 `Phase::Event/Delivery/Structure/Binding/Memo` 内调用返回 `DispatchError::Reentrant`。
- `activate_node` 是**路由原语**：等价于 `dispatch_intent(Intent { target: Node(node), payload: Activate, .. })`；需要 closest-wins、submit 或完整默认时用它。
- 直接原语也返回 `TurnReport`；事件槽 `take → catch_unwind → put` 必须在直接原语中使用；panic 后槽位不得永久为 `None`。
- 直接原语不执行 `type=submit` 等传播/表单默认；需要它们时使用 `activate_node` 或 `dispatch_intent`。UIA 的 Invoke/Toggle/ReplaceValue/SetSelection/SetFocus 正是“节点本地默认”的调用者。

#### 16.6 默认动作分层

每个默认动作必须标注执行者与时机：

| 事件/场景 | 默认动作 | 执行者 | 时机 | 可跳过 |
|---|---|---|---|---|
| 指针按下 | 焦点转移到可聚焦目标；text-input 放置 caret | runtime | turn 内，handler 之前或之后按 §16.8 | consume/prevent |
| 指针松开 | 运行 click；`type=submit` 且在 form 内提交 | runtime | turn 内，handler 之后 | consume/prevent |
| Enter | 组合确认；按钮/复选框激活；text-input 提交最近 form | runtime | turn 内，handler 之后 | consume/prevent |
| Space | 按钮/复选框激活 | runtime | turn 内，handler 之后 | consume/prevent |
| Escape | 组合取消；确认窗口 Deny；其他交给窗口默认 | runtime/宿主 | 组合在 handler 前；其余按 §16.7 | consume（组合/确认窗口除外） |
| Tab/Shift+Tab | 焦点遍历 | runtime | turn 内，handler 之后 | consume |
| PageUp/PageDown/Home/End | 文本输入内 caret 命令；否则滚动 | runtime/宿主 | turn 内 caret；宿主滚动 | consume/prevent |
| Backspace/Delete/方向键 | 文本编辑 reducer | runtime | turn 内，handler 之后 | consume/prevent |
| 可打印字符 | 文本插入（WM_CHAR）→ `type_text_node` | 宿主（内部 Event turn） | 收到 WM_CHAR 时 | consume/prevent + 抑制令牌 |
| 滚轮/滚动条 | applied offset | 宿主 | turn 外 | 不进入 runtime |
| 复选框 | 受控对齐 / 非受控本地切换 | runtime | turn 内，handler 之后 | consume/prevent |
| Submit | 运行 `on:submit` 一次 | runtime | turn 内 | consume；`prevent_default` 无对象 |

**关键修正：**

- Enter 提交与点击提交都接受 `consume` 与 `prevent_default`；Part I §5.5 已按本表给出同样的“可跳过”列。
- `SubmitEvent` 没有后续默认动作，`prevent_default` 在 submit 上无实际效果；需要停止后续处理时用 `consume`。这一点保持。
- 打印字符的插入是**宿主**默认，但通过 `type_text_node` 在 Event turn 内完成：它运行 `on:input`、返回 `TurnReport`、受 panic 边界与写入门约束；**不形成 `Input` intent**。宿主不得直接调用内部插入函数绕过 `TurnReport`。keydown 被 consume 时宿主必须跳过对应 WM_CHAR。
- 受控 checkbox 的 pending 应用与对齐都在 runtime turn 内、snapshot 之前完成；宿主不得在 flush 后再改本地值。

#### 16.7 键盘优先级与 WM_CHAR 抑制

固定顺序（从高到低）：

```
L0  IME 组合中的按键（不路由；组合取消例外）
L1  不可路由的编辑器保留快捷键：Ctrl+A / Ctrl+Z / Ctrl+Y / Ctrl+C / Ctrl+X / Ctrl+V
L2  已声明且启用的菜单 accelerator
L3  用户 keydown：capture → target（closest-wins）→ bubble
L4  runtime 控件默认：Backspace/Delete/方向键/Home/End 的编辑或 caret、Enter/Space 激活、
    Tab 焦点遍历、form 提交
L5  宿主默认：可打印字符 WM_CHAR → type_text_node、滚动、原生焦点遍历/激活
```

- L1 快捷键**不能**被 `on:keydown` 观察或消费；需要自定义时不要占用这些组合。
- Backspace/Delete/方向键/Home/End **不是** L1；它们在 L4，所以 `on:keydown` 可以先观察并 consume。Part I §5.5/§5.6 已按 L0–L5 修正。
- L2 accelerator 被声明后，不再作为节点 keydown 派发；L3 用户 handler consume 后，L4/L5 全部跳过。
- **WM_CHAR 抑制令牌**：宿主在 keydown turn 的 `TurnOutcome.consumed || prevent_default` 为真且按键是可打印字符时，记录 `CharSuppression { target, scan_code, key, modifiers }`；下一条匹配 target/scan_code 的 WM_CHAR 丢弃并清除令牌。下一次 keydown、焦点变化、窗口失活或 50 ms 内的无匹配 WM_CHAR 清除令牌；key repeat 按同一 scan_code 处理；dead key 与 IME 组合字符只有在产生它们的 keydown 被消费时才抑制。没有令牌时 WM_CHAR 正常插入。

#### 16.8 指针焦点、caret 与复选框

- 指针按下产生 `Press` 意图（source `Pointer`，target 为归一化命中节点）。宿主先用当前场景计算 `caret_index`，作为 `PressEvent.caret` 传入；runtime 不依赖 render。runtime 的默认动作：
  1. 若目标或其最近可聚焦祖先可聚焦且未禁用，焦点转移；
  2. 若目标是 text-input 且 `caret` 有值，设置 selection/caret 并清除原 selection（Shift 按下时保留 anchor 扩展）；
  3. 记录 press target；宿主维护 capture。
- 指针松开且命中同一启用目标时产生 `Activate`；否则不激活。
- 点击 button/checkbox 也按上表聚焦；是否需要“点击不聚焦”的平台变体由宿主策略决定，但必须一致并测试。
- 禁用控件：不派发 Press/Activate，不穿透；祖先禁用同样阻断。
- 复选框：
  - 有 `checked` 绑定为受控：产生 proposed；先运行 `on:change`；未 consume/prevent 时应用 pending；flush 后按 `checked` 绑定强制对齐；不存在第二次 `on:change`。
  - 无 `checked` 绑定为非受控：有 handler 时先运行，未 consume 时本地切换；无 handler 时直接本地切换。**不得**出现“无 handler 时完全不能切换”的现状。
- 程序化 Store/Signal 变化不派发 `on:change`；只有用户/UIA 产生的 Change 意图派发。

#### 16.9 窗口/activation 处理器与 Drop

窗口/activation 拥有独立处理器表：

```rust
pub struct WindowHandlers {
    pub keydown: Option<Box<dyn FnMut(&mut KeyEvent) -> HandlerOutcome>>,
    pub drop: Option<Box<dyn FnMut(DropEvent) -> HandlerOutcome>>,       // 值语义，into_paths 可用
    pub close: Option<Box<dyn FnMut(CloseEvent) -> CloseOutcome>>,       // 值语义，Allow/Deny/Pending
    pub command: BTreeMap<CommandId, Box<dyn FnMut(&mut CommandEvent) -> HandlerOutcome>>,
    pub menu_state: Option<Box<dyn Fn(&MenuStateEvent) -> MenuState>>,
}

pub struct CloseEvent {
    pub request: CloseRequest,
    pub source: CloseSource,
}
pub enum CloseOutcome { Allow, Deny, Pending }
pub enum CloseSource { SystemMenu, AltF4, Command, Programmatic, ConfirmationWindow }
```

- `DropEvent`/`CloseEvent` 按值传入，避免 `into_paths(self)`/`CloseRequest::allow(self)` 这类消费方法被 `&mut` 破坏；handler 内部可按值处理，返回 `HandlerOutcome`/`CloseOutcome`。
- `CloseOutcome::Pending` 表示“epoch 保持待决，确认窗口稍后回复”。它只对目录声明 `Confirm` 的窗口有效；`Immediate` 的 `on_close` **根本不会运行**（现有测试就是这一契约），关闭直接执行，`Drop` 处理器仍随销毁运行。
- `CommandEvent` 的 accessor（`source/target/window`）改为 `&self`，不移动事件；`MenuStateEvent::menu_state()` 返回 `MenuState`，与现有 `MenuCommandState` 映射。
- `keydown` 仍按 `&mut`，因为 handler 需要 `consume/prevent_default`；无焦点时 `KeyEvent.target = EventTarget::Window(activation)`。

- 在窗口 factory 的 setup 中通过 `WindowCtx::on_keydown/on_drop/on_close/on_command/on_menu_state` 注册；owner 是 activation owner；窗口关闭时随 activation 释放；重开必须重新注册。
- `WindowHandlers.keydown` 是窗口根的 fallback handler：路由 target 为焦点节点；没有焦点时为窗口根。它参与 capture/target/bubble，位于根。
- `Drop` **只**是窗口级处理器，不属于元素事件槽；`<view on:drop>` 是编译错误。`Drop` 的 target 是 `EventTarget::Window(activation)`，不做 closest-wins；一个窗口至多一个 drop handler。
- `on_menu_state` 在 `Phase::MenuState` 中运行：只读 Signal/Store；写入返回 typed error；panic contained；不参与 `TurnOutcome`；菜单初始化失败时保持原状。
- `on_close` 只在目录声明 `Confirm` 的关闭请求 turn 中运行；`Immediate` 不调用它。`Allow`/`Deny` 直接结算；`Pending` 保持关闭 epoch 待决。返回 `Pending` 时，handler 内排队的 `request_show(确认窗口)` **在同一个关闭 turn 内结算并校验确认窗口已可见**；若没有可见的确认窗口，报告 `TurnError::CloseConfirmationNotShown` 并按 `Deny` 失败关闭（fail closed），与现有 `DoNothing → ConfirmationNotShown` 测试一致。
- handler 内调用 `request.allow()/deny()` 显式回复时，显式回复优先于返回值；两者矛盾时以显式回复为准并记录诊断。确认窗口稍后通过 `close_request()` 回复同一 epoch；epoch 解除前父窗口不接受输入，但允许组合取消。
- 关闭 turn 内的窗口请求（确认窗口 show、父窗口 hide）在结算前完成；只有关闭 turn **之后**由其他 handler 排队的请求才按失效规则拒绝。`CloseSource` 区分系统菜单、Alt+F4、命令、程序化关闭与确认窗口回复。
- 窗口 factory、`on_close`、`on_drop`、`on_command` 的 panic 都进入 `TurnReport.errors`；不得穿过窗口过程。

#### 16.10 Delivery 批次

- `drive_tasks` 的**一个批次是一个 Delivery turn**，内含按完成顺序排列的 delivery steps。
- 每个 step 在运行前重新校验：task generation、owner generation、activation、窗口可见性、关闭挂起、目标节点存活。
- continuation 之间的写入立即可见；UI 只在批次结束 flush 一次。
- 一个 continuation panic/Err：停止后续 step，保留已写入状态，批次末 flush，返回带错误的批次报告；不得在批次中途静默跳过或重置整个队列。
- 隐藏窗口：tree 仍存活，delivery 允许运行；flush 后快照可延迟到 show 前，但任何读取其呈现/焦点/编辑状态的入口必须先 flush。
- 关闭确认挂起（close epoch）的窗口：delivery **延迟**到 epoch 解除；Allow 后按原顺序运行，Deny 后继续；Close 后丢弃。不得在挂起期间运行可能修改确认状态的 continuation。
- 窗口关闭后，旧 activation 的迟到交付直接丢弃；不得写入新 activation。
- continuation 不得读取已发布快照；需要 UI 几何的异步结果回到 Event turn 通过显式命令处理。此限制由 phase gate（`Phase::Delivery` 不提供 snapshot 读取）强制，而不是仅靠文档。

#### 16.11 错误通道与诊断

- 同步入口返回 `TurnReport`；异步/宿主入口返回批次报告。
- `TurnReport.errors` 是本次 turn 的唯一错误通道；宿主/应用必须在 turn 边界读取，不得静默丢弃。
- 开发模式额外提供 `ZENUI_TRACE=events,turns,errors`；每个错误带 `node/tag/owner/generation/phase` 与替代写法。
- `HandlerPanicked`/`FactoryPanicked`/`CleanupPanicked` 带 panic 消息与位置；`FactoryFailed` 带 factory 返回的错误；`FieldFault` 带 row/field；`GraphCycle` 带环上的 SourceRef 列表；`CloseConfirmationNotShown` 带窗口 activation 与目录 key。

### 17. UIA 动作与发布

#### 17.1 两条入口，而不是一条

UIA provider 线程只读已发布树；写动作进入每窗口动作队列，由 UI 线程在 turn 中执行。UIA 写动作**不走** closest-wins，也不产生普通 `Intent`；它是 typed node command，理由：

- ADR-0012 明确 UIA 调用 `click_node`/`change_node`/`replace_text_node`/`set_selection_node`/`focus_node`；
- `SetSelection` 不得派发 `on:input`（GLOSSARY、验证重点、样式与输入）；
- `Scroll` 只改宿主 applied offset，不进入 runtime；
- UIA 的可操作节点已经是语义节点，closest-wins 是鼠标便利，不是 UIA 语义。

但 UIA 动作与普通输入共享：目标校验、turn 队列、写入门、flush、panic 边界、`TurnReport`。因此 Part I 的“Intent 是唯一事件入口”修正为“Intent 是唯一**路由型用户输入**入口；可打印字符由宿主 `type_text_node` 直接进入 Event turn；UIA 动作是另一条 typed command 入口”。

#### 17.2 动作与载荷

```rust
/// runtime 全局唯一、可 Send 的窗口激活令牌；由 runtime 在 mint WindowCtx 时分配。
/// 槽位单调分配、不复用；generation 用于拒绝旧 activation。
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
pub struct ActivationId { slot: u32, generation: u32 }
impl ActivationId {
    pub fn to_bits(self) -> u64;
    pub fn from_bits(bits: u64) -> Self;
}

pub enum UiAction {
    Invoke { node: NodeId },
    Toggle { node: NodeId },
    ReplaceValue { node: NodeId, text: String },
    SetSelection { node: NodeId, anchor: usize, focus: usize }, // 运行时字符偏移
    SetFocus { node: NodeId },
}

/// provider 线程 → UI 线程的同一个 per-window FIFO；Send POD，不含 WindowCtx/NodeRef。
pub enum ProviderAction {
    Node(UiActionRequest),
    Scroll(ScrollRequest),
}
pub struct UiActionRequest {
    pub runtime: u32,
    pub activation: ActivationId,
    pub action: UiAction,
}
pub struct ScrollRequest {
    pub runtime: u32,
    pub activation: ActivationId,
    pub command: ScrollCommand,
}

pub enum UiActionError {
    Stale, Hidden, Disabled, Suspended, NotForeground, Composing, Rejected,
}
```

`Scroll` **不在** `UiAction` 中：它由宿主执行 applied-offset 路径（ADR-0010），不进入 runtime，也不形成 Event turn；但它仍与 node action 共享同一个 per-window FIFO、顺序、1024 上限和清空规则（ADR-0012 的单队列契约）。宿主不是从另一个队列“旁路”处理 Scroll。

| 动作 | 执行 | 用户事件 | 默认动作 | 重验 |
|---|---|---|---|---|
| `Invoke` | `click_node(node)` | 该节点的 `on:click` 一次 | 节点局部 handler；不回溯祖先，不执行 submit 默认 | 存在/generation/启用/可见/未关闭 |
| `Toggle` | `change_node(node, proposed)` | 该节点的 `on:change` 一次 | 受控对齐/非受控切换与指针同源 | 同上；不可写时拒绝 |
| `ReplaceValue` | `replace_text_node(node, text)` | 一次 `on:input` | 整体替换、caret 末尾、单条 undo；值相同则静默 | 同上；组合中拒绝（`Composing`） |
| `SetSelection` | `set_selection_node(node, anchor, focus)` | 无 `on:input` | 夹取到已提交文本范围；组合中拒绝 | 同上；组合中拒绝 |
| `SetFocus` | `focus_node(node)` | `Blur`/`Focus` 与存活节点转移一致 | 要求节点可聚焦且启用 | 额外要求窗口前台 |

- `ProviderAction` 只含 POD：`runtime: u32`、`activation: ActivationId`、动作载荷。`ActivationId` 是 runtime 全局唯一的窗口槽 + generation，不是现有 per-catalog-key 的 `activation: u32`；`(runtime, activation)` 在 runtime 的全局窗口表中解析到唯一 `WindowCtx`，generation/槽不匹配即按竞态丢弃。`WindowCtx` 不进入跨线程队列。
- provider 侧构造：宿主创建 `WindowAccessibility` 时注入 `runtime_id` 与 `activation.to_bits()`（不是只传 HWND），即 `WindowAccessibility::new(hwnd, runtime_id, activation_bits)` 或等价的 `bind_identity`。必须新增公开 `WindowCtx::runtime_id() -> u32`（或 `Runtime::runtime_id()`）作为 runtime 来源；`NodeId` 也提供公开的 `runtime_id()`（现为 `pub(crate)`，必须放开或提供等价 accessor）。`ScrollRequest` 不含 `NodeId`，**必须**用 `WindowAccessibility` 保存的 runtime id 构造，不能从节点反推。若 provider 拿不到这两个字段，动作在入队前就应返回 `UIA_E_ELEMENTNOTAVAILABLE`，不得构造伪造身份。
- 每个窗口的队列本身也绑定该窗口；`runtime/activation` 是校验字段，不是队列路由依据。这样即使两个 catalog key 的旧 `activation=1` 同时存在，也不会串窗。
- `SetSelection` 的偏移由 provider **在入队前**从 UTF-16 转成运行时字符偏移；runtime 不再转换，避免非 BMP 二次转换。`ReplaceValue` 只有文本，没有偏移。UIA 的 `SetValue` pattern 映射到 `ReplaceValue`，`Toggle` pattern 映射到 `Toggle`。
- `ReplaceValue` 在组合中**拒绝**（`UiActionError::Composing`），保持 ADR-0012 “组合中的输入可读但拒绝写”的现契约；不新增“取消组合”语义，也不派发 Composition 事件。
- `Toggle` 的 proposed 由当前 ToggleState 取反；禁用/不可写时拒绝。
- UIA 动作不执行菜单命令、不执行 `type=submit` 默认、不产生 capture/bubble；`Scroll` 是宿主路径，不在本表。

#### 17.3 队列与 turn

- 每个窗口一个 FIFO `ActionQueue<ProviderAction>`，最多 1024 条（node 与 scroll 共享上限）；满或 post 失败返回 `UIA_E_ELEMENTNOTAVAILABLE`，不留下部分条目。
- UI 线程按队列顺序 drain。每个 `ProviderAction::Node` 是一个 Event turn（不是合并批次），`TurnReport` 单独记录错误；每条之间 flush 一次，保证下一条重验看到最新状态。`ProviderAction::Scroll` 在宿主 applied-offset 路径执行，不形成 runtime turn，但仍在同一队列位置被取出并先于其后的 node action 生效。
- 每条 node action 前按 §17.2 的逐动作矩阵重验：NodeId 存在、generation 匹配、元素启用、窗口可见且未关闭、窗口接受输入；SetFocus 额外要求前台；SetSelection/ReplaceValue 在组合中拒绝；Toggle/Invoke 不额外要求前台。失败按普通竞态丢弃，不产生宿主错误、不重试。`Scroll` 在宿主路径重验可滚动、未挂起、窗口可见。
- 隐藏/关闭/零客户区清空整个队列（含未执行的 Scroll）；清除后旧动作永不执行。

#### 17.4 发布与事件

UIA 发布保持 ADR-0012 的整体替换契约：

1. 每个已发布窗口在每次场景提交后，从 `PresentationSnapshot` + 同一个 `Scene` 构建一份新的不可变 `AccessibilityTree`。
2. 发布是 `RwLock<Option<Arc<AccessibilityTree>>>` 的原子替换；provider 每次调用解析当前发布，不保留第二份界面。
3. 结构/属性/焦点事件由**相邻两次发布**按 provider-local runtime ID 比较产生；顺序固定为结构 → 属性 → 焦点。
4. 结构事件：`ChildAdded` 发在新增子节点；`ChildRemoved` 发在父节点并携带被移除 child 的 runtime ID；`ChildrenReordered` 发在父节点。新增子树只报顶层。
5. 属性事件只比较两次发布都存在的节点：`IsEnabled`、`ToggleState`、`Value`。
6. 焦点事件只在发布窗口前台时投递；后台焦点变化不补发；焦点清空以 `GetFocus` 为空表达，不发单独事件。
7. `PresentationDelta` **不供 UIA 消费**。UIA 需要完整旧/新树来判断属性变化与结构父节点；delta 缺 parent/子序/旧值，不能替代比较。delta 只服务 renderer。
8. UIA 树构建成本允许 O(可见节点)；之后按基线决定是否持久化。首版不得为了“增量”引入第二棵可修改界面树。

#### 17.5 隐藏、挂起与关闭

- 隐藏、关闭挂起、零客户区：不发布树；清空动作队列；provider 查询返回 `UIA_E_ELEMENTNOTAVAILABLE`。
- 关闭确认挂起：父窗口保持发布但报告 `IsEnabled=false`、`IsKeyboardFocusable=false`；写动作拒绝；确认窗口有自己的 root。
- 窗口后台：树可读；焦点属性与焦点事件遵循前台规则。
- 窗口化 `For`：只有已挂载行有 NodeId、scene 元素和 UIA 节点；离开窗口的行从树中移除，重进是新 NodeId、新 runtime ID。

#### 17.6 ADR-0012 修订要点

§12 的 ADR-0012 修订必须补齐：

- UIA 写动作是 typed node command，不是 Intent 路由；这是“唯一**路由型**用户输入入口”的明确例外；
- `ActivationId` 改为 runtime 全局唯一的窗口槽 + generation；`WindowAccessibility` 创建时注入 runtime 与 activation，`NodeId::runtime_id()` 公开；`ProviderAction` 是 Send POD，队列不含 `WindowCtx`/`NodeRef`；
- `ProviderAction::{Node, Scroll}` 共用同一个 per-window FIFO、顺序、1024 上限和清空；`Scroll` 仍由宿主执行 applied-offset，不进入 runtime；
- `ReplaceValue`/`SetSelection`/`SetFocus` 的载荷与默认动作；`ReplaceValue` 在组合中拒绝（`Composing`），与 ADR-0012 现契约一致；
- UIA 发布仍为整体替换 + 相邻发布比较；delta 只服务 renderer；UIA 没有 `applied_revision`；
- 结构事件父节点/runtime ID 规则保持不变。

### 18. 响应式值、绑定槽、补丁与身份

#### 18.1 ReactiveValue 与 MemoCompute

值相等必须能在类型擦除后执行；不能依赖“worklist 里每次重算都算变化”。

```rust
pub trait ReactiveValue: Clone + 'static {
    /// 值语义相等；用于 memo 的下游抑制。
    fn equivalent(&self, other: &Self) -> bool;
}

impl<T: Clone + PartialEq + 'static> ReactiveValue for T {
    fn equivalent(&self, other: &Self) -> bool { self == other }
}

/// 一次 memo 重算的完整契约：调用 + 类型擦除相等。
pub trait MemoCompute {
    fn call(&self) -> Box<dyn Any>;
    fn eq(&self, old: &dyn Any, new: &dyn Any) -> bool;
}

#[repr(C)]
pub struct MemoCell {
    compute: Option<Rc<dyn MemoCompute>>, // 16 B
    value: Option<Rc<dyn Any>>,          // 16 B
    revision: u64,                       // 8 B
    deps: DepListId,                     // 4 B；指向 MemoDepsArena
    flags: MemoFlags,                    // 1 B + padding；合计 48 B
}

/// deps 不与槽头内联：SmallVec<[DepId; 4]> 本身约 24 B，会直接破坏 48 B/64 B 预算。
pub struct MemoDepsArena { lists: PagedArena<DepList> }
#[derive(Clone, Copy)] pub struct DepListId(u32);
pub struct DepList { entries: SmallVec<[DepId; 4]> }
```

- `Signal<T>`、`Memo<T>`、`Read<T>` 的公开 bound 是 `T: ReactiveValue`；`memo(|| ...)` 的返回类型必须 `ReactiveValue`。
- `RowSet` 是 newtype，其 `PartialEq` 先比较 `Arc::ptr_eq`（`shares_with`）与 order revision，再按 store + ids 顺序深比较；这样 `Memo<RowSet>` 走统一 `equivalent` 的 blanket impl，不需要 specialization，纯 reorder 也不会被判等。
- `MemoCompute` 的 `eq` 在 `call` 之后由 typed adapter 执行；old/new 都是 `Box<dyn Any>`，adapter 先 downcast 到 `T`。downcast 失败是内部契约错误。
- `MemoCell` 的 `compute` 与 `value` 各 16 B，revision 8 B，deps 4 B，flags 1 B + padding，合计 48 B；**deps 在独立 `MemoDepsArena`**；预算上限 64 B。`SignalCell` 为 32 B。`DepList` 的存储单独计入 `memo_deps_storage`。
- 不得用“每次重算都标脏下游”代替 `equivalent`；10k 行共享 memo 的相等重算必须不进入 binding worklist。

#### 18.2 Read、Once、Field 与可失败读

`Read<T>` 的公开变体补齐 `Once`，并把“读取可能失败”定义在求值结果里，而不是让每个绑定自己发明：

```rust
pub enum Read<T> {
    Static(T),          // 字面量
    Once(Once<T>),      // 显式快照；与 Static 共享静态依赖，但保留诊断来源
    Signal(Signal<T>),
    Memo(Memo<T>),
    Field(Field<T>),    // Field::get 返回 Result
}

pub enum ReadFault {
    FieldMissing(FieldError),
    ComputedPanicked,
    GraphCycle,
    Disposed,
}

pub enum ReadValue<T> {
    Value(T),
    Fault(ReadFault),
}
```

- `Read::Once` 单独存在是为了“为什么没更新”的诊断能回答“这是 once 快照”，而不是把所有静态值混成 `Static`。
- `Read::Field` 的求值返回 `ReadValue<T>`；绑定层把 `Fault` 写入 `BindingSlot.fault`，并保留 `current` 的最后已提交值。`Field::get` 本身仍返回 `Result`，供组件 setup 的 `?` 使用。
- `Read<T>` 作为组件 prop 时，组件作者有两种读法：
  - `read.read_once()?`：挂载快照，失败向上抛；
  - `read.bind()`：得到可失败绑定，供 `Show`/`For`/控件使用。
- 不得把 `FieldError::Missing` 静默转成 `false`/空字符串/0；第一次挂载没有最后值时，按 §18.3 的 part 策略处理。

#### 18.3 BindingSlot 与按 part 的错误策略

**最后值只有一个权威**：`BindingSlot.current`。`ReadSlot` 只描述来源，不保存值；`fault` 与 `current` 并列，而不是把 `current` 替换成错误枚举。

```rust
pub struct BindingSlot<T> {
    pub source: ReadSlot,      // 来源描述，不存 current；T 只由 BindingSlot 携带
    pub current: Option<T>,    // 唯一已提交值；None = 首次尚未成功
    pub fault: Option<ReadFault>, // 本次求值失败；可与 current 同时存在
    pub generation: u32,
}
```

**存储归属（写死）：** `BindingSlot` **不内联**在 `ElementData`/`NodeSlot` 中，也不存在 `ElementData.current[part]`。每个 tree 拥有一个 `BindingTable`，按值类型分表：

```rust
/// 8 B 打包：table: u8 + slot: u24 + generation: u32；与 NodeRef 同构。
#[repr(transparent)]
pub struct BindingRef(u64);

pub struct BindingTable {
    text: PagedArena<BindingSlot<String>>,
    strings: PagedArena<BindingSlot<Arc<str>>>,
    bools: PagedArena<BindingSlot<bool>>,
    numbers: PagedArena<BindingSlot<f64>>,
    lengths: PagedArena<BindingSlot<Length>>,
    colors: PagedArena<BindingSlot<Color>>,
    row_sets: PagedArena<BindingSlot<RowSet>>,
    // 每种值类型一张表；PartId 决定类型，BindingRef.table 必须匹配
}

/// 元素/结构节点的绑定索引；按 PartId 稳定排序。
pub struct BindingList { entries: [(PartId, BindingRef)] }
```

- `ElementData.bindings` 是 `BindingListId`（`u32::MAX` 表示无绑定）；`ShowData`/`ForData` 直接保存 `when`/`each` 的 `BindingRef`。
- 一个 part 在 `BindingList` 中最多一项；`BindingRef.generation` 拒绝已释放槽。
- 元素卸载时先退订边，再把 `BindingList` 中的每个槽归还对应表并清空 list；`BindingList` 本身归还 `AuxArenas.binding_lists`。
- `Static`/`Once` 的值在挂载时写入 `current`，`ReadSlot` 只保留来源标记；它们没有 `DepKey`，永不重算。这样不存在“值在 ReadSlot 与 current 各存一份”的双权威。

状态组合：

| `current` | `fault` | 含义 |
|---|---|---|
| `None` | `None` | 首次挂载尚未求值 |
| `None` | `Some` | 首次求值失败，无最后值 |
| `Some` | `None` | 正常，最后值有效 |
| `Some` | `Some` | 本次失败，保留最后值并报 fault |

按 part 的可见策略：

| part | 有最后值时 | 首次求值失败时 | 错误上报 |
|---|---|---|---|
| 文本 | 保留最后文本 | 文本为空，元素仍挂载 | `FieldFault` |
| `value`/`disabled`/`checked` | 保留最后值 | 属性不出现/保持 intrinsic 默认 | `FieldFault` |
| `style:*` | 保留最后样式 | 使用 intrinsic 默认 | `FieldFault` |
| `Show.when` | 保持当前分支 | 不挂载新分支（保持未挂载） | `FieldFault` |
| `For.each` | 保持当前行集 | 空行集 | `FieldFault` |
| 组件 `Read<T>` prop | 由组件 `try_get` 决定 | 由组件 `try_get` 决定 | `FieldFault` |

- 错误状态本身不自动 bump `tree.revision`；只有它导致可见值/结构变化时才计入 effective change。
- 首次失败后，源恢复时下一次 flush 重新求值，清 `fault` 并更新 `current`；不得要求重挂载。
- `Show`/`For` 的首次失败不产生“false/空数组”的业务语义，只是“无可用值，保持未挂载/空行集”，并在报告中说明。

#### 18.4 BindingPart、ReadSlot 与 BindingPatch

Part I 只引用了这些名字，没有定义。补齐为稳定判别式：

```rust
pub enum BindingPart {
    Text,
    Attr(AttrId),
    Style(StylePropId),
    Bool(BoolProp),       // disabled, checked, aria-pressed, ...
    ShowWhen,
    ForEach,
}
// 反向边不内联 BindingPart；注册后压成 PartId(u16)，再打包进 ConsumerRef。
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
pub struct PartId(u16);

pub enum StructuralPart {
    ShowBranch,
    ForRows,
    ForOrder,
    RowWindow,
}

pub struct OnceOrigin(u32); // 快照来源诊断 id；不携带值

pub enum ReadSlot {
    Static,                 // 值只在 BindingSlot.current；挂载时写入
    Once(OnceOrigin),       // 值只在 BindingSlot.current；保留诊断来源
    Signal(SourceRef),
    Memo(SourceRef),
    Field(FieldKey),
}

pub struct BindingPatch {
    pub node: NodeRef,
    pub part: BindingPart,
    pub old: Option<Box<dyn Any>>,   // 旧 current
    pub new: Option<Box<dyn Any>>,   // 新 current；None = 首次失败/清除
    pub fault: Option<ReadFault>,
}
```

- 每个 part 有且只有一个 `BindingSlot`；`BindingSlot` 记录来源、最后值、fault、generation，`ReadSlot` 只描述来源（`Static`/`Once` 不携带值）。静态槽不注册 `DepKey`，值在挂载时复制进 `current`；`OnceOrigin` 只用于“为什么没更新”的诊断。
- `BindingSlot` 的存储位置与生命周期按 §18.3 的 `BindingTable`/`BindingList` 执行；`ElementData` 只保存 `BindingListId`，`NodeSlot` 不保存任何绑定字段。不得重新引入 `ElementData.current[part]`。
- `BindingPatch` 在 flush 内按 `(tree, node, part)` 去重；一个 part 一个 turn 最多应用一次。应用顺序：`ShowWhen`/`ForEach` 结构触发 part 在 flush step 2a 求值并立即写回（其 patch 归结构阶段）；其他 part 在 step 3 应用。结构 patch 先于值 patch；同一节点的多个 part 按 `BindingPart` 的稳定序应用。
- `patch` 同时携带旧/新值，供 delta 与快照构建使用；不得在构建快照时重新读取绑定源（那会绕过 flush 的一致性）。
- 宏为每个 part 生成绑定描述符；描述符只包含 `ReadSlot` 构造与 part id，不包含闭包求值逻辑。数据位置的闭包由宏降为 `memo` 后作为 `ReadSlot::Memo`。`Static`/`Once` 的初始值通过 `BindingSlot::new_static/once` 写入 `current`。

#### 18.5 Owner、OwnerRef 与创建 API

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
pub struct OwnerRef {
    slot: u32,
    generation: u32,
}

pub struct Owner { /* runtime + OwnerRef */ }

impl Runtime {
    pub fn app_owner(&self) -> Owner;
    pub fn signal_in<T: ReactiveValue>(&self, owner: Owner, value: T) -> Signal<T>;
    pub fn memo_in<T: ReactiveValue>(&self, owner: Owner, f: impl Fn() -> T + 'static) -> Memo<T>;
    pub fn task_in<...>(&self, owner: Owner, ...) -> Task<...>;
}

impl MountCx<'_> {
    pub fn owner(&self) -> Owner;
    pub fn signal<T: ReactiveValue>(&self, value: T) -> Signal<T>;
    pub fn memo<T: ReactiveValue>(&self, f: impl Fn() -> T + 'static) -> Memo<T>;
    pub fn on_cleanup(&mut self, f: impl FnOnce() + 'static);
}
```

- `MountCx` 由 runtime 在挂载时构造：`Runtime::mount_component`/窗口 factory/`Show`/`For` 行 factory 把 `MountCx<'_>` 传给组件 setup。`#[component]` 识别保留参数 `cx: MountCx<'_>`，不把它生成为 builder prop；现有 `signal()`/`memo()` 在 `Phase::Setup`/`Phase::Structure` 中解析到当前 `MountCx` 的 owner，其他 phase 必须用 `signal_in`/`memo_in`。`signal_in`/`memo_in` 校验 `Owner` 属于同一 runtime，跨 runtime 返回 typed error。
- 资源（Signal、Memo、任务、事件处理器、绑定消费者、窗口请求、行带）都登记在 `OwnerRef` 上；普通元素不再各自创建 owner，资源挂到最近的结构 owner（组件/Show/For 行/窗口 activation/应用）。
- owner 使用 generation + paged arena；复用槽必须换 generation；task/row-band/WindowCtx 持有 owner generation，迟到交付按 generation 拒绝。
- handler/memo compute 内创建资源默认拒绝（`CreationError::NoOwner`），除非显式传 `Owner`（`signal_in`/`memo_in`）。memo compute 内创建 memo 默认拒绝，避免环；需要时显式挂到 app owner，并在文档说明生命周期。
- 隐式 memo 的 owner = 产生它的绑定所在节点/组件的 owner；元素卸载时先退订，再释放隐式 memo；若还有别的消费者，保留到最后一个消费者离开。
- 跨 owner 读取：`try_get` 返回 `HandleError::Disposed`/`WrongOwner`；`get` 只在同 owner、存活上下文内使用，违反是开发期契约 panic。Part I §2.2 与 §5.9 的“跨 owner 是 typed error / 是 panic”按此统一：**跨 owner 边界用 typed error；同一 owner 内违反 handle 契约是开发期 panic**。

#### 18.6 RowId、FieldKey 与 DepKey

业务 key 不是行身份。行身份用 arena 的 slot + generation，**不把业务 key 塞进 RowId**：

```rust
pub trait RowKey: Copy + Eq + Hash + Ord + 'static {}
impl<T: Copy + Eq + Hash + Ord + 'static> RowKey for T {}

pub trait Row: Clone + 'static {
    type Key: RowKey;
    fn key(&self) -> Self::Key;
}

/// 8 B：32-bit slot + 32-bit generation；与 NodeRef 同构。
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
pub struct RowId {
    pub slot: u32,
    pub generation: Generation,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
pub struct FieldKey {
    pub row: RowId,
    pub field: FieldId,
}

/// Typed, erased field handle：runtime + FieldKey + PhantomData<T>。
pub struct Field<T> {
    runtime: u32,
    key: FieldKey,
    _marker: PhantomData<fn() -> T>,
}

pub enum DepKey {
    Signal { slot: u32, generation: u32 },
    Memo { slot: u32, generation: u32 },
    Field(FieldKey),
    Rows(FilterId),
    Appearance,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
pub struct StoreId(u32);     // runtime 内 store 槽；RowId 来自 runtime 全局 row arena

pub struct RowSetData {
    pub store: StoreId,       // 校验 ForSource/Field 归属；不复制到每行
    pub ids: Box<[RowId]>,    // 8 B/行；顺序 = Store 当前用户 order
}

/// 必须是 newtype，不能是 `type RowSet = Arc<RowSetData>`：
/// newtype 才能提供 shares_with 与自定义 PartialEq，同时继续命中 ReactiveValue 的 blanket impl。
#[derive(Clone)]
pub struct RowSet(Arc<RowSetData>);
impl RowSet {
    pub fn shares_with(&self, other: &RowSet) -> bool { Arc::ptr_eq(&self.0, &other.0) }
    pub fn ids(&self) -> &[RowId];
    pub fn store(&self) -> StoreId;
}
impl PartialEq for RowSet {
    fn eq(&self, other: &Self) -> bool {
        self.shares_with(other) ||
        (self.store() == other.store() && self.ids() == other.ids())
    }
}
impl Eq for RowSet {}

/// For 的唯一数据入口：Store 句柄 + 行集读源。
pub struct ForSource<R: Row> {
    pub store: Store<R>,
    pub rows: Read<RowSet>,
}

pub struct RowView<R: Row> {
    id: RowId,
    store: Store<R>,
    snapshot: R,              // 挂载时快照，供 key/item 工厂读取业务字段
}
impl<R: Row> RowView<R> {
    pub fn id(&self) -> RowId;
    pub fn key(&self) -> R::Key;
    pub fn get(&self) -> &R;
    pub fn field<T: ReactiveValue>(&self, field: FieldId) -> Field<T>;
}

pub struct For<R: Row, K: RowKey> {
    source: ForSource<R>,
    key: Rc<dyn Fn(&R) -> K>,
    item: Rc<dyn Fn(RowView<R>) -> MountResult<MountPlan>>,
    row_height: Option<Length>,
}
```

`ForSource`/`RowView`/`For` 属于 view/runtime 层，组合了 core 的 `Store<R>`/`RowSetData` 与 view 的 `Read<RowSet>`；`crates/core` 不得依赖 `Read`，只提供 `Store`/`Rows`/`RowSetData`/`RowId`。`impl<R: Row, F: FilterSpec<R>> From<Rows<R, F>> for ForSource<R>` 把 `Rows` 的 store 与行集读源装入；裸 `Read<RowSet>` 由 `For` 的 `store` prop 补全。`ForData` 的擦除边界见本节末。

```rust

impl<R: Row> Store<R> {
    pub fn key_of(&self, id: RowId) -> Option<R::Key>;
    pub fn get(&self, id: RowId) -> Option<R>;
    pub fn contains(&self, id: RowId) -> bool;
    pub fn rowset(&self, ids: impl IntoIterator<Item = RowId>) -> RowSet; // 校验每行归属
}
```

**类型擦除边界。** `NodeArena` 不泛型化，`ForData` 不能带 `R`/`K`。挂载 `For<R,K>` 时把它降为：

```rust
struct ForData {
    source: ErasedForSource,     // StoreId + each 的 BindingRef + 行集读源
    driver: Rc<dyn ForDriver>,   // 唯一持有 R/K 类型的地方
    window: RowWindow,
    // ... 已挂载窗口簿记
}
struct ErasedForSource { store: ErasedStore, rows: BindingRef }
trait ForDriver {
    /// 通过捕获的 Store<R> 取行快照；ForData 用它做 key 映射/重复检测/挂载。
    fn row_snapshot(&self, id: RowId) -> Option<Rc<dyn Any>>;
    fn key_hash(&self, id: RowId) -> Option<u64>;
    fn key_eq(&self, a: RowId, b: RowId) -> bool;
    fn mount_row(&self, view: ErasedRowView, cx: &mut MountCx<'_>) -> MountResult<MountPlan>;
}
struct ErasedRowView { id: RowId, store: ErasedStore, row: Rc<dyn Any> }
struct ErasedStore { runtime: u32, store: StoreId }
```

- `ForData` 遍历 `RowSet.ids` 时调用 `driver.row_snapshot(id)`/`key_hash(id)`/`key_eq(a,b)`；typed 的 `Store::get`/`key_of` 调用全在 driver 内，erased 层只处理 `RowId` 与 `Rc<dyn Any>`。这给 key 映射、重复 key 校验和行挂载提供了真实数据路径。
- 挂载时 `ForData` 用 `(id, store, driver.row_snapshot(id))` 构造 `ErasedRowView`；`driver.mount_row` 内部 downcast 到 `R` 并构造 `RowView<R>`。`Rc<dyn Any>` 是所有权快照，不与 `&mut MountCx` 形成别名；`ErasedRowView` 不再带生命周期参数。
- `mount_row` 返回 `MountResult<MountPlan>`；`Err` 映射为 `TurnError::FactoryFailed`，panic 映射为 `FactoryPanicked`；失败只释放拟议行 owner，旧行映射保持不变。`For<R,K>.item` 的签名同步为 `Fn(RowView<R>) -> MountResult<MountPlan>`。
- 该擦除只发生在 `ForData` 边界；公开 `For<R,K>`、`ForSource<R>`、`RowView<R>` 保持类型安全。

- `Field<T>` 持有 `FieldKey`；`Field::get` 在行 slot/generation 不匹配时返回 `FieldError::Missing`，不得重定向到同业务 key 的新行。
- `RowId` 的 generation 来自 row arena 的**槽 generation**；删除后同业务 key 重新插入必须分配新 slot 或递增 generation，旧 `RowId` 不得命中新行。Store 的 `key → RowId` 索引是 O(1)（或 O(log n)），由应用层 key 映射维护。
- `For` 的行身份是 `RowId`；重排保留 `RowId`；删除后同业务 key 重新插入产生新 `RowId`，旧行元素卸载、旧 NodeId Stale、局部编辑状态不继承。`For` 的 key selector 接收 `&R`（由 `ForSource.store` 解析），只用于重复 key 检测与 keyed 重排；持久表存 `RowId`。
- `For` 的唯一数据入口是 `ForSource<R> { store: Store<R>, rows: Read<RowSet> }`；`ForData` 保存擦除后的 `ErasedForSource` + `ForDriver`（见上）。item factory 接收 `RowView<R>`，提供 `id()/key()/get()/field::<T>()`。不允许只给 `For` 一个 `Read<RowSet>` 而没有 `Store<R>`：那样 `key_of`/行数据/重复 key 校验都无接收者。
- `ChangeSet` 的 `inserted/removed` 使用 `RowId`；同 key 的 removed+inserted 不得被 `items.contains_key` 合并。
- `RowSet` 是包裹 `Arc<RowSetData>` 的 newtype，元素是 `RowId`（8 B/行），不是 `RowKey`；`RowSetData.store` 记录来源 store，`ids` 的顺序是 **Store 当前用户顺序**（order revision 驱动），不是业务 key 排序。`PartialEq` 先 `Arc::ptr_eq`（`shares_with`），再比较 store 与 `ids` 顺序；这样既有 O(1) 快路径，又不需要 specialization。业务 key 由行数据提供，不复制进集合。delete+reinsert same key 会产生不同 RowId，不会被 `Memo<RowSet>` 的相等抑制；纯 reorder 改变 `ids` 顺序，因此 `Memo<RowSet>` 的 `equivalent` 必须比较顺序（或 order revision），不能只比较集合。
- `StoreId` 是 runtime 内的 store 槽（u32）。`RowId` 来自 runtime 全局 row arena，本身已全局唯一；`StoreId` 用于 `StoreChange` 路由与 `ForSource`/`RowSet` 归属校验。`Field<T>` 解析 `RowId` 时经 runtime 的 RowId→store 表找到所属 store；`FieldId`/`FilterId` 是 runtime 内唯一的注册值。Phase 1 只启用一个活跃 `Store<R>`；多 store 保留同一机制，但不是首版门禁，启用前必须重做 `DepKey::Rows` 的归属校验。

#### 18.7 ChangeSet、FilterSpec 与候选行投影

`ChangeSet` **不是**泛型：字段只用 `RowId`/`FieldId`/`FilterId`，不需要 `R`。`FilterSpec<R>` 只用于 predicate：

```rust
pub struct ChangeSet {
    pub inserted: SmallVec<[RowId; 8]>,
    pub removed: SmallVec<[RowId; 8]>,
    pub fields: SmallVec<[(RowId, FieldId); 8]>,
    pub membership: SmallVec<[FilterId; 8]>,
    pub order: bool,
}

pub struct PendingChanges {
    pub stores: SmallVec<[StoreChange; 4]>,
}
pub struct StoreChange {
    pub store: StoreId,
    pub changes: ChangeSet,
}

pub trait FilterSpec<R: Row>: 'static {
    fn id(&self) -> FilterId;
    /// 该 filter 依赖的字段；用于把字段变化投影到候选行。
    fn watched_fields(&self) -> &'static [FieldId];
    fn matches(&self, row: &R) -> bool;
}
```

- Store 事务提交返回 `ChangeSet`；Runtime 把**自上次 flush 以来的所有提交**累积为 `PendingChanges`，`flush(dirty_trees, pending: &PendingChanges)` 的 step 0 读取 `changes.removed` 做 quarantine，结构提交确认卸载后才退订。没有这个入口，quarantine 无法实现；per-turn 只保留最后一个提交会让隐藏/延迟场景丢失 removed。
- Store 维护 `FieldId → [FilterId]` 的候选反向索引；提交时对每个变化字段找出可能受影响的 filter，重新求值 `matches`（包括当前不在结果内的候选行），产出 membership 迁移。
- `Rows<F>` 的 source 在 membership/order revision 变化时标脏；`Memo<RowSet>` 观察这些 revision，不复制字段边。
- 过滤结果与顺序由共享 `RowSet` 提供；`RowSet.ids` 的顺序是 **Store 当前用户顺序**（order revision 驱动），`For` 直接使用该顺序做 keyed 重排，业务 key 只用于重复检测。`For` 的持久簿记保存已挂载窗口的 `(RowId, row_index, NodeRef)`，业务 key 通过 `Store::key_of(RowId)`、行数据通过 `Store::get(RowId)` 取得，不保存全量 key→row 映射。
- `Rows<F>` 的投影在 membership/order revision 变化时重建 `RowSetData`；纯 order 变化必须产生新的 `ids` 顺序并推进 revision，否则 `Memo<RowSet>` 的相等会抑制重排，`Store::reorder` 变成 no-op。
- `FilterId` 由 filter 定义注册，不能是 `[bool; 3]`；`FieldId` 由模型定义注册，不能是 `FieldKind`。
- 聚合/空判断（`is_empty`、count）直接读 membership/count，不物化完整 `RowSet`。

#### 18.8 flush 顺序、预退订与 liveness

Part I §6.5 已包含 step 0；完整签名与 PendingChanges 入口如下：

```
flush(dirty_trees, pending: &PendingChanges):
  0. quarantine removed rows
     对 pending 中每个 StoreChange.changes.removed 的 RowId 标记 retired/quarantined；
     liveness 跳过只服务这些行的 memo；**边与订阅保留**，等结构提交确认卸载。
  1. dirty memo worklist（runtime 全局）
     只求值仍被 mounted 消费者可达的脏 memo；跳过 quarantined 行；按依赖顺序；
     值变化 → Memo 消费者入 worklist，Binding/Structural 消费者标脏并加入 dirty_trees；
     相等 → 不标下游。
  2. per-tree structural trigger + staging + commit
     2a. 求值脏的 ShowWhen/ForEach binding：source → current/fault → BindingPatch；失败保留旧 current。
     2b. 用 2a 的 current 预挂载/校验/提交；成功才对确实卸载的行预退订并移除边；
         失败释放拟议结构、保持旧结构，并取消该批 quarantine。
  3. binding worklist
     跳过 2a 已求值的结构 part；每个脏 part 求值 → 与 current 比较 → 写回 → 记录 BindingPatch。
  3.5 pending edit lineage observe
  4. focus settlement
  5. cleanup
  6. effective change / revision
```

- **liveness 定义**：一个 memo 是 live 的，当且仅当存在一条从它出发的消费者链到达一个已挂载的 Binding/Structural 消费者。worklist 跳过非 live memo；quarantined 行上的消费者在本轮视为 non-live；它们保留到 owner 释放、结构提交确认卸载或下一次显式读取。
- 共享 memo 的消费者可以跨 tree；它变化时，Binding/Structural 消费者各自所属 tree 加入 `dirty_trees`，Memo 消费者进入全局 worklist。
- 同一 binding 一个 turn 最多求值一次，除非焦点结算产生新一轮；memo 不受此限，但同一 turn 内被多次标脏的 memo 只重算一次，且重算后若再次被标脏必须重新入 worklist（不得因为“已算过”而跳过）。
- 删除行/过滤变化必须先 **quarantine**（step 0），实际预退订在结构提交确认卸载后执行；这是对《数据与更新》“删除行先退订再求值”的落实，同时避免结构提交失败时把仍挂载的行提前退订。
- `PendingChanges` **累积自上次 flush 以来的所有 Store 提交**，不是只保留当前 turn 的最后一个提交；隐藏窗口、headless 与可见窗口都在 turn 末同步执行 step 0–6，只有快照根/场景构建可以延迟（§19.5）。焦点/结构提交产生的新 Store 提交合并进 quarantine，并在回到 1 之前重新执行 0/2a；`PendingChanges` 只在 step 6 之后清空。

#### 18.9 memo cycle、poison 与读契约

- 求值栈检测循环：读取正在 `computing` 的 memo 产生 `ReactiveError::GraphCycle`；该 memo 标 `poisoned`，当前求值中止；其他 memo 继续。
- `Memo::get() -> T`：
  - 存活且非 poison：返回值；
  - poison 但有最后值：返回最后值，并向 diagnostics 报 `ComputedPanicked`；
  - poison 且无最后值：panic（同 owner 契约错误）；
- `Memo::try_get() -> Result<T, HandleError>`：poison/cycle/disposed 返回 `Err`，不 panic。
- binding 求值使用 `try_get`/内部 `ReadValue`；`get` 只用于组件 setup 等确定存活的上下文。
- `ReactiveError` 增加 `GraphCycle`；`ReactiveError` 与 `TurnError` 的关系见 §16.2。

#### 18.10 隐式 memo 与创建时机

- 数据位置的闭包在**挂载/结构分支挂载**时由宏降为 `memo`，owner 是所在节点/组件的 owner；不在每次求值时新建。
- 隐式 memo 的依赖由求值栈动态登记；每次重算整体替换依赖集。
- 隐式 memo 与手写 memo 走同一 `MemoCell`/`MemoCompute`，不引入第二种派生机制。
- 不得在 handler 内隐式创建；需要跨 turn 的派生值必须在 setup 或显式 `memo_in(owner, ...)` 中创建。
- `once` 不是 memo；它没有依赖、没有重算、不会因源变化更新；重挂载得到新快照。

#### 18.11 测试

必须新增：

- `delete + reinsert same business key`：旧 Field 读 Missing、旧 For 行不继承 caret/once/焦点；
- `Memo<RowSet>` 的 `shares_with` 快路径与深比较等价；
- 相等 memo 重算不标记下游；10k 行共享 memo 相等写入不进入 binding worklist；
- 三级 memo 链、菱形、跨窗口共享 memo；
- handler/memo 中创建资源被拒绝；`signal_in`/`memo_in` 显式 owner 可释放；
- memo cycle/poison 的 `get`/`try_get`/binding 最后值；
- `ChangeSet` 对不在结果内的候选行字段变化标脏 `Rows(filter)`；
- 删除行预退订后不再运行该行 memo；
- `Read::Field` 首次失败/恢复、`Show`/`For` 保持旧结构；
- 空白/相等写入的 lineage observe。

### 19. 呈现快照、delta 与内存预算

#### 19.1 SnapshotNode 必须表示文本与结构

Part I §7.1 已把 `SnapshotNode` 定义为 Element/Text 枚举；这里补齐字段与共享存储：

```rust
pub enum SnapshotNode {
    Element(SnapshotElement),
    Text(SnapshotText),
}

pub struct SnapshotText {
    pub key: PresentationKey,
    pub text: Arc<str>,
    pub revision: u64,
}

pub struct SnapshotElement {
    pub key: PresentationKey,
    pub id: NodeId,
    pub tag: &'static str,
    pub attrs: AttrSlice,          // 指向共享 attr arena 的 offset/len
    pub styles: StyleSlice,        // 指向共享 style arena
    pub edit: Option<EditId>,      // 指向共享 edit arena；TextEditState 不内联
    pub semantics: SnapshotSemantics,
    pub children: PersistentChildren,
    pub revision: u64,
}
```

- 文本节点有 `PresentationKey`，renderer 用它做 shaping/布局缓存键；元素节点同时有 `NodeId`（公开元素身份）和 `PresentationKey`（呈现身份）。
- 结构节点（组件/Show/For 容器）在快照中透明，但其子树节点保留 key；`For` 的 spacer 是普通元素，带 `role="spacer"`。
- `PresentationKey` 是 `NodeRef`（slot + generation）的公开编码；槽位复用必须换 generation，renderer 缓存按 key 失效。不得使用裸 slot 或裸数组下标。
- `SnapshotRoot` 含 `nodes`、`focus`、`appearance`、`row_bands`、`revision`、`env_revision`（只用于诊断，不参与呈现相等性）。
- **发布所有权固定**：`SnapshotRoot` 是内部数据根；唯一对外发布/持有的单位是 `PresentationSnapshot`，它包裹 `Arc<SnapshotRoot>`。`Scene::build`/`build_tree`/宿主/UIA/测试都接收 `&PresentationSnapshot`，不直接持有 `SnapshotRoot`。`PresentationSnapshot` 的 `PartialEq` 先比较 revision，再按 key 短路；`Arc::ptr_eq` 是 fast path。

```rust
pub struct SnapshotRoot {
    pub nodes: SnapshotChunks,
    pub focus: Option<PresentationKey>,
    pub appearance: Appearance,
    pub row_bands: RowBands,
    pub revision: u64,
    pub env_revision: u64, // 诊断；不参与呈现相等性
}

#[derive(Clone)]
pub struct PresentationSnapshot { root: Arc<SnapshotRoot> }
impl PresentationSnapshot {
    pub fn revision(&self) -> u64;
    pub fn root(&self) -> &SnapshotRoot;
}
```

#### 19.2 快照的共享与相等

- 每个 tree 一个 `Arc<SnapshotRoot>` 数据根，对外发布为 `PresentationSnapshot`（§19.1）；宿主、UIA、renderer、测试各自持有 `PresentationSnapshot`；旧根在最后一个引用释放时回收。
- 快照构建不执行用户闭包、不修改保留树；只读取 `BindingPatch` 的已提交结果与结构提交结果。
- 未变化子树的 chunk 和节点共享；路径复制只复制从变化节点到根的 chunk 路径。
- `PresentationSnapshot` 的相等性用于测试与 renderer 的快速路径；比较时按 `revision` 与 key 短路，不对整棵持久树做深比较。ADR-0006 的 `Eq + Send + Sync + 'static` 契约保留，但相等性语义改为“revision + 结构/属性/焦点等价”，并在 ADR 中写明。`PresentationSnapshot` 不实现 `Copy`；Clone 只增加 `Arc` 计数。
- 文本节点 `Arc<str>` 共享；文本变化只替换该节点与祖先路径。

#### 19.3 PresentationDelta

```rust
pub struct PresentationDelta {
    pub from_revision: u64, // 上次成功发布的 revision；批量提交时是累计起点
    pub to_revision: u64,
    pub changed: SmallVec<[PresentationKey; 16]>,
    pub inserted: SmallVec<[PresentationKey; 8]>,
    pub removed: SmallVec<[PresentationKey; 8]>,       // 被移除子树的全部节点
    pub removed_subtrees: SmallVec<[PresentationKey; 4]>, // 子树根，便于快速丢弃
    pub layout_roots: SmallVec<[PresentationKey; 4]>,
    pub focus_changed: bool,
    pub appearance_changed: bool,
    pub row_bands_changed: bool,
}

/// 宿主/renderer 消费的唯一发布单位；delta 为 None 表示全量根。
pub struct PresentationUpdate {
    pub snapshot: PresentationSnapshot,
    pub delta: Option<PresentationDelta>,
}
```

- `changed` 包含所有属性/文本/direct child 顺序变化的节点，以及它们的祖先路径（祖先的 `children` chunk 变化）；renderer 不需要自己找父链。
- `removed` 包含被移除子树的**每个** key；`removed_subtrees` 是同一批的根，供快速清理。子树很大时 delta 变大是实际成本，不伪装成 O(1)。
- `inserted` 包含新子树中需要在 renderer 建立缓存的节点；如果子树很大，同样计入成本。
- delta 不携带旧/新语义值；UIA 不使用 delta（§17.4）。renderer 只需知道哪些 key 变了，再读最新快照节点。

#### 19.4 delta 应用与追赶

- `applied_revision` 存在于 renderer/host 的 per-tree 视图，不在 runtime tree；runtime 只维护 `last_published_revision`。renderer 只应用 `from_revision == applied_revision` 的 delta。
- 发布 API 必须同时携带快照与 delta：`Runtime::presentation_update(tree) -> PresentationUpdate`（或宿主包装的同名入口）；`presentation_of(tree)` 只返回 `snapshot`，是给 UIA/测试的便捷入口。`Scene::build`/`build_tree` 仍只接收 `PresentationSnapshot`，delta 由宿主在构建前应用到 renderer 缓存。
- 若 delta 断档（宿主跳帧、隐藏窗口、批量提交、消费者滞后）：丢弃待应用 delta，读取最新 `PresentationSnapshot`，按 key 做一次全量重建（或按节点的 `revision` 增量比较），把 `applied_revision` 设为该 snapshot 的 revision。**全量重建是合法回退，不是错误。**
- 旧 delta 可丢弃；delta 与根同代（`to_revision == root.revision`）。不得让 delta 与根来自不同提交。
- UIA 永远走整树发布 + 相邻比较，不读 delta，因此**没有 `applied_revision`**；它只记录 `last_published_revision` 与上一棵 `AccessibilityTree` 用于相邻比较。`applied_revision` 是 renderer 专属的 delta 游标，两者不是同一概念。
- 测试必须覆盖：连续 delta、断档回退、隐藏后 show、批量 Delivery 多提交、子树删除/重插。

#### 19.5 快照构建时机

- **可见窗口且存在发布消费者**：每个有效 turn 在结算时**同步**构建 `PresentationSnapshot`（包裹新 `SnapshotRoot`）与 `PresentationUpdate`；delta 的 `from_revision` 是上次成功发布的 revision，`to_revision` 是新 snapshot revision。场景/布局仍可按需延迟。
- **隐藏窗口**：flush 与 revision 已在 turn 末同步完成，只有**快照根构建**可以只标脏；show 前或任何读取其呈现/焦点/编辑状态的入口之前，必须完成一次 `PresentationSnapshot` 构建并发布 `PresentationUpdate { snapshot, delta: None }`（完整根）。不得用“从某消费者的 applied_revision 到新根”的 delta 猜测消费者状态。
- **headless runtime**：没有宿主消费者时，可以在根构建上延迟；测试通过显式 `commit()` 或读取快照触发。延迟不得改变语义：读取前必须完成 flush 与快照构建。
- 一个 turn 内多个 commit（例如批次 Delivery）发布**从上次成功发布 revision 到最终 revision 的累计 delta**；不能安全合并时发布 `delta: None` 的完整根。中间 revision 的可见状态不丢：累计 delta 必须包含所有中间变化，或直接全量。若 UIA/renderer 需要每个 step，必须在 step 边界读取，而不是依赖 delta 流。

#### 19.6 UIA 发布

见 §17.4。摘要：整树发布 + 相邻比较；delta 不参与；焦点事件前台规则；结构事件父节点规则；隐藏/关闭清空。

#### 19.7 内存预算（按固定布局重写）

以下为 64-bit、`Option<Arc<T>>` 8 B、`Option<NodeRef>` 8 B（NonZero 编码）的前提。实现必须在 Phase 1 门禁中用 `size_of` 断言；未列出的字段不得偷偷加入。

| 类型 | 目标 | 组成与说明 |
|---|---:|---|
| `NodeRef` | 8 B | `NonZeroU64`；32-bit slot + 32-bit generation；0 保留 |
| `NodeId` | 16 B | `runtime: u32` + `NodeRef: u64` + padding |
| `RowId` | 8 B | 32-bit slot + 32-bit generation；与 NodeRef 同构，不含业务 key |
| `PresentationKey` | 8 B | `NodeRef` 的公开编码；槽位复用换 generation |
| `OwnerRef` | 8 B | 32-bit slot + 32-bit generation |
| `NodeSlot` | 64 B | `repr(C)`：3×u32 = 12 + 2×u8 = 2 + 2 B padding = 16；6×8 B 指针（5 链 + snapshot）= 48；合计 64 |
| `ElementData` | ≤96 B | tag(u16) + flags(u8) + owner(8) + 7×u32 句柄（attrs/class/inline styles/events/edit/bindings/semantics）；attrs/styles/events/edit/binding list 全部外置到 `AuxArenas` |
| `ConsumerRef` | 16 B | `NodeRef`/`SourceRef` 8 + `PartId` 2 + kind 1 + reserved 1 + padding；`PartId` 是注册的 u16 |
| `SignalCell` | 32 B | `Option<Rc<dyn Any>>` 16 + `writes: u64` 8 + flags 1 + padding |
| `MemoCell` | 48 B | `compute: Option<Rc<dyn MemoCompute>>` 16 + `value` 16 + `revision` 8 + `deps: DepListId` 4 + flags 1 + padding；deps 在独立 `MemoDepsArena`；预算上限 64 B |
| `BindingSlot<T>` | 按值类型分表，实测 | 只在 per-tree `BindingTable` 中：`ReadSlot` + `Option<T> current` + `Option<ReadFault> fault` + generation；`ElementData` 只存 `BindingListId`，不内联槽 |
| `BindingRef` / `BindingList` | 8 B / 每 part 16 B | `BindingRef` 是 `#[repr(transparent)] u64`；`BindingList` 是 `(PartId, BindingRef)` 稳定有序表，因 `BindingRef` 8 B 对齐，每项实际 16 B（2 B PartId + 6 B padding + 8 B）；由 `AuxArenas.binding_lists` 拥有 |
| 反向边 | 8 B/DepEntry + 16 B/edge | `DepEntry { first_edge: u32, len: u32 }` + 扁平 `EdgeArena`；空依赖不付 SmallVec 头 |
| 事件槽 | 16 B + 闭包 | `EventId` 索引到事件 arena；handler 捕获另计 |
| `SnapshotNode` 头 | 64–96 B | key/id/tag/attrs slice/styles slice/edit id/semantics/children/revision；attrs/styles/children/edit 全部外置；内联 `TextEditState`（88 B）会直接破坏预算 |
| `SnapshotText` | 32 B + 文本 | key + `Arc<str>` + revision |
| `RowSet` | 8 B/行 + `Arc<RowSetData>` 头 | newtype `RowSet(Arc<RowSetData>)`；`RowSetData { store: StoreId, ids: Box<[RowId]> }`；顺序是 Store 当前用户 order；共享身份投影；**O(总行数)**，单独计预算 |
| `For` 持久簿记 | O(窗口) | 只保存已挂载 `(RowId, row_index, NodeRef)` 与行带元数据；业务 key 不进表 |
| 运行时每行（典型 8 节点） | ≤4 KiB（实测门禁） | NodeSlot + payload + owner + reactive 槽；不含快照/布局 |
| 每行含快照/布局/场景 | 另表，实测 | 不与 runtime 表格混算 |

**关键修正：**

- Phase 1 必须加入编译期断言：`size_of::<Option<NodeRef>>() == 8`、`size_of::<NodeSlot>() == 64`、`size_of::<NodeId>() == 16`、`size_of::<ConsumerRef>() == 16`、`size_of::<RowId>() == 8`、`size_of::<BindingRef>() == 8`、`size_of::<(PartId, BindingRef)>() == 16`、`size_of::<MemoCell>() == 48`、`size_of::<ElementData>() <= 96`。`NodeRef`/`SourceRef` 必须是 `NonZeroU64` newtype；`NodeKindTag`/`DirtyFlags` 必须 `#[repr(u8)]`，`TreeKey` 必须 `#[repr(transparent)] u32`；`ConsumerRef` 必须用 `PartId(u16)`，不能内联带负载的 `BindingPart`。
- `NodeSlot` 只有在 `TreeKey = u32`、`DirtyFlags = u8` 时才刚好 64 B；这两个宽度必须写进类型定义，不得留给实现猜。
- `PresentationKey` 不占 `NodeSlot` 字段，由 `NodeRef` 派生；若未来需要持久 key，必须重新做预算。
- `MemoCell` 固定 48 B：compute 16 + value 16 + revision 8 + deps id 4 + flags 1 + padding；**deps 不内联**，在独立 `MemoDepsArena`。实现必须在门禁中同时报告 `memo_storage` 与 `memo_deps_storage`；不得把 `SmallVec<[DepId;4]>` 放回槽内（那会到 72 B）。
- `SnapshotNode` 的头预算是 64–96 B；加上外置 attrs/styles/children 的引用成本后，单节点典型 100–150 B。若内联 `SmallVec<[SnapshotAttr;4]>`，实测会到 ~350 B；设计必须明确外置。
- 反向边不得用 `SmallVec<[ConsumerRef;4]>` 作为每个 Dep 的空容器（空容器 72 B）；用 `DepEntry` + 扁平边 arena，空依赖 8 B。

#### 19.8 RowSet 与 O(窗口) 目标

“列表常驻内存与可见窗口成正比”必须拆成两条：

- **UI/For 持久内存**：O(窗口) —— `For` 的行元素、行 owner、绑定、事件、局部编辑状态只覆盖已挂载窗口。
- **共享身份投影**：O(总行数) —— `RowSet` 的 8 B/行，元素是 `RowId`（slot + generation），不是业务 key；`RowSetData` 头另有 `StoreId` 与 `ids` 指针。它是所有消费者共享的一份，不是每窗口复制。10k 行约 80 KB + Arc 头，可接受，但必须计入预算。

因此：

- §1/§2.1/§4.5/§4.6/§9.1/§10 Phase 1 已按“UI/For 持久内存 O(窗口)；共享 RowSet O(总行数)”表述；实现与验收必须保持这两条分开，不得用单一“O(窗口)”覆盖 RowSet。
- 10k 行内存测试同时报告 `mounted_nodes_bytes`、`for_bookkeeping_bytes`、`rowset_bytes`、`rowset_shared_count`；不得只报一个“总数”来宣称 O(窗口)。
- `For` 的完整顺序来自共享 `RowSet`；不再维护第二份全量 `BTreeMap`。ADR-0011 的“full keyed order cache”由 `RowSet` 承担，二者是同一份共享投影。`RowSet` 的顺序是 Store 当前用户顺序；业务 key 只用于 keyed 重排，不负责排序。

#### 19.9 反向边、DepId 与页回收

- `DepKey → DepId` 使用 intern 表；`DepId` 是 u32 索引，指向 `DepEntry`。
- 反向边用扁平 `EdgeArena`：`Vec<ConsumerRef>` 分页 + free list；`DepEntry { first_edge, len }` 8 B；边 16 B。
- 最后一个消费者离开时，立即清空该 `DepEntry` 的边并归还边页；`DepKey` 的 intern 条目在源释放且无消费者时移除；源仍存活但暂时无消费者时保留 intern 条目（8 B），下次重新挂接复用。
- Signal 与 Memo 释放时，既要清自己的 deps，也要清自己作为 source 的下游边（移除消费者并清空 entry）；不得只清一半。
- 新增计数器：`dep_entries_live`、`dep_entries_storage`、`consumer_edges_live`、`consumer_edges_storage`、`edge_pages`；soak 后 storage 回到页粒度。

#### 19.10 复杂度更新

| 操作 | 目标 |
|---|---|
| 单行字段更新（窗口化） | O(订阅该字段的绑定数 + 快照路径) |
| 行集投影变化 | O(总行数) 瞬时候选校验 + O(窗口) 持久 |
| 删除行 | O(该行绑定/边 + 窗口内受影响节点) 预退订 |
| 反向边写入 | O(该源消费者数)；不克隆集合 |
| 快照单节点变化 | O(log n) chunk 路径 + 祖先路径 |
| delta 断档恢复 | O(最新根可见节点) 全量重建（合法回退） |
| 10k 行滚动跨行 | O(进出窗口行 × 行内节点) |
| 文本缩放手势 | O(可见节点) 场景/布局重建；不 bump revision |
| 空 turn | O(1)；不重建快照、不重排、不绘制 |

**Phase 1：统一 NodeArena 与代际 arena**

- 元素、文本、组件、Show、For 进入统一 arena；NodeRef/NodeId/PresentationKey；父子兄弟链。
- `TreeKey=u32`、`DirtyFlags=u8`、`NodeSlot=64B`、`ElementData≤96B` 的固定布局；`PresentationKey` 由 NodeRef 派生。

#### 20.3 性能/内存门禁

必须在仓库内建立可执行门禁，而不是“CI 记录趋势”：

- **固定 runner**：至少一个标签为 `perf-windows` 的固定 Windows runner（CPU/内存/OS 记录在基线文件）；开发机数字不作为发布承诺。
- **基线文件**：`bench/baselines/<bench>.json`，包含计数、时间中位数、p50/p95、git sha、runner、字体/资产版本。

### 21. 宏与 DX 决议

#### 21.1 位置糖只按位置，不按值类型

- 闭包字面量只在 §6.2 的位置表内降为 `memo`；`on:*`、`Show fallback`、`For` 行 factory、`For key`、Children/slot、组件 prop 不降为 memo。
- `For key` 是身份投影闭包：接收 runtime 从 `ForSource.store` 解析出的 `&R`；只读该行的业务字段，不得读 Signal/Memo/Field handle、不得有副作用、不得捕获可变状态；在 RowSet 投影变化时运行；重复 key 是 typed `ReactiveError::DuplicateKey`。它不是数据位置，不生成 memo。
- `For` 行 factory 接收 `RowView<R>`，不是裸业务 key；需要响应式字段时用 `row.field::<T>(FieldId)`，需要行快照时用 `row.get()`，需要业务 key 时用 `row.key()`。
- `row-height` 是声明的静态 `Length`：必须是字面量或 `once(...)`，不得是 `Read<Length>`；动态行高不在本方案。
- 组件数据 prop 类型导向：`Read<T>`/`Once`/handle；不按闭包猜。

#### 21.2 字面量、Once 与 typed 常量

“非字面量的 `String`/`bool`/`.get()` 是编译错误”必须由宏 + 类型共同保证：

- 宏只对**语法字面量**生成 `Read::Static`；
- 公开数据位置不再提供 `From<T> for ValueSlot<T>` 的 blanket，也不提供 `String` 的隐式 Once；
- `&'static str` 字面量可以生成 `Static`；非字面量 `&str`（变量）必须 `once(...)`；
- typed 常量（`em(1.75)`、`Color::Role(...)`、`Length`）不是字面量，必须 `once(...)` 或显式 `static_` 构造；SDK 文档示例同步改为 `style:width={once(em(1.75))}`；
- `once(...)` 是显式快照；`Read::Once` 保留诊断来源；
- compile-fail 用例覆盖：裸 `String` 变量、裸 `bool` 变量、`.get()`、非字面量 `&str`、typed 常量未包 `once`。

#### 21.3 fallible handler 示例

```rust
<checkbox
    checked={completed}
    on:change={|event: &mut ChangeEvent| -> Result<(), WriteError> {
        todos.set_completed(todo, event.proposed()).finish()?;
        Ok(())
    }}
/>
```

- 含 `?` 的闭包必须显式写返回类型；`HandlerOutcome` 不能修复 Rust 的返回类型推断。
- 零参数 handler 不能控制 flow；需要 consume/prevent 时写一参数。
- 命名函数按一参数；零参数命名函数写 `|| f()`。

#### 21.4 窗口 API、focusable 与 type=submit

- `WindowCtx::on_keydown`、`on_drop`、`on_close`、`on_command`、`on_menu_state` 在 factory setup 注册；随 activation 释放。
- `focusable` 是语义属性：`focusable={true/false}` 或 `focusable`（true）；映射到 UIA `IsKeyboardFocusable`；自定义控件必须显式声明。
- `type="submit"` 是 button 的显式行为：默认 `button`；只有 `type="submit"` 且在 form 内才提交；现有“type 是保留呈现属性”的语法参考需要修订。
- `<form>` 是 intrinsic：提供 `Submit` 目标与 UIA Group；没有浏览器式导航默认。
- 窗口级 `on:drop` 不存在；写 `<view on:drop>` 是编译错误并提示 `WindowCtx::on_drop`。

#### 21.5 组件与 Read prop

- 组件挂载一次；props 是挂载时值或 `Read<T>` handle。父组件不重跑，因此 prop 句柄在子组件生命周期内固定；需要替换 prop 时由父级 `Show`/`For` 重挂载子组件。
- `Read<T>` prop 的读取：
  - `read_once()?`：挂载快照；
  - `bind()`：可失败绑定；
  - `try_get()`：显式处理 fault。
- 组件不得把 `Read<T>` 当普通值捕获；捕获的是身份，不是值。

#### 21.6 常见任务表更新

| 目标 | 写法 |
|---|---|
| 按钮点击 | `<button on:click={\|\| save()}>"Save"</button>` |
| 行点击 | `<view on:click={\|\| select(row)}> ... </view>` |
| 行内删除不触发行 | `<button on:click={\|\| delete(row)}>` |
| 观察所有点击 | 根容器 `on:click_capture={\|e\| trace(e.target())}` |
