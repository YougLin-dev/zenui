# 界面与组件

本页介绍目标 SDK 的使用方式。`view!`、`MountPlan`、组件宏和目标数据原语属于正在开发的接口，不是对当前 `zenui-core` 导出函数的说明。

## 组件是挂载单元

组件在挂载时执行一次，返回 `MountResult<MountPlan>`。它负责注册状态、派生值和监听，再返回界面描述。

字段更新不会重新执行整个组件。列表重排可以保留相同 key 的控件身份，因此 caret、selection、IME composition 等本地状态不必跟着数据移动而重置。

一个组件的骨架如下：

```rust
#[component]
fn FilterButton(
    current: Signal<Filter>,
    value: Filter,
    label: &'static str,
) -> MountResult<MountPlan> {
    let selected = memo(move || current.get() == value);

    view! {
        <button
            class="rounded-md bg-zinc-100 px-3 py-1 aria-pressed:bg-blue-600"
            aria:pressed={selected}
            on:click={move || current.set(value)}
        >{label}</button>
    }
}
```

`MountPlan` 是待提交的描述，不是已经创建的 OS 控件，也不是可独立重渲染的虚拟节点。`?` 仍然是普通 Rust 语义：读取失败时不会提交半个组件。

## view! 只安排结构

`view!` 中的小写标签对应 ZenUI 注册的 intrinsic，不等同于浏览器 element。PascalCase 名称对应 Rust 组件，props 按函数签名传递。

事件、具名 slot 和 branch factory 可以是 closure；普通数据位则是以下几类：

| 写法 | 含义 |
| --- | --- |
| `{handle}` | 从对应源读取，跟随更新 |
| `"text"` | 静态文本或静态属性值 |
| `{once(value)}` | 此次挂载使用的明确的一次性值 |

例如：

```rust
let title = store.title(id).read_once()?;
let remaining_txt = memo(move || format!("{} remaining", remaining.get()));

view! {
    <view>
        <text>{remaining_txt}</text>
        <text>{once(title)}</text>
    </view>
}
```

`once` 不是全局 memo，也不保证整个应用只计算一次。组件因结构变化重新挂载时可以重新求值。

属性拥有自己的类型和同步规则。文本读取 String、checkbox 同步 bool、TextInput 处理编辑 epoch；相同的 `{handle}` 写法不意味着它们使用同一个万能绑定算法。

## 派生值留在 setup

比较、格式化、布尔推导和模型查询写在 `view!` 之外，用 `memo` 创建身份稳定的派生值：

```rust
let visible = memo(move || todos.rows(filter.get()));
let cannot_add = memo(move || draft.with(|title| title.trim().is_empty()));
```

这样可以直接阅读状态来自哪里，也不必在树中重复计算或引入额外的模板表达式。

Store 中的查询同样拥有稳定身份。不要在每次 Memo 计算时新建 Memo 或订阅，否则图节点会随派生流程不断增加。

## 条件和行

`Show` 挂载与卸载分支，而不是用不可见样式代替：

```rust
<Show when={cannot_add} fallback={move || view! { <EditTools /> }}>
    <EmptyDraftHelp />
</Show>
```

分支切换释放对应 Owner、订阅和临时资源；再次进入时创建新一代子控件。不要保留已卸载分支的执行任务或事件回调，并期待它们作用于新分支。

`For` 使用稳定 key 管理控件：

```rust
<For each={visible} key={|row: &TodoRow| row.id}>
    {move |row: TodoRow| view! {
        <TodoItem todo={row} store={todos} />
    }}
</For>
```

key 借用当前投影行完成比较；row factory 接收拥有自己身份的行。相同 key 的重排保留控件，key 消失只卸载对应界面，不会默认删除业务实体。

虚拟列表使用同一条原则。滚出可见区域时，可以缓存布局和绘制资源；重新物化其他 key 时不能继承旧行的编辑状态、IME、`once` 文本或任务 owner。

## Children 与具名 slot

slot 接收惰性 factory，而非提前构建好的另一棵结构：

```rust
#[component]
fn Panel(
    title: &'static str,
    actions: impl Into<Children>,
    children: impl Into<Children>,
) -> MountResult<MountPlan> {
    let actions = actions.into();
    let children = children.into();

    view! {
        <view class="rounded-lg bg-white p-3">
            <view class="flex justify-between">
                <text>{title}</text>
                <view>{actions}</view>
            </view>
            <view>{children}</view>
        </view>
    }
}
```

普通 Panel 的 children 在挂载时消费；反复切换的 `Show.fallback` 则需要可重复构造 branch。两者在控件描述内部具有不同调用要求，不能把一个 `FnOnce` 当作可反复执行的分支。

## 错误与属性

事件返回 `()`、`WriteOp` 或约定的 `Result`，由控件或命令入口消费。它们不会被静默丢弃。

错误的显示应与控件剩余生命周期一致：局部挂载失败交给仍然存活的父级错误或窗口出口；app、tray 和 session 的错误需要应用自己的记录与展示路径。错误报告不能代替事务取消、任务取消或窗口关闭状态机。

## 不能写成普通数据的表达式

以下几种写法有不同的行为，不伪装为同一类：

- `{count.get()}` 是调用当下的值，不会自动变成订阅；
- `{move || count.get()}` 是 factory / closure，普通数据位不额外接受它；
- `{if ready { a } else { b }}` 是结构分支之外的 Rust 表达式，不使用它代替 `Show`；
- `{dynamic_class}` 不是编译期 class token；
- `style:width="12px"` 不是 typed length，使用 `px(12.0)`；
- `.title(move || title.get())` 不要求宿主重算 closure，传入 `Memo<String>` 等 handle。
