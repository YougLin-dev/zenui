# 界面与组件

本页介绍目标 SDK 的使用方式。`view!`、`MountPlan`、组件宏和目标数据原语属于正在开发的接口，不是对当前 `zenui-core` 导出函数的说明。标签、属性、事件与组件 props 的完整词表见 [视图语法参考](视图语法参考.md)。

## 组件是挂载单元

组件在挂载时执行一次，返回 `MountResult<MountPlan>`。它负责注册状态、派生值和监听，再返回界面描述。

字段更新不会重新执行整个组件。列表重排可以保留相同 key 的控件身份，因此 caret、selection、IME composition 等本地状态不必跟着数据移动而重置。

一个组件的骨架如下：

```rust
#[component]
fn FilterButton(
    current: Signal<Filter>,
    value: Filter,
    label: &'static str,
) -> MountResult<MountPlan> {
    let selected = memo(move || current.get() == value);

    view! {
        <button
            class="rounded-md bg-control px-3 py-1"
            aria:pressed={selected}
            on:click={move || current.set(value)}
        >{label}</button>
    }
}
```

`MountPlan` 是待提交的描述，不持有已经呈现的界面，也不是可独立重渲染的虚拟节点。`?` 仍然是普通 Rust 语义：挂载失败会取消整个拟议组件，并清理 setup 中创建的订阅、事件、任务和未发布节点，已存活的兄弟组件不受影响。

## view! 只安排结构

`view!` 中的小写标签对应 ZenUI 注册的 intrinsic，不等同于浏览器 element。PascalCase 名称对应 Rust 组件，props 按函数签名传递。

事件、具名 slot 和 branch factory 可以是 closure；普通数据位则是以下几类：

| 写法 | 含义 |
| --- | --- |
| `{handle}` | 从对应源读取，跟随更新 |
| `"text"` | 静态文本或静态属性值 |
| `{once(value)}` | 此次挂载使用的明确的一次性值 |

例如：

```rust
let title = store.title(id).read_once()?;
let remaining_txt = memo(move || format!("{} remaining", remaining.get()));

view! {
    <view>
        <text>{remaining_txt}</text>
        <text>{once(title)}</text>
    </view>
}
```

`once` 不是全局 memo，也不保证整个应用只计算一次。组件因结构变化重新挂载时可以重新求值。

属性拥有自己的类型和同步规则。文本读取 `String`；checkbox 同步 `bool` 语义，字段读取可以是 `Result<bool, FieldError>`，失效读取不当作 `false`；TextInput 处理编辑 revision 与 origin。相同的 `{handle}` 写法不意味着它们使用同一个万能绑定算法。`button`、`checkbox` 与 `text-input` 天生可聚焦；任意元素注册 `on:focus` 或 `on:blur` 后进入焦点顺序，只有 `on:click` 不会让普通容器可聚焦。`button type="submit"` 点击提交最近的 `form` 一次；同一声明里的其它 `type` 值只是呈现属性。

## 派生值留在 setup

比较、格式化、布尔推导和模型查询写在 `view!` 之外，用 `memo` 创建身份稳定的派生值：

```rust
let visible = memo(move || todos.rows(filter.get()));
let cannot_add = memo(move || draft.with(|title| title.trim().is_empty()));
let has_draft = memo(move || !cannot_add.get());
```

这样可以直接阅读状态来自哪里，也不必在树中重复计算或引入额外的模板表达式。

Store 中的查询同样拥有稳定身份。Memo、查询与订阅在组件 setup 或所属作用域中创建，使派生节点保持固定身份。

## 条件和行

`Show` 挂载与卸载分支，而不是用不可见样式代替：

```rust
<Show when={has_draft} fallback={move || view! { <EmptyDraftHelp /> }}>
    <EditTools />
</Show>
```

分支切换释放对应 Owner、订阅和局部资源；再次进入时创建新一代子控件。已卸载分支结束时，其执行任务与事件交付随之失效。需要在 owner 结束时收尾的资源（例如保存草稿）用 [`on_cleanup`](数据与更新.md#资源回收与-cleanup) 登记；回调按逆序执行，可以读取仍存活的 Signal/Memo，但不能写入或创建资源。

`For` 使用稳定 key 管理控件：

```rust
<For each={visible} store={todos} key={|row: &TodoRow| row.id}>
    {move |row: RowView<TodoRow>| view! {
        <TodoItem todo={row.key()} store={todos} />
    }}
</For>
```

`For` 的 key selector 借用当前行的身份投影，row factory 接收 `RowView`：`id()` 是行身份，`key()` 是业务键，`get()` 是挂载快照，`field::<T>(FieldId)` 按本行身份建立响应式字段句柄（读取与失效语义见[通用行字段](数据与更新.md#通用行字段)）。`each` 给出 `Store` 构造的行集时必须同时给出 `store`；`Rows` 投影自带 store，可以单独传入。业务模型拥有字段数据，界面按行身份保留控件、Owner 与本地编辑状态；过滤或消失只卸载界面，不删除模型。key 在发布结构更新前完成检查。

虚拟列表可以缓存布局和绘制资源；重新物化的业务 key 使用自己的 Owner、编辑状态和 `once` 值，不能继承另一行的本地状态。

### 窗口化 For（row-height）

未声明 `row-height` 的 `For` 会全量挂载每一行，节点、布局与场景成本随总行数线性增长；超过 1000 行时运行时记录一次 [`RuntimeDiagnostic::NonWindowedFor`]，由下一次 `Runtime::refresh()` 的 `RefreshReport::diagnostics()` 交付。长列表应声明 `row-height` 并让宿主提供行窗口。

声明 `row-height` 的 `For` 只挂载宿主行窗口内的行（[ADR-0011](../adr/0011-windowed-for-mounting.md)）：

```rust
<view class="gap-0">
    <For each={visible} store={todos} key={|row: &TodoRow| row.id} row-height={em(2.5)}>
        {move |row: RowView<TodoRow>| view! {
            <view style:height={em(2.5)}>
                <TodoItem todo={row.key()} todos={todos} />
            </view>
        }}
    </For>
</view>
```

- `row-height` 是每行的外层高度，`For` 的父容器必须是零间距纵向布局（`class="gap-0"`）；每一行必须恰好占满这个高度。示例用 `em(2.5)`，行高随辅助功能文本缩放；固定 `px` 行高不会缩放，文本放大后可能裁剪。
- 运行时在已挂载行两侧插入上、下两个 `role="spacer"` 的 `view`：上 spacer 为 `first_row × row-height`，下 spacer 为 `(total_rows − first_row − mounted_rows) × row-height`。内容范围、滚动条与显露始终按完整行数计算。
- 快照只包含已挂载行与两个 spacer；`PresentationSnapshot::row_bands()` 给出 `SnapshotRowBand`（band key、顶端 spacer、行高、起始行、总行数），`Scene::row_bands()` 给出解析后的行带几何。
- 宿主把每个行带的几何、已应用偏移与视口高度换算成 `(first, count)`，作为一批调用 `Runtime::set_row_windows`；同一批在一个原子结构 turn 里预校验并应用，任一行带失效、属于其他窗口或重复出现时整批不应用，任一行工厂失败时整批回滚到旧窗口。运行时是唯一挂载或卸载行的一方。窗口外的行没有 Scene 元素与 Node ID，旧 ID 报告 `Stale`。
- 行重新进入窗口时重新挂载：新 Node ID、新 Owner、重新求值的 `once` 与新的本地编辑状态。仍在窗口内的行保持 Node ID、Owner、caret、selection、组合与历史。
- 聚焦行在窗口外一行以内时窗口自动扩大一行，caret 与组合保留；更远时宿主先 blur 并取消组合，运行时卸载该行。Tab 只遍历已挂载行，到边界后离开列表。
- 没有宿主窗口时（headless）从第 0 行起挂载固定的默认窗口；Host 通过 `set_row_windows` 校正。
- 重排、过滤与删除仍按完整 keyed 顺序计算，重复键检查不变；key 只应依赖行身份，行集投影未变时不会重新求值。

## 呈现快照与 Node ID

`Runtime::presentation()` 返回最近一次提交界面的只读 presentation snapshot：每个已提交元素的稳定 `NodeId`、tag、已解析的呈现属性、编译期 class 解析出的类型化样式声明、文本、焦点、文本输入的 caret/selection/preedit 与组合替换区间，以及应用外观，并按已提交顺序给出子节点。它不包含布局几何、闭包或平台句柄，生成时也不执行用户闭包。快照是不可变、结构共享的呈现单位：同一树 revision 的重复读取返回共享同一数据根的 `PresentationSnapshot`，`Clone` 只增加引用计数；相等性先比较 revision 与根身份，再退化到内容。元素与文本节点都携带跨快照稳定的 `PresentationKey`，`PresentationUpdate` 用它们发布累计 delta；UIA 不消费 delta，而是整树发布并在相邻发布之间比较。外观属于已提交状态：切换主题会推进 revision、改变快照相等性并触发重绘，但不会重建界面树。

```rust
let snapshot = app.presentation()?;
for element in snapshot.elements() {
    println!("{:?} {}", element.id(), element.tag());
}
```

`Show` 与 `For` 只出现在快照中的已提交分支和行。仍然挂载的 Node ID 在重排与过滤期间保持不变；重新挂载的元素获得新 ID。`Runtime::node_status()` 区分存活（`Live`）、已卸载（`Stale`）与从未分配（`Unknown`）的 ID。

后端按 Node ID 派发：`click_node`、`keydown_node`、`change_node`、`submit_node`、`focus_node`、`blur_node`，组合的 `compose_start_node`、`compose_update_node`、`compose_commit_node`、`compose_cancel_node`，以及文本编辑的 `insert_text_node`、`backspace_node`、`delete_forward_node`、`set_caret_node`、`set_selection_node`、`select_all_node`。派发只使用给出的身份：未知、已卸载、类型不匹配或状态冲突的 ID 返回显式 `DispatchError`，不会回退到 label、内部下标或相邻元素；`blur_node` 只清除该元素自己的焦点。按 label 触发的命令仍是测试助手；除整值 `input` 与无事件的 `set_caret` 外，它们解析到同一个 Node ID 后走同一条派发路径。

## Children 与具名 slot

slot 接收惰性 factory，而非提前构建好的另一棵结构：

```rust
#[component]
fn Panel(
    title: &'static str,
    actions: impl Into<ChildrenFactory>,
    children: impl Into<Children>,
) -> MountResult<MountPlan> {
    let actions = actions.into();
    let children = children.into();

    view! {
        <view class="rounded-lg bg-surface p-3">
            <view class="flex-row justify-between">
                <text>{title}</text>
                <view>{actions}</view>
            </view>
            <view>{children}</view>
        </view>
    }
}
```

普通位置在挂载时消费一次 `Children`；具名 slot 由自己的 `ChildrenFactory` 类型定义，可以在该组件的挂载过程中按需构造其内容。`Show` 中反复进入的分支使用可重复 factory。工厂类型区分一次消费与重复构造，不允许普通数据闭包混入这里。

组件签名决定必需 slot、可选 slot 与位置 children 的数量。重复的具名 slot、额外位置 children、缺少必需内容和不受支持的展开在编译期报告；未进入分支不会执行其 factory。

## 错误与属性

事件返回 `()`、`WriteOp` 或约定的 `Result`，由控件或命令入口消费。它们不会被静默丢弃。

错误的显示由相应的存活 Owner 承担：局部挂载失败交给仍存活的父级错误或窗口出口；app、tray 和 session 使用各自的错误记录与展示路径。错误报告与事务取消、任务取消和窗口关闭分别处理。

## 不同数据位置的语义

以下几种写法有不同的行为，不伪装为同一类：

- `{count.get()}` 是调用当下的值，不会自动变成订阅；
- `{move || count.get()}` 是 factory / closure，普通数据位不额外接受它；
- `{if ready { a } else { b }}` 是结构分支之外的 Rust 表达式，不使用它代替 `Show`；
- `{dynamic_class}` 不是编译期 class token；
- `style:width="12px"` 不是 typed length，使用 `px(12.0)`；
- 具名 `.title(...)` 接收 `Memo<String>` 或该属性声明类型的 handle。

## 属性类型与诊断

ZenUI 注册的每个 intrinsic 和组件声明属性来源、事件 payload、回调结果、slot 与语义字段。这些声明驱动 `view!`、typed 调用和错误定位，同一做法不需调用方引入内部支持类型。

未知 token、错误属性类型、错误事件 payload 与重复或缺少 slot 给出具体诊断，并标记相应字面量或实参。class 内部的字符区间无法准确映射到 `proc_macro` span 时，退回整个字面量加上 token 字符范围，不虚构精确子 span。

class 词表当前覆盖布局、绘制与文本：padding、gap、flex 方向、换行（`flex-wrap`）与对齐、`w-full`、`flex-1`；语义颜色（`bg-*`、`text-*`、`border-*`）、`border`、`rounded-*` 与 `opacity-*`；`text-sm|base|lg` 与 `font-normal|semibold`。语义颜色由调色板解析，圆角只影响绘制。条件变体 `dark:`、`hover:`、`focus:`、`focus-visible:`、`active:`、`disabled:`、`checked:`、`aria-pressed:` 从已提交状态、应用外观或宿主瞬态选择绘制声明；状态变体只能设置绘制属性（本实现的 `border` 只改变描边，不参与布局，因此也属于绘制属性）。尚未登记的 token 在展开期报错，不会静默忽略。

`style:background`、`style:color`、`style:border-color`、`style:opacity`、`style:width` 与 `style:height` 接受类型化值，可直接给值或给 `Once`、`Signal`、`Memo`；`px()` 与 `em()` 构造长度，`Opacity::percent()` 构造不透明度，`em` 按元素字号换算。inline 声明覆盖同属性的 class 声明与状态变体，未知 `style:` 属性与错误的值类型是编译错误。`style:height` 是窗口化 `For` 行槽的显式高度来源；固定高度行用它把各行钉在声明的 `row-height` 上。
