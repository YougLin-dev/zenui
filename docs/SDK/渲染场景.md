# 渲染场景

`zenui-render` 是平台无关的场景 seam：输入 presentation snapshot 与 viewport，输出绝对逻辑几何、文本 run、命中测试和本地编辑装饰。它不依赖 GPU、Win32，也不读取运行时内部。

## 输入与输出

- `Viewport` 携带逻辑宽高与 Window scale。布局始终使用逻辑像素；scale 只随场景交给 surface 后端，不改变几何。
- 发布单位是 `PresentationUpdate { snapshot, delta: Option<PresentationDelta> }`（`Runtime::presentation_update` / `presentation_update_of`）。`zenui-render::PresentationView` 持有当前根与 `applied_revision`：只有 `from_revision == applied_revision` 且与快照同代的 delta 被接受，断档、缺失或不同代时丢弃 delta 并按最新根全量重建。delta 只给出变化 `PresentationKey`，场景始终从发布根构建；UIA 不消费 delta。契约见 [ADR-0026](../adr/0026-published-presentation-updates-and-deltas.md)。
- `class` 字面量在 `view!` 展开期解析为类型化声明，经 `SnapshotElement::styles()` 以源码顺序到达场景；简写已展开到长手属性。`Scene::build` 在 intrinsic 默认样式之上应用这些声明。
- `SceneElement::resolved_style()` 给出 class 解析后的绘制值：语义颜色角色或字面量、边框宽度、圆角、元素不透明度、字号与字重。颜色保留角色形式，直到后端按当前调色板解析。字号与字重同时进入文本整形、测量与 caret 几何；`SceneEnv::text_scale_percent` 会在声明解析后放大最终字号。
- 快照携带应用外观；`dark:` 声明按它选择。后端据此选取 `RenderPalette::light()` 或 `RenderPalette::dark()`，语义颜色角色在两个调色板中含义相同。系统高对比度开启时，宿主改用 `RenderPalette::high_contrast(HighContrastColors)`，覆盖应用明暗外观的角色颜色；显式 `Color::Literal` 不重映射。
- 条件声明从该元素的已提交状态、`SceneEnv` 或 `InteractionPaths` 选择：hover、焦点、可见焦点、按下瞬态、禁用、勾选与 `aria:pressed`。`hover:`/`active:` 对 `InteractionPaths` 中“最深命中节点 → 根”的路径内任意元素成立，内建 hover/pressed 视觉只落在最深节点；路径为空时回退到 `SceneEnv::hovered/pressed` 单节点。同一属性被多条活动声明设置时，条件 rank 高者胜出，相同 rank 用更晚的源码顺序。
- `SnapshotElement::styles()` 中 class 声明保持源码顺序，inline 声明附加在其后，由 `origin` 区分。inline 声明以 `StyleOrigin::Inline` 到达，总是覆盖同属性的 class 声明与状态变体。`px` 长度按逻辑点解析；`em` 按元素解析后的字号解析，未声明字号的元素使用 14 点默认值。文本缩放只放大字号与由它派生的 `em` 几何，固定 `px` 仍是逻辑点。
- `Scene::build` 用默认环境与空路径构建；`Scene::build_with(snapshot, viewport, &SceneEnv, &InteractionPaths)` 接受宿主拥有的键盘焦点模态、滚动偏移、文本缩放、高对比度与交互路径；`Scene::build_cached(snapshot, viewport, &SceneEnv, &InteractionPaths, &mut SceneCache)` 复用文本布局缓存。`SceneEnv` 保持 `Copy + Eq`，路径用 `Arc<[NodeId]>` 放在独立的 `InteractionPaths`。`Scene::cache_key()` 返回 `SceneKey`：快照 revision、`SceneEnv::env_generation` 与 `InteractionPaths::generation`；外观走快照 revision，系统偏好/DPI/滚动/焦点 modality 走环境代际，hover/press/focus 路径变化走交互代际。`SceneEnv::with_text_scale_percent(u16)` 的有效范围是 100–225，越界回退 100；默认 100。`SceneEnv::with_scroll_offset(i32)` 是每 activation 的整页逻辑像素偏移，默认 0，正值让内容上移；场景把它夹到 `[0, max]`，实际值由 `Scene::scroll_offset()` 报告。`Scene::max_scroll_offset() = max(0, floor(content_extent.height - viewport.height))`，内容不足时为零；`Scene::content_extent()` 是平移前的内容范围，宽度等于视口宽度、高度不小于视口高度。平移只在布局后应用一次：元素 rect、glyph、caret、selection、preedit、`hit_test` 与滚动条共享同一份已平移几何，视口矩形是裁剪与命中的权威边界。偏移不是快照属性，不改变 Node ID 或快照相等性。契约见 [ADR-0010](../adr/0010-scroll-is-presentation-state.md)、[ADR-0006](../adr/0006-presentation-transients-and-style-resolution.md)。
- `Scene::build` 每次做一次完整 Taffy 重排，Node ID 原样保留。场景不是第二棵保留树。
- `Scene::elements()` 按绘制顺序（先序）列出已提交元素；`Scene::node(id)` 按 Node ID 查找。离屏元素保留在列表与 Node 查询中，几何不变。
- 窗口化 `For` 的快照携带 `SnapshotRowBand` 元数据（band key、顶端 spacer Node ID、声明行高、起始行、总行数），并只提交已挂载行与两个 `role="spacer"` 的 `view`。spacer 用 inline `Height` 声明占住窗口外的行范围，因此内容范围恒为 `总行数 × 行高`，与挂载窗口无关；零高 spacer 是合法的已提交元素。
- `Scene::row_bands()` 按呈现顺序给出解析后的行带几何：内容顶端（不含滚动偏移）、逻辑行高、当前起始行与总行数。宿主据此把已应用偏移与视口高度换算成行窗口；场景本身不挂载或卸载行。行带外没有元素，命中落在对应 spacer 上（`Visual::Container`）。
- `Scene::visible_elements()` 只按绘制顺序给出与视口相交的元素；场景构建时算好这份索引，GPU 绘制与 `hit_test` 都只遍历它，像素与全量遍历一致。
- `Scene::hit_test(point)` 从最高层向下命中，使用半开区间，返回最上层的 Node ID；视口内的点只可能落在可见索引的元素上，结果与全量反向扫描一致。
- `Scene::scrollbar()` 从 viewport、内容范围、已应用偏移与最大偏移推导覆盖层滚动条，返回 `Scrollbar` 的轨道与 thumb 矩形；内容能够滚动、轨道至少 24 逻辑点高且 thumb 短于轨道时才存在。thumb 高度按 viewport/content 比例缩放且最小 24 逻辑点，位置按已应用偏移落在剩余轨道上；轨道位于视口右缘内侧、不预留布局空间，也不新增元素或 Node ID。`Scrollbar::hit(point)` 供宿主在元素命中之前取得优先权；`Scene::hit_test` 本身不变。
- 每个元素的 `rect()` 是绝对逻辑矩形；文本 run 携带字体、字号、normalized coords、baseline 与绝对 glyph 位置。
- `Scene::decorations()` 给出 caret、selection 与 preedit underline；caret 只为聚焦输入生成，`Scene::caret(id)` 取它的矩形；`SceneElement::caret_at_value` 取某个值偏移处的 caret，组合窗口用它对齐 preedit 起点。`Scene::set_caret_visible` / `Scene::caret_visible` 只控制 caret 是否绘制，不改变几何查询。

## 内建视觉

场景只理解以下 intrinsic；其他 tag 返回 `UnsupportedTag`：

| tag | 视觉与布局 |
| --- | --- |
| `view` | 容器；默认纵向，`role="main"` 增加 16 内边距，`role="group"` / `"toolbar"` / `"listitem"` 改为横向；`role="spacer"` 是窗口化 `For` 的零间距占位容器 |
| `form` | 横向容器，行间距 8 |
| `text` | 文本容器；内容来自直接文本子节点 |
| `button` | 横向居中、内边距、最小高度 24；`aria:pressed` 进入 `Visual::Button` |
| `checkbox` | 16×16 方块；`checked` 进入 `Visual::Checkbox` |
| `text-input` | 带边框和内边距的输入盒，最小 80×24，在行内可伸展 |

默认缓存使用系统 sans-serif、字号 14、行高 1.35。Parley 负责 Latin 与 CJK 的整形与字体回退；场景只做 shaping，glifo/vello 的栅格化留在 GPU 阶段，使用 `TextRun` 携带的字体与 glyph 数据。根元素至少与 viewport 的逻辑高度一致，因此纯高度变化也会重排。

## 文本资产

- `SceneCache::new()` 沿用系统字体集合；`SceneCache::with_text_assets(TextAssets)` 注册应用字体并在构造期校验。缓存持有资产，`Scene::build_cached` 复用它。
- `TextAssets::new(主家族)` 后接 `with_font(FontAsset::new(bytes))`、`with_fallback_family(name)`、`with_system_fallback(bool)` 与 `with_dictionary_provider(...)`。家族按主家族与回退声明的顺序组成 `FontFamily::List`。
- 系统回退默认关闭：集合只含配置字体，已覆盖的文本不会改用机器字体。开启后系统家族进入集合，可按同一列表与 Parley 的回退选择服务未覆盖的文本。
- 字体字节保存在内存中；文件读取、`include_bytes!` 与打包由应用决定。资产对缓存不可变，换字体需要构造新缓存。
- 分词语料见 [ADR-0020](../adr/0020-application-segmentation-data.md)：provider 替换编译进二进制的 ICU4X 词典，需覆盖应用用到的复杂脚本并与 Parley 的 `icu_segmenter` 版本兼容。
- Windows 宿主通过 `HostConfig::with_text_assets` 接受同一份资产；`Host::open` 在创建窗口前构造缓存，失败返回 `HostError::TextAssets`，不产生 HWND（[窗口与任务](窗口与任务.md)）。

## 属性与本地编辑状态

`value`、`checked`、`disabled`、`aria:pressed`、`role` 参与几何或视觉；`aria:label`、`type`、`id` 是接受的语义属性，不改变几何与绘制。`class` 不是呈现属性：它由 `view!` 编译为类型化声明，正常路径不会出现在快照属性里。其他属性——包括手工构造快照里的原始 `class`、`style:*` 与尚未实现的 `placeholder`——返回 `UnsupportedAttribute`，不会被静默丢弃。

文本输入按 `value` 绘制；组合期间按 `TextEditState::composition` 给出的区间用 preedit 替换该段文本。caret 与 selection 的字符偏移先换算成 UTF-8 字节，再由 Parley 给出几何。折叠的 selection 不产生高亮；preedit 在自己的范围下方画 1 逻辑像素下划线。caret 几何来自聚焦输入的本地编辑状态，未聚焦输入不生成 caret 装饰；GPU 是否绘制由 `Scene::caret_visible` 决定，宿主在闪烁或组合期间把它设为 false，几何查询保持可用。caret 是选择的活动端，`TextEditState::anchor` 是固定端；Shift 扩展时只移动活动端。

## 明确错误

`SceneError` 区分：

- `InvalidViewport`：非有限或负尺寸，或非正 scale；
- `UnsupportedTag`：没有内建视觉的元素；
- `UnsupportedAttribute`：场景 seam 不理解的属性；
- `UnsupportedStyle`：属性与取值不匹配、场景无法应用的样式声明；
- `UnsupportedContent`：`checkbox` 或 `text-input` 带有子节点；
- `BareRootText`：顶层裸文本没有 Node ID，不能成为场景元素；
- `Layout`：Taffy 无法完成布局。

场景构建不 panic，也不忽略未知输入。`TextAssetError` 由 `SceneCache::with_text_assets` 在缓存构造期返回，区分没有字体、空字节、非字体容器、没有可用家族、未注册的主家族与回退家族；错误不会推迟到绘制。

## GPU 渲染层

`GpuRenderer` 把场景通过 `vello_gpu` 与 wgpu 画进任意 `TextureView`。`GpuContext::new()` 请求默认适配器与设备；没有可用适配器时返回 `RenderError::NoAdapter`，设备创建失败返回 `NoDevice`，不会 panic。

- `RenderTargetConfig` 声明目标视图的物理像素尺寸与格式，只接受 `Bgra8Unorm` 与 `Bgra8UnormSrgb`；视图必须与配置一致。
- 渲染时把逻辑矩形与 glyph 位置乘以 `Scene::viewport().scale()`，字号同样缩放；逻辑布局本身不变。
- `RenderPalette` 提供容器、控件、文本、边框、强调色、危险色、悬停/按下变体、selection、caret 与滚动条的颜色；`bg-*`、`text-*`、`border-*` 角色按这些字段解析。
- `HighContrastColors` 承载 Windows 高对比度主题的窗口、文本、按钮、highlight、灰文本与边框颜色；`RenderPalette::high_contrast` 把它们映射到语义角色。宿主只在偏好开启时选择这个调色板；selection 保留 80 alpha 的 highlight 覆盖，`danger` 与 `accent` 共用 highlight。契约与角色表见 [ADR-0022](../adr/0022-system-preferences.md)。
- 滚动条覆盖层画在内容与 caret 之后：轨道与 thumb 使用 `Scene::scrollbar()` 的同一份几何，轨道、thumb 各自取 `scrollbar_track` 与 `scrollbar_thumb`，圆角 4 逻辑点。内容不溢出时不画。
- 后端按 `ResolvedStyle` 绘制每个元素自己的背景、文本色、边框色、圆角与不透明度；未声明的属性回落到 intrinsic 视觉与调色板，控件内建视觉按 hover/pressed/disabled 选择 `control_hover`、`control_pressed`、`accent_hover`、`accent_pressed` 与 `text_disabled` 等字段。圆角只影响填充与描边，不裁剪子节点，也不改变命中测试与 caret 几何；不透明度只作用于该元素自身的绘制。文本通过 glifo 的 glyph run 绘制；caret、selection 与 preedit 下划线按场景装饰绘制。
- 调色板分量按 sRGB 解释。`Bgra8Unorm` 目标原样写出这些字节；`Bgra8UnormSrgb` 会再应用一次传输编码，中间调因此变亮（离屏测试记录了 128 → 约 187）。宿主应优先请求非 sRGB 视图；若只能拿到 sRGB surface，需要显式的转换或 blit，而不是直接在渲染器里猜测。
- 离屏测试创建 wgpu 适配器、读回像素并覆盖两种格式；没有适配器的环境（例如缺少软件 Vulkan 的 Linux runner）跳过像素测试，适配器错误本身仍是显式 `RenderError`。
