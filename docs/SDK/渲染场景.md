# 渲染场景

`zenui-render` 是平台无关的场景 seam：输入 presentation snapshot 与 viewport，输出绝对逻辑几何、文本 run、命中测试和本地编辑装饰。它不依赖 GPU、Win32，也不读取运行时内部。

## 输入与输出

- `Viewport` 携带逻辑宽高与 Window scale。布局始终使用逻辑像素；scale 只随场景交给 surface 后端，不改变几何。
- `class` 字面量在 `view!` 展开期解析为类型化声明，经 `SnapshotElement::styles()` 以源码顺序到达场景；简写已展开到长手属性。`Scene::build` 在 intrinsic 默认样式之上应用这些声明。
- `SceneElement::resolved_style()` 给出 class 解析后的绘制值：语义颜色角色或字面量、边框宽度、圆角与元素不透明度。颜色保留角色形式，直到后端按当前调色板解析。
- 条件声明从该元素的已提交状态选择：焦点、禁用、勾选与 `aria:pressed`。同一属性被多条活动声明设置时，条件 rank 高者胜出，相同 rank 用更晚的源码顺序。
- `Scene::build` 每次做一次完整 Taffy 重排，Node ID 原样保留。场景不是第二棵保留树。
- `Scene::elements()` 按绘制顺序（先序）列出已提交元素；`Scene::node(id)` 按 Node ID 查找。
- `Scene::hit_test(point)` 从最高层向下命中，使用半开区间，返回最上层的 Node ID。
- 每个元素的 `rect()` 是绝对逻辑矩形；文本 run 携带字体、字号、normalized coords、baseline 与绝对 glyph 位置。
- `Scene::decorations()` 给出 caret、selection 与 preedit underline；caret 只为聚焦输入生成，`Scene::caret(id)` 取它的矩形；`SceneElement::caret_at_value` 取某个值偏移处的 caret，组合窗口用它对齐 preedit 起点。`Scene::set_caret_visible` / `Scene::caret_visible` 只控制 caret 是否绘制，不改变几何查询。

## 内建视觉

场景只理解以下 intrinsic；其他 tag 返回 `UnsupportedTag`：

| tag | 视觉与布局 |
| --- | --- |
| `view` | 容器；默认纵向，`role="main"` 增加 16 内边距，`role="group"` / `"toolbar"` / `"listitem"` 改为横向 |
| `form` | 横向容器，行间距 8 |
| `text` | 文本容器；内容来自直接文本子节点 |
| `button` | 横向居中、内边距、最小高度 24；`aria:pressed` 进入 `Visual::Button` |
| `checkbox` | 16×16 方块；`checked` 进入 `Visual::Checkbox` |
| `text-input` | 带边框和内边距的输入盒，最小 80×24，在行内可伸展 |

正文使用系统 sans-serif、字号 14、行高 1.35。Parley 负责 Latin 与 CJK 的整形与字体回退；场景只做 shaping，glifo/vello 的栅格化留在 GPU 阶段，使用 `TextRun` 携带的字体与 glyph 数据。根元素至少与 viewport 的逻辑高度一致，因此纯高度变化也会重排。

## 属性与本地编辑状态

`value`、`checked`、`disabled`、`aria:pressed`、`role` 参与几何或视觉；`aria:label`、`type`、`id` 是接受的语义属性，不改变几何与绘制。`class` 不是呈现属性：它由 `view!` 编译为类型化声明，正常路径不会出现在快照属性里。其他属性——包括手工构造快照里的原始 `class`、`style:*` 与尚未实现的 `placeholder`——返回 `UnsupportedAttribute`，不会被静默丢弃。

文本输入按 `value` 绘制；组合期间按 `TextEditState::composition` 给出的区间用 preedit 替换该段文本。caret 与 selection 的字符偏移先换算成 UTF-8 字节，再由 Parley 给出几何。折叠的 selection 不产生高亮；preedit 在自己的范围下方画 1 逻辑像素下划线。caret 几何来自聚焦输入的本地编辑状态，未聚焦输入不生成 caret 装饰；GPU 是否绘制由 `Scene::caret_visible` 决定，宿主在闪烁或组合期间把它设为 false，几何查询保持可用。caret 是选择的活动端，`TextEditState::anchor` 是固定端；Shift 扩展时只移动活动端。

## 明确错误

`SceneError` 区分：

- `InvalidViewport`：非有限或负尺寸，或非正 scale；
- `UnsupportedTag`：没有内建视觉的元素；
- `UnsupportedAttribute`：场景 seam 不理解的属性；
- `UnsupportedStyle`：属性与取值不匹配、场景无法应用的样式声明；
- `UnsupportedContent`：`checkbox` 或 `text-input` 带有子节点；
- `BareRootText`：顶层裸文本没有 Node ID，不能成为场景元素；
- `Layout`：Taffy 无法完成布局。

场景构建不 panic，也不忽略未知输入。

## GPU 渲染层

`GpuRenderer` 把场景通过 `vello_gpu` 与 wgpu 画进任意 `TextureView`。`GpuContext::new()` 请求默认适配器与设备；没有可用适配器时返回 `RenderError::NoAdapter`，设备创建失败返回 `NoDevice`，不会 panic。

- `RenderTargetConfig` 声明目标视图的物理像素尺寸与格式，只接受 `Bgra8Unorm` 与 `Bgra8UnormSrgb`；视图必须与配置一致。
- 渲染时把逻辑矩形与 glyph 位置乘以 `Scene::viewport().scale()`，字号同样缩放；逻辑布局本身不变。
- `RenderPalette` 提供容器、控件、文本、边框、强调色、危险色、悬停/按下变体与 selection 的颜色；`bg-*`、`text-*`、`border-*` 角色按这些字段解析。
- 后端按 `ResolvedStyle` 绘制每个元素自己的背景、文本色、边框色、圆角与不透明度；未声明的属性回落到 intrinsic 视觉与调色板。圆角只影响填充与描边，不裁剪子节点，也不改变命中测试与 caret 几何；不透明度只作用于该元素自身的绘制。文本通过 glifo 的 glyph run 绘制；caret、selection 与 preedit 下划线按场景装饰绘制。
- 调色板分量按 sRGB 解释。`Bgra8Unorm` 目标原样写出这些字节；`Bgra8UnormSrgb` 会再应用一次传输编码，中间调因此变亮（离屏测试记录了 128 → 约 187）。宿主应优先请求非 sRGB 视图；若只能拿到 sRGB surface，需要显式的转换或 blit，而不是直接在渲染器里猜测。
- 离屏测试创建 wgpu 适配器、读回像素并覆盖两种格式；没有适配器的环境（例如缺少软件 Vulkan 的 Linux runner）跳过像素测试，适配器错误本身仍是显式 `RenderError`。
