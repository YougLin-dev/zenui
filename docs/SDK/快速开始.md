# 快速开始

## 环境

ZenUI 使用 `rust-toolchain.toml` 中固定的 Rust 工具链。安装 rustup 后，第一次执行 Cargo 命令即可使用对应版本。

主工作区包含 `crates/core`、`crates/app`、根包 `zenui`、宏/样式/渲染 crate、Windows 宿主和共享 demo。根包承载 target API 与最小可运行 Todo，并保留最小二进制入口。

| 路径 | 用途 |
| --- | --- |
| `crates/core` | headless Runtime、模型、查询、Owner、事务和测试 |
| `crates/app` | Todo 场景及其确定性 trace |
| `zenui`（根包） | target API、最小 headless Todo 与最小二进制入口 |
| `crates/macro` | `view!` 与 `#[component]` 宏 lowering |
| `crates/style` | 静态 class 与类型化样式声明 |
| `crates/render` | Taffy/Parley 布局、场景与 GPU 绘制 |
| `crates/windows` | Win32 宿主、原生输入/IME/DPI 与隐藏窗口 smoke |
| `crates/demo` | 共享 todo 状态、主/详情/确认三个窗口的示例目录 |

所有正常依赖都记录在主工作区的 `Cargo.lock`。核心 crate 只使用标准库，不添加运行时依赖，也不使用 `unsafe`。

## 运行一个真实示例

执行：

```sh
cargo run -p zenui-app --example todolist_headless --locked
```

场景按固定顺序插入 Todo、修改完成状态、筛选和重排，再覆盖删除、焦点及拒绝句柄后的恢复。输出是确定性的文本 trace，可以直接用于两次运行之间的对比。

这个示例调用现有 Rust API，不使用 `view!`、原生窗口或 GPU。适合先理解模型写入、行集、Owner 和事务如何配合。

## 运行 target API 的最小 Todo

```sh
cargo run -p zenui --example minimal_todo --locked
```

它使用 `view!`、mount-once 组件、Copy Signal/Memo/Store Field、`Show`/`For` 与共享 RowSet，在 headless 环境运行；不声明原生窗口、真实 IME 或 Windows 完成。示例挂在 headless activation 上：`Load sample` 启动 app 所有权任务并提交共享模型；`Import file` 用 `window.request_file_dialog(...)` 请求 app 所有权的文件选择器，示例再通过 `Runtime::take_file_dialog_requests` 与 `Runtime::complete_file_dialog_request` 完成这次选择，app 所有权 worker 读取 UTF-8 文本并把每个非空行提交为任务，成功后显示导入计数。公开行为测试位于根包 `tests/minimal_todo.rs`、`tests/acceptance.rs`、`tests/sdk.rs`、`tests/tasks.rs` 与 `crates/demo/tests/import.rs`；Windows 宿主用原生 `IFileOpenDialog` 承担同一个 picker seam。

任务边界测试直接覆盖：worker 返回前关闭窗口、重开后旧 activation 的交付被丢弃、app 所有权任务在窗口关闭后仍提交模型、UI 句柄无法进入 `Send` worker，以及非法交付被拒绝后的恢复。`compile_fail` doctest 验证 `Signal`/`Store` 不能跨线程捕获；这些证据只说明 headless 语义，原生窗口与 IME 由 Windows 宿主和实机验收覆盖。

阶段一完成判据与原生缺口的完整对照见 [stage-one 验收](../实现/stage-one-验收.md)；Windows 原生切片见 [stage-two 验收](../实现/stage-two-验收.md)。

## 运行 Windows 原生多窗口 Todo

```sh
cargo run -p zenui-windows --example todo_host --locked
```

它在真实 Windows 窗口与 GPU 上挂载同一个 `zenui-demo` Todo：主窗口工具栏的 Details 打开共享模型的详情窗口，Hide 保留详情窗口的本地 note，Close 后可以重新打开（确认窗口只在主窗口有待保存草稿时出现）。主窗口有非空草稿时，关闭会显示声明的确认窗口；Continue editing 保留草稿与焦点，Discard draft 释放主窗口与确认窗口。完整流程、100%/150% 截图和证据等级见 [stage-three 多窗口验收](../实现/stage-three-多窗口-验收.md)。

## 了解工作区

```sh
cargo test --workspace --locked
```

测试覆盖句柄与代际校验、模型查询、Owner 释放顺序、事务阶段、错误传播和 Todo 交互。

`crates/core/examples/syntax_model_shapes.rs` 是语法类型形状实验，能检查非 Copy 数据的 Copy identity handle、组件尾部的 `?` 和两个分支中的资源共享；target API 的行为证据由根包测试承担：

```sh
cargo test -p zenui-core --example syntax_model_shapes
```

这也是一个可编译的 example，会生成二进制入口，再由 Cargo 执行其中的单元测试。

## 独立原型

`examples/` 中各原型拥有自己的 Cargo 配置，不属于主工作区：

| 原型 | 开发范围 |
| --- | --- |
| `macro_poc` | 少量 intrinsic、静态 class 和事件的宏 lowering |
| `native_poc` | 文本、Taffy 布局和 headless GPU readback |
| `desktop_poc` | 信号、样式、Vello 图层及离屏合成实验 |

这些原型用于验证局部实现，不代表最终 SDK 已经形成统一、可运行的桌面应用。运行前请先读取相应的 Cargo 配置和入口。

宏原型有独立测试入口：

```sh
cargo test --manifest-path examples/macro_poc/Cargo.toml --workspace --locked
```

宏诊断的编译失败用例位于 [`examples/macro_poc/frontend/tests/compile_fail/`](../../examples/macro_poc/frontend/tests/compile_fail/)，覆盖 HTML 标签名、未知 class 和 script 事件。

## 预览目标语法

[todo-tour.rs](../../examples/todo-tour.rs) 汇总最新的目标写法。它展示完整的预期开发体验：Copy handle、数据位的 `once`、命名派生值、窗口和任务边界。

这个文件的目的在于阅读方案，不能作为现阶段的编译输入。缺少的 API、平台后端和 renderer 不能由示例文本替代。

## 当前阶段的开发范围

当前代码已覆盖 headless Runtime、`view!` 与 intrinsic、Windows 原生输入/IME/DPI、多窗口与关闭确认，以及锚定到窗口的原生打开文件对话框；菜单/托盘、保存/文件夹对话框、拖放、辅助技术和跨平台支持仍在开发中。跨显示器混合 DPI 与实机 device loss 仍是 #63 的开放证据缺口。

你可以运行上面的命令理解已有行为；需要修改目标 API 时，应先确认对应底层模型已覆盖，不要把目标语法当成现有能力。
