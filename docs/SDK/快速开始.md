# 快速开始

## 环境

ZenUI 使用 `rust-toolchain.toml` 中固定的 Rust 工具链。安装 rustup 后，第一次执行 Cargo 命令即可使用对应版本。

当前主工作区包含两个 crate：

| 路径 | 用途 |
| --- | --- |
| `crates/core` | headless Runtime、模型、查询、Owner、事务和测试 |
| `crates/app` | Todo 场景及其确定性 trace |

所有正常依赖都记录在主工作区的 `Cargo.lock`。核心 crate 只使用标准库，不添加运行时依赖，也不使用 `unsafe`。

## 运行一个真实示例

执行：

```sh
cargo run -p zenui-app --example todolist_headless --locked
```

场景按固定顺序插入 Todo、修改完成状态、筛选和重排，再覆盖删除、焦点及拒绝句柄后的恢复。输出是确定性的文本 trace，可以直接用于两次运行之间的对比。

这个示例调用现有 Rust API，不使用 `view!`、原生窗口或 GPU。适合先理解模型写入、行集、Owner 和事务如何配合。

## 了解工作区

```sh
cargo test --workspace --locked
```

测试覆盖句柄与代际校验、模型查询、Owner 释放顺序、事务阶段、错误传播和 Todo 交互。UI 子目录包含预期的编译失败场景，用来固定句柄类型使用错误时的诊断。

`crates/core/examples/syntax_model_shapes.rs` 提供语法类型形状的最小验证，能检查非 Copy 数据的 Copy identity handle、组件尾部的 `?` 和两个分支中的资源共享：

```sh
cargo test -p zenui-core --example syntax_model_shapes
```

这也是一个可编译的 example，会生成二进制入口，再由 Cargo 执行其中的单元测试。

## 独立原型

`examples/` 中各原型拥有自己的 Cargo 配置，不属于主工作区：

| 原型 | 开发范围 |
| --- | --- |
| `macro_poc` | 少量 intrinsic、静态 class 和事件的宏 lowering |
| `native_poc` | 文本、Taffy 布局和 headless GPU readback |
| `desktop_poc` | 控件结构、信号、样式及离屏合成实验 |

这些原型用于验证局部实现，不代表最终 SDK 已经形成统一、可运行的桌面应用。运行前请先读取相应的 Cargo 配置和入口。

宏原型有独立测试入口：

```sh
cargo test --manifest-path examples/macro_poc/Cargo.toml --workspace --locked
```

## 预览目标语法

[todo-tour.rs](../../examples/todo-tour.rs) 汇总最新的目标写法。它展示完整的预期开发体验：Copy handle、数据位的 `once`、命名派生值、窗口和任务边界。

这个文件的目的在于阅读方案，不能作为现阶段的编译输入。缺少的 API、平台后端和 renderer 不能由示例文本替代。
