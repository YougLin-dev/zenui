# 样式与输入

## 静态 class

class 在编译时解析为 ZenUI 的原生样式描述。每个 token 映射到明确的属性、值与变体，运行时只计算条件命中和对应字段更新，不解析 CSS 字符串或 Browser selector。

```rust
<button
    class="rounded-md bg-accent px-4 py-2 text-inverse"
    disabled={cannot_add}
>"Add"</button>
```

padding、gap、border、radius 等 token 映射到各自受影响的字段，不覆盖同属性的无关部分。布局、文本和绘制各消费自己的已解析字段，字号等共享输入保留单一来源。

## 条件与优先级

每个条件由控件或环境状态提供：

- `active:` 是正在按下的瞬态，不表示选中；
- `focus:` 表示当前焦点，`focus-visible:` 根据键盘等输入方式决定可见焦点样式；
- `disabled:`、`checked:`、`aria-pressed:` 等来自对应的语义字段；
- `dark:` 来自应用外观（`Appearance`），不跟随操作系统设置。

条件只决定一条声明是否参与比较。同一属性被多条活动 class 声明设置时，条件按 `dark` < `hover` < `focus` < `focus-visible` < `active` < `disabled` < `checked` < `aria-pressed` 的 rank 比较，高 rank 胜出；rank 相同才比较源码顺序。普通 inline declaration 覆盖同字段的 class 声明及其状态变体，状态激活不改变这个 origin 关系。hover、press 与键盘模态是宿主瞬态，外观是已提交状态；解析与优先级由场景一次完成，理由见 [ADR-0006](../adr/0006-presentation-transients-and-style-resolution.md)。

## 动态样式使用 typed 值

颜色和几何需要明确的类型，不解析任意单位字符串：

```rust
style:opacity={panel_opacity}
style:background={panel_tint}
style:width={em(1.75)}
```

普通 inline declaration 与同属性 class declaration 冲突时，普通 inline 优先。状态激活不会把普通 class 的提升改变成 inline origin。

`class` 只接受字符串字面量；不接收运行时拼接、注册 enum 或从网络/数据库得到的 class 字符串。需要用户驱动视觉变化时，使用 typed inline declaration，或按状态选取不同的静态 class 字面量。

## 从 UI 值到绘制状态

模型状态或主题可以派生出颜色：

```rust
let panel_tint = memo(move || match window.appearance() {
    Ok(Appearance::Dark) => Color::Literal([24, 24, 27, 255]),
    _ => Color::Literal([255, 255, 255, 255]),
});
```

这类 `Memo` 是稳定的界面派生值。动画插值进度、frame timestamp 等逐帧 transient 不进入 Signal 图，避免每一帧把整个业务响应式系统标脏；整页滚动偏移同样是宿主 presentation 状态而不是业务值，滚动不提交事务，也不改变模型、焦点或 caret（[ADR-0010](../adr/0010-scroll-is-presentation-state.md)）。

motion 与 ticker 有自己的 renderer handle。业务事件可以改变 motion 的目标，renderer 决定中间值、调度帧、空闲停帧和资源生命周期。滚动没有独立的 renderer 状态：宿主把已夹取的偏移放进 `SceneEnv`，场景每次构建只平移一次。

## 文本输入的两个方向

draft 等 UI 值流向 TextInput，用户的本地提交再写回 draft：

```rust
<text-input
    value={draft}
    on:input={move |value: String| draft.set(value)}
    on:keydown={move |event: KeyEvent| {
        if event.key() == Key::Escape {
            draft.set(String::new());
            event.consume();
        }
    }}
/>
```

`value` 与 `on:input` 分别表示外部值和已经提交的本地编辑。TextInput 在编辑器内保存当前文本、选择、composition 编辑 revision 和 origin，而不是把 `Signal<String>` 本身当作编辑器状态。

一次已提交的本地编辑按以下顺序处理：

1. 先更新本地文本和 selection，调用一次 `on:input`。
2. 在连续的 command turn 中完成应用写入和派生计算。
3. `value` 若带回这次编辑的 origin 与 revision，只确认编辑器已同步，不执行外部替换。
4. 应用发起的清空、撤销、格式化或远端更新按独立 revision 执行外部替换。
5. 新 revision 的外部到来不依赖字符串相等判断，也不被前一次本地 origin 长期屏蔽。

## 键盘、IME 与文本索引

键盘事件遵循明确的路由：平台按 IME 状态仲裁；焦点编辑器处理用户注册的 handler；由 handler 显式 `consume()` 后，事件结束。未消费事件才继续控件默认编辑、激活或表单命令。IME 候选确认不进入表单命令。

输入事件区分 physical key、logical key 与文本输入。dead key 与键盘布局切换由平台归一化，文本输入和快捷命令各自使用对应的键位语义。

preedit 保持在编辑器内；提交后才更新业务草稿。取消组合恢复组合前的已提交状态。外部替换按原因决定 selection 是保留并夹取、恢复指定范围还是折叠到末尾，并在 composition 中显式选择 commit 或 cancel 策略。

headless target runtime 提供同一套组合边界：

```rust
<text-input
    value={draft}
    aria:label="What needs to be done?"
    on:input={move |value: String| draft.set(value)}
    on:compositionstart={move |event: CompositionEvent| { /* phase, text, caret, selection */ }}
    on:compositionupdate={move |event: CompositionEvent| {}}
    on:compositionend={move |event: CompositionEvent| {}}
    on:compositioncancel={move |event: CompositionEvent| {}}
/>

app.compose_start("What needs to be done?")?;
app.compose_update("What needs to be done?", "nihao")?;  // 只更新本地 preedit
app.preedit("What needs to be done?");                    // Some("nihao")

// 结束组合的两条互斥路径，二选一：
app.compose_commit("What needs to be done?", "你好")?;    // 候选确认：派发一次 on:input
// app.compose_cancel("What needs to be done?")?;        // 取消：恢复组合前状态，不派发输入
```

组合期间 `on:input` 不触发，preedit 与临时 caret 只属于编辑器，`input` 与 `set_caret` 被拒绝；`compose_commit` 与 `compose_cancel` 都是终态，同一次组合只能选择其一。`compose_commit` 用候选文本替换组合区间（按提交时的当前 value 夹取）并派发一次 `on:input`，`compose_cancel` 丢弃 preedit 且不派发输入。`keydown` 在组合中先消费候选 Enter 与 Escape（取消），不进入用户 key handler 或表单提交；候选文本仍由 IME 随后通过 compositionend/`compose_commit` 确认，组合结束后的普通 Enter 才走提交命令。更完整的外部 origin/revision 策略属于原生适配步骤；原生 IME 适配仍属于独立的 Windows 步骤。

原生宿主按 Node ID 使用同一套平台无关的编辑归约：`insert_text_node`、`backspace_node`、`delete_forward_node`、`set_caret_node`、`set_selection_node`、`select_all_node`。编辑替换当前 selection；caret 与 selection 都以字符计数，并夹取到当前值长度，因此不会切开 UTF-8。改变文本的编辑恰好派发一次 `on:input`，caret / selection 移动不派发事件。组合中的编辑与移动返回 `DispatchError::Rejected`；禁用输入拒绝编辑、移动与组合开始/更新/确认，但取消始终可用，以免 preedit 无法结束。handler 改写后的值若更短，本地 caret 与 selection 会在刷新后夹回新值范围。

Rust 字符串的 UTF-8 offset、Windows / AT 的 UTF-16 position、Unicode grapheme、内部 glyph position 与可访问性 range 使用不同类型和统一转换。公开的编辑与辅助能力操作按字符 / grapheme 语义表达，内部字形 index 不作为选区。

## 列表与焦点

`For` 按业务 key 复用行，重排不换行组件，因此行内 caret、selection 和本地编辑状态可以留在正确的业务实体上。

删除或过滤消失卸载行，但不会默认删除模型数据。过滤再次出现时，新的一行组件可以选择新的 mount snapshot，不会无条件保留旧的行内 composition。

删除一个焦点控件前记录焦点意图：受影响的控件、类型、可见位置与命令代际。结构变化后从新的可见集合中依次考虑同类型的下一控件、上一控件、输入区域和过滤控件；批量删除只结算一次。禁用、隐藏、裁剪或已卸载的候选不参与接任；用户的新焦点操作取消旧意图。

新布局发布后，将最终焦点目标滚动到可见位置。焦点、输入法与辅助动作使用该次发布的几何和节点代际。

headless target runtime 把以上规则固化为可执行边界：

```rust
<text-input
    aria:label="Edit A"
    on:focus={move |event: FocusEvent| { /* FocusCause::Command | Settlement */ }}
    on:blur={move |event: BlurEvent| {}}
/>

app.focus("Edit A")?;   // 旧目标 blur 一次，新目标 focus 一次；相同目标不派发
app.focus_next()?;      // Tab / 方向键向前
app.focus_previous()?;  // Tab / 方向键向后
app.blur()?;            // 清空焦点
app.focused();          // 当前目标的 tag 与 aria:label
```

遍历顺序是挂载树的前序：组件与 `Show` 的活动分支向下展开，`For` 按业务顺序。`button`、`text-input`、`checkbox` 与显式挂载 `on:focus`/`on:blur` 的元素可聚焦，`disabled={true}` 的元素被跳过。重排保留存活控件的焦点；一次结构变化只做一次结算：先取旧一代挂载顺序里、发布后仍可聚焦的同 tag 下一控件、再取上一控件，然后退到任意仍可聚焦的下一/上一控件（当时禁用、本帧重新启用的旧控件也可以接任；“输入区域/过滤器”属于应用语义，headless 只提供这层通用回退）；本帧新挂载的控件不参与接任。焦点 handler 自身造成的进一步结构变化进入下一轮结算，并受固定轮数上限约束。失败的帧不发布焦点移动：目标已被移除或禁用时直接丢弃焦点，不派发 blur。关闭窗口直接丢弃焦点，不向已卸载的界面派发事件。原生焦点适配器仍属于独立的 Windows 步骤。

## 语义树与播报

`role` 和 `aria:*` 映射为控件语义状态与动作。checked、pressed、disabled 与真实控件状态同源；同一 visible tree 产生布局、命中与语义几何，不在交互时额外猜测另一套状态。

list、listitem、group、pressed toggle 等角色来自控件结构，而非添加一个名称字符串。没有业务行和筛选没有匹配项是两个独立的提示，具有不同的语义内容。

可见的 `role="alert"` 文本不自动抢焦点，错误展示也不清空草稿。`role="alert"` 目前不产生 UIA 事件；播报时机仍以真实辅助技术的观察为准，不能由一段标记代替。

Windows 宿主把这份语义树发布为 UIA：每个窗口一个 fragment root，角色映射控制类型，`aria:label` 优先于可见文本，`id` 映射 AutomationId；`disabled`、`checked`/`aria:pressed` 与焦点进入状态。Invoke/Toggle/Value/TextPattern/ScrollPattern 的 presence 来自同一份快照语义；写操作排队到 UI 线程重验，不在 provider 线程修改界面。相邻发布按 runtime ID 投递结构、属性与焦点事件；后台窗口不投递焦点事件，hover/press 与滚动几何不产生事件。窗口根的 ScrollPattern 只暴露垂直滚动，水平为 `NoScroll`，不新增滚动条 NodeId。契约见 [ADR-0012](../adr/0012-uia-derived-tree-and-action-queue.md)；可见证据、Narrator 观察与边界见 [stage-three 辅助技术合同与朗读验收](../实现/stage-three-辅助技术总验收.md)，隐藏 smoke 与 CI 只作部分证据。
