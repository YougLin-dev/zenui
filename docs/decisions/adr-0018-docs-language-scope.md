# ADR-0018：语言分工——仓库产物英文，文档正文沿用中文

## 背景

本仓库的产物已经是两种语言的组合：

- **英文**：分支名、commit subject/body、PR 标题与描述、代码、标识符、注释、测试名、文件名。
- **中文**：`docs/` 下的正文，包括已冻结的 `docs/spec/` 十二篇与 `docs/evidence/`、`docs/decisions/`。

`docs/README.md` §7 写作规则第 1 条已经写明"正文中文，术语保留英文"，因此**中文文档不是疏漏，而是成文契约**。
与此并行存在的是一条粗粒度的"仓库内容一律英文"的口头规范；两者在文档上直接冲突，导致同一个 PR 的评审
可以得出相反结论（有人按口头规范要求改文档，有人按治理契约要求保留中文）。

必须裁定的是：**"英文"约束的作用范围**，而不是文档应该用哪种语言。三个候选路线见下节；其中两条会把
已冻结或只读的文档当作可改写对象，与 `ADR-0011`（一个事实只定义一次）、`ADR-0013`（归档只读）冲突。

## 备选项

1. **承认现状，把约束写成分工**：产物英文，文档正文沿用各文件既有语言（现状全部为中文）。
2. **整体英文化**：把 `docs/` 五十七篇（含冻结的 spec 层）翻译为英文。
3. **新内容英文、旧内容不动**：不做迁移，但同一文件内会出现中文段落与英文段落混排。

**未选 2**：spec 层是 `normative` 且已整体冻结（`docs/README.md` §4），就地改写需要逐条 ADR supersede；
`ADR-0013` 明确拒绝"为了让文档一致而重写历史"。翻译还会引入第二份可漂移的规范权威，直接违反
`ADR-0011` 的"一个事实只在一处定义"。这不是"工作量太大"的取舍，而是**会让规范失去唯一权威**。

**未选 3**：同一文件内混排语言，读者的阅读成本高于任何其他方案，且无法机械判定"新内容"，边界随
评审者的判断漂移。

## 决定

1. **产物一律英文**：分支名（`<type>/<TASK-ID>-<kebab-summary>`）、commit subject 与 body、
   PR 标题与描述、review 评论、代码、标识符、注释、测试名、文件名。禁止中文与拼音。
   **唯一例外是测试数据**：CJK 字面量作为 shaping / ICU 夹具的输入（`examples/native_poc`、
   `examples/macro_poc` 的断言文本）是数据，不是表述，不受本约束，也不得因为本 ADR 被删改。
2. **文档正文沿用文件既有语言**。范围包括 `docs/**` 与 `examples/*/README.md`；当前两者都是中文，
   术语保留英文；`docs/README.md` §7 第 1 条是本条的规范表述，本 ADR 只界定它的**适用范围**，不改写它。
3. **一个文件一种语言**：新增段落跟随所在文件的语气与语言；不允许在中文文件里插入英文长段落，反之亦然。
   `EVID-VAL-*`、`CLAIM-*`、`ADR-*` 都是文档，同样适用。
4. **GitHub 面上的文字**（PR 描述、PR 内评论、commit message）属于第 1 条，不属于第 2 条：即使讨论的是
   中文文档，写进 PR 的内容仍是英文。给中文团队看的会话消息不在此列。
5. **本 ADR 不追溯改写任何既有文件**。若将来需要英文文档集，必须作为独立项目新开 ADR，产出**新的**文档
   集（例如 `docs/en/`）并标明权威关系，不得就地翻译冻结层。
6. **评审判定规则**：今后不得再以"出现中文"为由要求修改 `docs/` 正文；只按第 1 条的产物清单判定。
   反之，产物里出现中文必须在本轮修掉。

## 依据

- `docs/README.md` §7 写作规则第 1 条："正文中文，术语保留英文"——文档语言已是成文契约。
- `docs/README.md` §4 状态表：`normative` 文档与实现冲突时**以文档为准**（实现即为缺陷），改写必须走
  `ADR-*`；`spec/` 整体 `normative`，并在 §9 快照中标注为 2026-11-18 冻结，就地翻译等于把最重的目录级
  改写塞进一次语言变更。
- `ADR-0011`：文档四层治理，"一个事实只在一处定义"；双语文档集会产生两份可漂移的规范。
- `ADR-0013`：归档只读、不重写历史；路线 2/3 与它冲突。
- `SPEC-SCOPE-021`：能力宣称必须落到 `EVID-*`/`CLAIM-*`。本条不新增任何能力宣称，因此依据不引用运行证据；
  引用一条无关的 `EVID-*` 只是装饰，正是该条目拒绝的写法。
- 仓库历史（`git log`，2026-11-18 的 `feat/MORT-4-a0-headless-core` 分支）：分支名、commit subject 与 body、
  注释与测试名已经是英文；代码里出现的汉字只作为 CJK shaping 测试数据，第 1 条已把它显式排除。

## 影响与撤销条件

**影响**

- 评审口径统一：文档按治理契约、产物按本 ADR，不再出现"同一处中文被判合格又被判不合格"。
- 外部读者只能通过英文产物（commit、PR、代码）理解变更动机；中文规范仍是唯一权威。这是本 ADR 明确的代价。
- 语言无法由 `scripts/check_docs.py` 机械校验（没有可靠的中文/英文判定），第 1、2 条由评审执行；这一点如实记录，
  不假装有 CI 防线。

**撤销条件（可判定）**

1. 仓库需要面向非中文贡献者时（任一项成立：公开 `v0.1` 发布、或外部贡献者因无法阅读 `docs/spec/` 而提出
   至少两次同类请求），必须新开 ADR，把 `docs/spec/` 英文化作为独立工作项，并在迁移期提供双语对照。
2. 若某个文件在两次评审中因语言问题得到相反结论，先按本 ADR 裁决，再评估是否需要细化规则；不得靠口头约定。
3. 任何"顺手把某篇文档翻译了"的局部改动都不被接受，理由同 `ADR-0013`：局部改写会同时破坏权威唯一性与
   文件内一致性。
