# 样式与输入

## 静态 class

class 使用编译期完整词表。每个 token 在编译时转换成 ZenUI 自己的样式描述，运行时不需要解析 CSS 字符串，也不需要 Browser selector engine。

```rust
<button
    class="rounded-md bg-blue-600 px-4 py-2 text-white disabled:opacity-50"
    disabled={cannot_add}
>"Add"</button>
```

`disabled:opacity-50` 等条件 variant 来自控件语义状态；`aria-pressed:` 对应 `aria:pressed`，不另写一套只服务于视觉的 selected bool。

未知 token 和无法支持的变体在输入源码时报告，不会静默丢弃。样式覆盖范围由当前注册的 utility registry 决定；不能因为沿用了熟悉的 utility 拼写，就假设 CSS 的所有选择器、层级和布局都支持。

## 动态样式使用 typed 值

颜色和几何需要明确的类型，不解析任意单位字符串：

```rust
style:opacity={panel_opacity}
style:background={panel_tint}
item_extent={em(1.75)}
```

普通 inline declaration 与同属性 class declaration 冲突时，普通 inline 优先。状态激活不会把普通 class 的提升改变成 inline origin。

动态 class 可以有完整的静态候选，例如注册 enum 或条件选择；不接收任意从网络或数据库拼出的 class 字符串。需要用户驱动视觉变化时，优先选择明确的 typed style 或已登记候选。

## 从 UI 值到绘制状态

模型状态或主题可以派生出颜色：

```rust
let panel_tint = memo(move || match scope.env.appearance().get() {
    Appearance::Dark => rgb(0x18181b),
    Appearance::Light => rgb(0xffffff),
});
```

这类 `Memo` 是稳定的界面派生值。动画插值进度、frame timestamp、滚动提交的瞬时帧位置等 transient 则不进入 Signal 图，避免每一帧把整个业务响应式系统标脏。

motion、scroll、ticker 有自己的 renderer handle。业务事件可以改变 motion 的目标，renderer 决定中间值、调度帧、空闲停帧和资源生命周期。

## 文本输入的两个方向

draft 等 UI 值流向 TextInput，用户的本地提交再写回 draft：

```rust
<text-input
    value={draft}
    on:input={move |value: String| draft.set(value)}
    on:keydown={move |event: KeyEvent| {
        if event.key() == Key::Escape {
            draft.set(String::new());
        }
    }}
/>
```

`value` 与 `on:input` 都保留下来，因为它们不是同一方向：

- 外部清空、撤销和业务替换通过 `value` 到达编辑器。
- 用户正常输入通过 `on:input` 更新草稿。

控件同时维护 caret、selection 和 composition。每次本地输入不应被当成外部文本替换再次灌回，导致 caret 移到末尾或 IME 被中断。外部 replace 和 local committed input 有各自的来源与 revision。

这属于 TextInput 专属 adapter，不能把所有 String 属性都当成编辑器处理。

## IME 交互

输入法候选的确认 Enter 由编辑器消费，不能继续触发表单提交；之后的正常 Enter 才提交一次 Add。取消组合时不会把未上屏文本写入业务草稿，退出编辑器或关闭窗口需要按当前 composition policy 处理。

异步模型提交不能改写正在进行的 composition。字段、Selection、视图和原文的 revision 对不上时，事件不应穿过代际边界继续提交。

原生的 focus、hit testing 和辅助技术 action 使用同一组 View identity 与 geometry。若一个 key 被卸载，它的监听和语义动作同时失效；重新出现相同业务 key 时创建新 Owner，而不是自动复活旧 IME 或控件状态。

## 列表与焦点

`For` 按业务 key 复用行，重排不换行组件，因此行内 caret、selection 和本地编辑状态可以留在正确的业务实体上。

删除或过滤消失卸载行，但不会默认删除模型数据。过滤再次出现时，新的一行组件可以选择新的 mount snapshot，不会无条件保留旧的行内 composition。

删除一个焦点控件前记录合理的后继：下一个控件、上一个控件、输入区域，最后是可用的过滤控件。用户已经主动改变焦点时，不迫使用户回到旧的移除转移计划。

## 语义树与播报

`role` 和 `aria:*` 提供的是控件的语义字段，而不是无障碍测试本身。checked、pressed、disabled 与真实控件状态同源，防止视觉与语义漂移。

可见的 `role="alert"` 文本不自动抢焦点；错误展示也不会清空草稿。真实的读屏播报、键盘路径和可执行动作还需要在目标平台实机上验证，不能由一段标记文本代替。
